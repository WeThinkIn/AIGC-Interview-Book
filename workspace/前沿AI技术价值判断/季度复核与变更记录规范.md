# 季度复核与变更记录规范

季度复核用于检查技术判断是否仍然成立，并把变化同步到教程、面试题、学习路线和岗位认知中。

## 一、复核样本

每季度优先复核：

- 新增或状态为“产业验证中”的技术主题；
- 被多个 Issue、PR 或真实面经反复提及的主题；
- 已经影响岗位 JD、面试题或项目实践的主题；
- 与主仓库多条学习路线关联的主题；
- 距离最近复核时间较长，或出现明显替代信号的主题。

## 二、复核问题

1. 核心问题是否仍然存在；
2. 技术机制是否仍然成立，还是已经被更简单的方案替代；
3. 是否出现了新的官方、论文、源码、工程或岗位证据；
4. 真实采用是否扩大，还是只停留在传播和演示层；
5. 对学习者的投入建议是否需要调整；
6. 现有教程、问答、路线和面试判断是否需要同步；
7. 过去的表述是否需要降级、补充边界或纠正。

## 三、变更类型

| 变更类型 | 适用情况 | 必须记录 |
| --- | --- | --- |
| 升级 | 证据增加，技术从观察或阶段跟进进入更高价值层级 | 新证据、升级原因、用户行动变化 |
| 维持 | 新证据没有改变原有判断 | 复核范围、关键来源、维持理由 |
| 降级 | 采用受限、边界暴露或替代方案成熟 | 新限制、替代关系、学习优先级变化 |
| 归档 | 主题不再适合作为当前主线，但仍有历史或迁移价值 | 归档原因、历史链接、替代学习入口 |
| 纠正 | 发现事实、机制、版本或引用存在错误 | 错误位置、修正依据、影响范围 |

## 四、记录模板

每次变更在[判断变更记录](判断变更记录/README.md)中新增一条记录，至少包含：

```markdown
# 主题｜YYYY 年第 N 季度判断变更

- 原状态：
- 新状态：
- 原判断摘要：
- 新证据：
- 变化原因：
- 对学习者的影响：
- 需要同步的章节或路线：
- 主编确认：
- 复核日期：
- 来源：
```

不覆盖旧记录，不把判断变化包装成“平台一直如此判断”。公开修正本身是平台可信度的一部分。
