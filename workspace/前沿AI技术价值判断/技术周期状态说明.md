# 技术周期状态说明

状态描述的是平台当前对技术长期学习价值的判断，不是对技术在所有场景下的绝对评价。

## 五类状态

### 跨周期主干

核心问题长期存在，机制能够迁移到多个模型、任务或系统，且已经具有足够的理论、工程或岗位证据。建议系统掌握，并沉淀为面试表达、项目能力和职业底座。

### 结构性增量

相较已有方法具有清晰的机制或系统增量，正在影响某个重要方向。建议重点理解问题、机制和边界，不要只记产品名称。

### 产业验证中

已经出现真实产品、工程或岗位信号，但采用范围、可靠性、成本或长期替代关系仍需观察。适合结合目标岗位进行学习，并保留不确定性。

### 阶段性跟进

当前具有短期热点、产品或岗位价值，但迁移性和长期稳定性有限。建议按需了解和实践，不替代跨周期主干的学习。

### 降低优先级

技术已经被更有效的方案替代，或者现有证据不足以支持较高的长期学习优先级。仍可保留其历史、适用边界和迁移关系，但不建议继续投入大量时间。

## 状态迁移

```text
技术信号
→ 产业验证中
→ 结构性增量
→ 跨周期主干
```

也可能发生反向迁移：

```text
阶段性跟进 / 产业验证中
→ 证据减弱或替代方案成熟
→ 降低优先级
```

状态迁移必须说明触发证据。技术热度上升不自动代表状态升级，榜单排名下降也不自动代表技术失去价值。

## 对用户的表达边界

推荐使用：

- 当前纳入长期知识主干；
- 当前建议重点跟进；
- 仍处于产业验证阶段；
- 当前更适合按需了解；
- 当前不建议作为第一学习优先级。

避免使用：

- 永远不会过时；
- 必然淘汰所有旧技术；
- 完全没有价值；
- 学会就一定能获得工作机会。
