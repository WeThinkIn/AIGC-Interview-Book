<h1 id="4.2.1_条件编码与多模态条件注入：文本、图像、视频与结构控制如何进入模型">4.2.1 条件编码与多模态条件注入：文本、图像、视频与结构控制如何进入模型</h1>

> 条件系统要解决两个接口问题：先把文本、参考图、首帧、源视频、音频、mask、pose、depth、trajectory 等输入变成合适的表示，再把这些表示注入生成主干。编码路径决定模型保留了什么信息，注入位置决定这些信息能影响哪些时空 token。

<h2 id="4.2.1.1_面试问题：视频生成模型为什么需要条件表示？一定要使用独立条件编码器吗？">4.2.1.1 面试问题：视频生成模型为什么需要条件表示？一定要使用独立条件编码器吗？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

模型需要的是**条件表示**，并不要求每种条件都配一个独立的大编码器。生成主干处理 noisy video latent 或时空 token，外部输入只有经过分词、投影、压缩或特征提取，才能在维度、粒度和位置关系上与主干接口匹配。

**条件表示主要有三种形态**

- 文本、音频和语义参考通常编码成长度可变的 token 序列，供视频 token 按需读取。
- 首帧、源视频、mask、depth、pose 等带明确位置的条件，通常保留二维或三维网格，经过 VAE、卷积网络或 patch projection 后与视频 latent 对齐。
- 时间步、帧率、宽高比、类别等全局信息，常直接映射为一个向量或少量 embedding。

**什么时候需要独立编码器**

独立编码器的主要价值是复用预训练语义或感知先验，并把高维原始输入压缩为稳定特征。例如，文本编码器提供语言表示，视觉编码器提供参考图语义，音频编码器提供语音或声学特征。但 mask 可以直接与 noisy latent 拼接，时间步可以由模型内部的 embedding 层处理，首帧也可能先经过同一个 VAE 再作为空间对齐 latent 输入。这些情况都不需要独立的预训练编码器。

几类条件路径及其输出粒度如图2-1所示。

> **配图占位（图2-1）**：展示三条条件路径。语义序列条件经文本/音频/视觉语义编码器得到条件 token；首帧、源视频、mask、pose、depth 经 VAE、卷积或 patch projection 得到与视频 latent 对齐的时空特征；时间步、帧率和宽高比经 embedding/MLP 得到全局向量。三条路径分别连接到 Cross-Attention、拼接/残差注入和 AdaLN，并标出“独立预训练编码器并非必需”。

**如何确认模型真正使用了条件**

工程上最容易忽略的是“接入了条件”不等于“模型使用了条件”。可以固定随机种子，分别做条件置空、错配和局部扰动，观察输出是否按预期变化；若替换参考图后主体几乎不变，问题可能出在编码器输出、投影层尺度、注入位置或训练数据，而不一定是生成主干容量不足。

> **面试速答**：视频模型必须把外部输入转成与主干兼容的条件表示，但不一定需要独立编码器。语义条件常用预训练编码器，空间对齐条件可走 VAE、卷积或直接投影，全局标量可用 embedding；判断设计是否有效，要看表示粒度、注入接口和条件消融结果。

<h2 id="4.2.1.2_面试问题：T5、CLIP-文本编码器与视觉条件编码路径分别保留什么信息？">4.2.1.2 面试问题：T5、CLIP 文本编码器与视觉条件编码路径分别保留什么信息？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

这几条路径的差异来自训练目标和输出粒度，不能简单概括成“T5 管语言，CLIP 管画面”。表2-1列出了各类表示实际保留的信息。

<p align="center">表2-1 文本与视觉条件编码路径的训练信号、信息粒度和使用边界</p>

| 编码路径 | 主要训练信号 | 常见输出 | 更容易保留的信息 | 主要边界 |
| --- | --- | --- | --- | --- |
| T5 类文本编码器 | 文本到文本的语言建模或去噪目标 | 文本 token 序列 | 词义、句法和组合关系；长文本能力取决于具体模型及上下文长度 | 没有天然的图像像素对齐，视觉概念仍依赖视频训练阶段学习 |
| CLIP 文本编码器 | 图文对比学习 | 文本 token 或 pooled embedding | 与图像数据对齐的视觉概念和类别语义 | 对细粒度属性绑定、数量和复杂关系的表达不一定稳定 |
| CLIP/自监督视觉编码器 | 图文对比或视觉表征学习 | 图像 patch token 或全局向量 | 主体类别、风格和高层参考语义 | 全局特征会弱化精确位置与像素细节，单靠它难以锁定首帧结构 |
| VAE latent / 空间编码分支 | 重建或带控制条件的生成目标 | 与视频网格对齐的 latent/feature map | 颜色、布局、轮廓和局部位置 | 语义抽象能力有限，且信息上限受压缩率和编码器结构约束 |

**语义参考与空间约束不能互相替代**

首帧 I2V 能体现最后两条路径的区别。视觉语义编码器可以告诉模型“参考图里是什么、整体外观如何”，但未必保留每个位置的像素结构；把首帧经 VAE 编码后拼到视频 latent，空间约束更强，却可能让模型过度复制首帧、运动不足。很多系统同时保留语义特征和空间对齐 latent，原因就在这里。

**多编码器的代价**

多编码器也有代价。不同特征的维度、范数和 token 长度不一致，简单拼接可能让其中一路占主导；编码器全部冻结时，条件空间与视频训练分布也可能存在偏差。工程上应分别做单路条件消融和冲突测试，不能只看多条件同时开启时的最终样例。

> **面试速答**：T5 类编码器主要提供语言组合表示，CLIP 文本编码器提供图文对齐语义，视觉编码器提供参考图的高层语义，VAE latent 或空间分支保留更精确的布局和外观。它们不能简单互换；选择取决于任务需要语义一致、主体参考，还是首帧级空间约束。

<h2 id="4.2.1.3_面试问题：如何选择-Cross-Attention、AdaLN、拼接与残差控制分支？">4.2.1.3 面试问题：如何选择 Cross-Attention、AdaLN、拼接与残差控制分支？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

选择注入方式时先看条件的**粒度和对齐关系**，再看模态名称。长度可变的语义 token、单个全局向量、与视频网格对齐的 dense map，需要的接口不同。

**语义 token 与全局向量**

Cross-Attention 和 AdaLN 的差别可以直接从算子看出来：

```math
\begin{aligned}
y_{\mathrm{attn}} &= \mathrm{softmax}\left(\frac{Q_xK_c^\top}{\sqrt{d}}\right)V_c, \\
y_{\mathrm{mod}} &= \gamma(c) \odot \mathrm{LN}(x) + \beta(c).
\end{aligned}
```

其中， $Q_x$ 来自视频 token， $K_c$ 和 $V_c$ 来自条件 token； $\gamma(c)$ 与 $\beta(c)$ 是条件生成的通道调制参数。前者允许不同视频 token 读取不同条件 token，适合文本、音频或参考图语义，但计算量会随两侧 token 数增长。后者用少量全局参数调制整层特征，适合时间步、类别、风格或 pooled text embedding，成本低，却难表达精确的局部位置。

**空间对齐条件**

另外两类路径处理空间对齐条件：

- **拼接。** 将 mask、首帧 latent、源视频 latent 或结构图与 noisy latent 在通道维拼接，或者把条件 token 接入视频 token 序列。通道拼接要求网格对齐，控制直接，但会改变输入层；token 拼接更灵活，同时增加注意力长度，模型也需要学会区分条件 token 和待生成 token。
- **残差控制分支。** 额外分支先编码 pose、depth、edge、trajectory 等 dense control，再把多尺度残差注入主干。它能在冻结或少量改动主干时增加结构控制，但带来额外显存和计算。这里的 Adapter/ControlNet 描述的是附加分支，分支输出仍要通过残差、注意力或调制进入主干，因此它不与前三种算子严格同级。

Reference Attention 通常也是 attention 路径的一个变体：参考 token 作为 key/value，或与生成 token 共同参与注意力，不应再单列成完全独立的注入范式。常见条件路径及位置关系见图2-2。

**条件控制失效时怎么查**

排查条件控制失效时，先确认条件是否具有正确的时间和空间对齐，再检查投影后的特征范数、注意力响应或残差幅度，最后做条件置空和错配实验。仅提高 guidance scale 可能放大语义条件，无法修复错位的 mask、首帧 latent 或轨迹。

> **面试速答**：Cross-Attention 适合长度可变的语义 token，AdaLN 适合全局向量，拼接适合与视频网格对齐的条件，残差控制分支适合多尺度 dense control。Adapter 是条件分支，不是与 attention、调制并列的单一注入算子；真正的选择依据是粒度、对齐方式、注入位置和计算预算。

<h1 id="4.2.2_Video-VAE-与潜空间建模：为什么视频生成通常不直接在像素空间完成">4.2.2 Video VAE 与潜空间建模：为什么视频生成通常不直接在像素空间完成</h1>

> Latent 视频生成把像素重建交给 VAE，把分布建模交给扩散或 Flow Matching 主干。VAE 决定主干能看到多少时空信息和多少 token，但最终质量还取决于生成主干、训练数据和采样过程。

<h2 id="4.2.2.1_面试问题：为什么视频生成通常选择-latent-space？它把哪些问题留给了-VAE？">4.2.2.1 面试问题：为什么视频生成通常选择 latent space？它把哪些问题留给了 VAE？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

视频通常选择 latent space，是因为像素视频包含大量局部冗余。先用 VAE 压缩空间、可选地压缩时间，再让生成主干处理更短的时空网格，可以明显降低训练显存和推理成本。Latent Diffusion 已验证这种“感知压缩 + 生成建模”的分工能够在计算量与细节保真之间取得实用平衡；视频只是把这个问题扩展到了时间维度。

**代价是 VAE 设定了信息上限**

这是一种工程折中，不是生成模型的必要条件。像素空间模型、离散 tokenizer 和多级级联都能生成视频。Latent 路线的优势是把高成本迭代放在紧凑表示上，代价是主干只能建模 VAE 保留下来的信息：小字、人脸细节、高频纹理或短促运动一旦在编解码阶段丢失，后续扩散模型很难可靠恢复。

**先判断瓶颈在 VAE 还是生成主干**

排障时先跑真实视频的 VAE round-trip，再看生成结果。若重建视频已经出现颜色漂移、文字损坏、周期性闪烁或快速动作变钝，瓶颈在 VAE；若重建正常、生成结果才漂移，再检查生成主干、条件和采样。这样可以避免用更大的 DiT 去补一个已经丢失信息的表示空间。

> **面试速答**：latent space 用有损压缩换取更低的时空建模成本，让生成主干集中处理语义、结构和运动。它不是唯一方案；代价是 VAE 会设置信息上限。工程上应先检查 VAE 重建，再判断生成主干是否有问题。

<h2 id="4.2.2.2_面试问题：Video-VAE-相比逐帧-Image-VAE-多解决了什么？causal-与-non-causal-如何选择？">4.2.2.2 面试问题：Video VAE 相比逐帧 Image VAE 多解决了什么？causal 与 non-causal 如何选择？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

逐帧 Image VAE 对每帧独立编码和解码，帧间关系全部留给生成主干。Video VAE 在编码器、解码器或两侧加入时间卷积、3D 卷积、时间注意力等跨帧算子，使相邻帧共享上下文，并可在时间轴上降采样。它解决的是**时序表示与重建**，不代表生成视频的长期一致性由 VAE 单独保证。

需要把时间耦合、时间压缩和因果性拆开看，具体差异见表2-2。

<p align="center">表2-2 逐帧 Image VAE、causal Video VAE 与 non-causal Video VAE 的关键差异</p>

| 维度 | 逐帧 Image VAE | Causal Video VAE | Non-causal Video VAE |
| --- | --- | --- | --- |
| 时间感受野 | 单帧 | 当前帧及历史帧 | 当前帧及前后帧 |
| 时间降采样 | 通常不做 | 可做，也可保持原帧率 | 可做，也可保持原帧率 |
| 主要优势 | 可直接复用图像 VAE，图像兼容性好 | 不访问未来输入，便于前缀复用和流式编解码 | 能利用双向上下文，适合离线整段重建 |
| 典型风险 | 独立重建误差表现为帧间闪烁 | 首帧与 chunk 边界更难处理，缓存实现复杂 | 依赖未来帧，分块边界和在线处理受限 |
| 系统前提 | 生成主干承担全部时序一致性 | 还需要生成主干、调度和缓存链路支持因果处理 | 需要明确推理窗口及重叠策略 |

**时间耦合、时间压缩与因果性是三个属性**

Video VAE 并不必然压缩时间。只要编码或解码过程显式混合跨帧信息，即使 $r_t=1$ ，它仍属于视频自编码器。反过来，把相邻帧做简单时间降采样，也不等于学到了稳定的运动表示。

**Causal 只约束信息依赖方向**

Causal 的定义也应限制在模块依赖关系上：时刻 $t$ 的表示不访问 $t$ 之后的输入。它为流式系统提供必要条件，但生成主干的时序依赖、attention pattern、采样过程和解码缓存都支持增量处理后，端到端流式生成才有可能成立。Non-causal 模型拥有更多上下文，重建质量可能更好，但这不是无条件保证。

**如何验证真实感受野**

工程上可以用单帧扰动检查真实感受野：只改未来某一帧，观察当前 latent 或重建帧是否变化；再用不同 clip 长度和 chunk 切分位置测试边界闪烁。这样比仅凭模块名称判断 causal 更可靠。

> **面试速答**：逐帧 Image VAE 只做空间编解码，Video VAE 还显式建模跨帧关系，并可选择时间压缩。Causal、是否时间降采样是独立属性；causal 便于前缀复用和流式编解码，端到端流式能力还取决于生成主干、采样过程和缓存链路。

<h2 id="4.2.2.3_面试问题：Video-VAE-的空间压缩、时间压缩和-latent-通道数应如何权衡？">4.2.2.3 面试问题：Video VAE 的空间压缩、时间压缩和 latent 通道数应如何权衡？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

VAE 规格至少要看空间压缩率、时间压缩率和 latent 通道数。只报一个“总压缩倍数”，无法判断模型减少了多少时空位置，也看不出每个位置保留了多少特征。

**先区分网格数、token 数和元素数量**

设 RGB 视频尺寸为 $T \times H \times W \times 3$ ，latent 尺寸为 $T' \times H' \times W' \times C_z$ 。假设各维可整除；如果主干还把 latent 切成大小为 $p_t \times p_h \times p_w$ 的 3D patch，则有：

```math
\begin{aligned}
T' &= \frac{T}{r_t}, \qquad H' = \frac{H}{r_h}, \qquad W' = \frac{W}{r_w}, \\
N_{\mathrm{grid}} &= T'H'W' = \frac{T H W}{r_t r_h r_w}, \\
N_{\mathrm{token}} &= \frac{N_{\mathrm{grid}}}{p_t p_h p_w}.
\end{aligned}
```

其中， $r_t$ 是时间压缩率， $r_h$ 和 $r_w$ 是空间压缩率， $C_z$ 是 latent 通道数； $p_t$、 $p_h$、 $p_w$ 分别是主干在时间、高度和宽度方向的 patch 大小。

当主干不再 patchify latent 时， $p_t=p_h=p_w=1$ ，此时 latent 网格数才等于 token 数。VAE 压缩与主干 patch 化发生在不同位置，比较模型成本时不能混为一个指标。

如果把通道也算入，输入与 latent 的元素数量之比为：

```math
R_{\mathrm{elem}}=\frac{3 T H W}{C_z T'H'W'}
=\frac{3 r_t r_h r_w}{C_z}
```

因此， $r_t r_h r_w$ 表示 VAE 对时空网格的缩减倍数， $R_{\mathrm{elem}}$ 才包含 latent 通道数。它仍然只是元素数量比，并未计入数值精度或熵编码，不能直接当成文件存储压缩率。增加 $C_z$ 不会改变 latent 网格数，却会增加每个位置的表示容量、latent 激活量和输入输出投影成本。把网格缩减倍数、patch 大小和元素数量比混在一起，模型之间的效率比较很容易失真。

**三个方向丢失的信息不同**

- **空间压缩**首先影响小物体、文字、人脸和细纹理。空间压缩过强时，生成主干即使预测正确，解码后仍可能糊成相似纹理。
- **时间压缩**首先影响高速动作、瞬时表情、闪光和口型等高频变化。压缩过强时常见动作变钝、短事件消失或音画边界偏移。
- **Latent 通道数**限制每个时空位置可携带的联合信息。通道过窄会同时影响颜色、纹理和运动表征；通道加宽又会提高 VAE 与主干投影层的成本。

**效率与选型不能只看压缩倍数**

token 减少通常会降低主干计算量，但“压缩两倍就快两倍”并不成立。全局注意力、局部窗口、稀疏注意力和卷积主干的复杂度不同，端到端延迟还包含 VAE 编解码、数据搬运和采样步数。

选型时先在真实视频上单独评估 VAE：按人脸、小字、高速运动、镜头切换和音画同步切片检查重建，再记录 latent token 数、通道数、显存和编解码延迟。VAE round-trip 合格后，才有必要比较下游扩散或 Flow Matching 的训练稳定性与生成质量。

> **面试速答**：空间和时间压缩决定主干处理多少时空 token，通道数决定每个 token 能装多少信息。空间压缩主要损伤细节，时间压缩主要损伤快速运动，通道过窄会限制整体表示能力。比较模型时要区分 token 缩减倍数和包含通道数的元素数量比，并先做 VAE-only 重建测试。

<h1 id="4.2.3_视频生成目标：Diffusion、Flow-Matching、Rectified-Flow-与采样过程">4.2.3 视频生成目标：Diffusion、Flow Matching、Rectified Flow 与采样过程</h1>

> 本节从训练目标讲到推理求解，重点分清模型学到的场、生成路径如何定义，以及推理时怎样把这个场积分成视频 latent。

<h2 id="4.2.3.1_面试问题：视频扩散模型训练时究竟学什么？为什么不能理解为逐帧去噪？">4.2.3.1 面试问题：视频扩散模型训练时究竟学什么？为什么不能理解为逐帧去噪？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

视频扩散模型学习的是：在给定噪声级别和条件后，如何从受扰动的**时空 latent** 估计去噪方向。典型训练并不会对每个样本完整执行一遍反向链，而是随机采样时间 $t$ 和噪声 $\epsilon$，直接构造 $z_t$，用一次网络前向计算监督信号：

```math
\begin{aligned}
z_t &= \alpha_t z_0 + \sigma_t \epsilon, \qquad \epsilon \sim \mathcal{N}(0,I), \\
\mathcal{L} &= \mathbb{E}\left[\left\lVert y(z_0,\epsilon,t)-f_\theta(z_t,t,c)\right\rVert_2^2\right].
\end{aligned}
```

**预测目标可以采用不同参数化**

$y$ 取决于参数化方式，可以是噪声 $\epsilon$、干净 latent $z_0$，也可以是常见约定下的 velocity $v_t=\alpha_t\epsilon-\sigma_tz_0$。三种写法描述的是相关的预测量，但损失权重、数值尺度和训练动态并不完全相同；更换 prediction type 时，采样器中的转换公式也必须同步。

**视频一致性来自时空联合建模**

“不是逐帧去噪”的原因不在损失函数名称，而在模型处理的数据与网络结构。视频 latent 通常形如 $T'\times H'\times W'\times C$，主干通过 3D 卷积、时间注意力或时空注意力联合处理多帧。若网络仍按帧独立预测，即使使用同一扩散损失，也不会自动获得可靠的运动连续性。时序一致性来自时空表示、主干结构和视频数据的共同约束，不能全部归功于 Diffusion。

**训练误差要按噪声区间观察**

工程上应按噪声区间统计训练误差，并分别检查静态镜头、快速运动和镜头切换样本。高噪声区语义结构学不好、低噪声区细节恢复差，是两类不同问题；只看一个全局平均 loss 很容易掩盖它们。

> **面试速答**：训练时通常随机采样一个噪声级别，模型用一次前向预测 $\epsilon$、$z_0$ 或 $v$，完整的多步求解主要发生在推理阶段。视频不是逐帧独立去噪，因为主干应在时空 latent 上联合预测；Diffusion 目标本身并不保证跨帧一致性。

<h2 id="4.2.3.2_面试问题：Diffusion、Flow-Matching-与-Rectified-Flow-是什么关系？">4.2.3.2 面试问题：Diffusion、Flow Matching 与 Rectified Flow 是什么关系？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

三者不能简单理解为互斥的模型类别。Diffusion 先规定数据逐渐变成噪声的随机过程，再学习其反向去噪量或 score；对应的 probability flow ODE 又能把同一组边缘分布写成确定性流。Flow Matching 则直接回归一条给定概率路径上的速度场，而这条路径既可以是扩散路径，也可以是其他路径。Rectified Flow 是强调直线插值与路径拉直的一类流模型构造，范围比 Flow Matching 更窄。

具体边界见表2-3。

<p align="center">表2-3 Diffusion、Flow Matching 与 Rectified Flow 的建模关系</p>

| 方法 | 训练时主要学习什么 | 路径如何得到 | 推理时如何生成 | 需要避免的误解 |
| --- | --- | --- | --- | --- |
| Diffusion / score-based model | 噪声、干净样本、velocity 或 score | 先定义前向加噪过程 | 求解反向 SDE、概率流 ODE 或其离散化更新 | 不等于只能随机采样，也不只支持 $\epsilon$ prediction |
| Flow Matching | 给定概率路径上的速度场 | 可使用扩散路径、OT 路径等 | 用 ODE 求解器积分速度场 | 不是 Diffusion 的简单反义词 |
| Rectified Flow | 尽量沿端点直线输运的速度场 | 给定噪声—数据耦合，使用直线插值；可进一步 reflow | 通常求解 ODE | 是流模型的一类构造，不等于所有 Flow Matching |

**Rectified Flow 如何定义直线路径**

以噪声端点 $z_n$ 和数据端点 $z_d$ 为例，Rectified Flow 常用：

```math
z_t=(1-t)z_n+t z_d, \qquad
\mathcal{L}_{\mathrm{RF}}
=\mathbb{E}\left[\left\lVert v_\theta(z_t,t,c)-(z_d-z_n)\right\rVert_2^2\right].
```

**少步采样不能只看训练目标**

直线路径通常更容易用较粗的时间离散逼近，但“使用 Flow Matching 就一定能少步采样”并不成立。实际步数还受路径弯曲程度、端点耦合、求解器阶数、训练质量、蒸馏和目标画质影响。比较两类模型时，应固定分辨率、CFG 和函数评估次数（NFE），再看画质、运动一致性与延迟；不同目标下的训练 loss 数值不能直接横向比较。

> **面试速答**：Diffusion 定义前向加噪并学习反向生成量，Flow Matching 直接学习给定概率路径的速度场；扩散路径本身也可以用于 Flow Matching。Rectified Flow 是使用直线插值并尝试拉直输运轨迹的一类方法，不等于整个 Flow Matching。是否能少步采样，要看路径和求解误差，不能只看方法名称。

<h2 id="4.2.3.3_面试问题：训练路径、推理时间步、数值求解器与-CFG-分别控制什么？">4.2.3.3 面试问题：训练路径、推理时间步、数值求解器与 CFG 分别控制什么？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

这四个概念处在不同层级：

1. **训练路径**规定 $\alpha_t$、$\sigma_t$ 或中间概率路径，决定训练时模型看到哪些信噪比和目标速度。
2. **推理时间步**选择从噪声端到数据端实际访问哪些 $t$ 或 $\sigma$。步数越少，网络调用越少，但离散误差通常更大。
3. **数值求解器**根据模型在当前状态的预测计算下一状态，例如 Euler、Heun 或 DPM-Solver 类方法。高阶方法可能减少误差，也可能增加单步网络调用。
4. **CFG**在每次模型预测时组合有条件与空条件结果，改变条件引导强度。用一般预测量 $f$ 表示：

```math
f_{\mathrm{cfg}}
=f_\theta(z_t,t,\varnothing)
+s\left(f_\theta(z_t,t,c)-f_\theta(z_t,t,\varnothing)\right).
```

其中 $s$ 是 guidance scale。增大 $s$ 往往能强化文本遵循，却可能压缩多样性，并带来颜色过饱和、结构伪影；在视频中也可能改变运动幅度或放大时序抖动。这是经验风险，不代表所有模型都会出现同一种退化。

训练与推理的关系如图2-4所示。

> **配图占位（图2-4）**：左侧画训练链路“真实视频 latent $z_0$ → 随机采样 $t$ 与噪声 → 构造 $z_t$ → 主干预测训练目标”，强调每个样本通常只取一个 $t$；右侧画推理链路“初始噪声 → 时间步网格 → CFG 条件/空条件预测 → 数值求解器更新 → 视频 latent”，标出时间步控制查询位置、求解器控制更新公式、CFG 控制预测方向。

**为什么框架里的 scheduler 容易混淆**

不少框架把“时间步离散 + 更新公式”一起封装为 scheduler，因此工程名称与理论概念不总是一一对应。替换 scheduler 或 sampler 也并非必然即插即用：prediction type、时间或 $\sigma$ 约定、输入缩放和终点处理必须与训练配置匹配，否则即使代码能运行，生成分布也可能已经错位。

**如何排查采样问题**

排查采样问题时，先记录实际 $t/\sigma$ 序列和每步网络调用次数，再用固定随机种子扫描“步数 × CFG”。低步数时结构崩坏，优先检查时间网格与求解误差；提高 CFG 后才出现饱和、闪烁或动作僵硬，再检查条件引导，而不是笼统归因于模型容量。

> **面试速答**：训练路径决定模型学哪些中间状态，推理时间步决定查询哪些状态，数值求解器决定如何从当前状态走到下一状态，CFG 决定条件方向被放大多少。工程库常把推理时间步与数值求解器一起封装为 scheduler，但替换时必须匹配 prediction type、时间参数化和缩放约定。

<h1 id="4.2.4_生成主干网络：U-Net-与视频-DiT">4.2.4 生成主干网络：U-Net 与视频 DiT</h1>

> 生成主干接收带噪视频 latent、时间信息和条件表示，输出去噪量或速度场。U-Net 与视频 DiT 的区别主要在特征组织和计算拓扑，训练目标仍由上一节的 Diffusion 或 Flow Matching 决定。

<h2 id="4.2.4.1_面试问题：U-Net-为什么适合扩散去噪？扩展到视频时需要改什么？">4.2.4.1 面试问题：U-Net 为什么适合扩散去噪？扩展到视频时需要改什么？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

U-Net 适合扩散去噪，核心在于一次预测需要同时处理不同空间尺度的信息：低分辨率特征更侧重主体布局和大范围结构，高分辨率特征更侧重边缘、纹理与局部位置。

**U-Net 为什么合适**

- **多尺度路径**：编码器逐级降低分辨率并扩大感受野，解码器再恢复空间尺寸，使同一个网络能够处理从整体结构到局部细节的预测。
- **跳跃连接（skip connection）**：把当前噪声状态下的高分辨率中间特征送到对应解码层，保留位置和边界信息。这些特征仍然含有噪声，模型需要将其与低分辨率特征融合后预测训练目标。
- **分层条件注入**：时间步嵌入、文本条件和结构控制可以进入不同分辨率层，同时影响整体语义与局部细节。

卷积还提供了局部性和平移等变的归纳偏置。需要明确的是，U-Net 只是生成主干的一种选择，Diffusion 和 Flow Matching 都没有限定必须使用哪类网络。

**扩展到视频时，需要补上跨帧信息流**

仅把输入张量增加一个时间维还不够。如果每一帧仍由同一套空间网络独立处理，模型学到的依然主要是单帧去噪。常见改法有两条：

- **复用图像 U-Net**：保留预训练的 2D 空间层，在部分分辨率层插入时间卷积、时间注意力或 motion module。这种方式便于继承已有的空间表征，新增模块的作用范围取决于插入位置和时间感受野。
- **构建时空 U-Net**：将卷积、注意力或上下采样直接扩展到时间维，统一设计空间与时间运算。这通常会增加计算量，与图像预训练权重的兼容也更复杂。

具体选择 Temporal Conv 还是 Temporal Attention 属于 4.2.5。本题要抓住的是：视频化改造必须让中间特征跨帧交换信息。

**工程上如何确认时间模块生效**

出现运动很弱、身份漂移或跨帧闪烁时，先在验证样本上关闭时间模块，或打乱带噪 latent 的帧序，观察模型预测是否明显变化；再检查时间层的梯度、输出幅度和训练数据中的运动分布。预测几乎不变，通常说明时间路径没有被有效利用，继续堆训练步数未必能解决问题。

> **面试速答**：U-Net 通过多尺度编码、解码和跳跃连接同时处理整体结构与局部细节。扩展到视频后，必须让中间特征跨帧交互；可以在图像 U-Net 中插入时间模块，也可以直接构建时空 U-Net，取舍点是预训练复用、时间建模范围和计算成本。

<h2 id="4.2.4.2_面试问题：视频-DiT-如何处理时空-latent？为什么更适合规模化？">4.2.4.2 面试问题：视频 DiT 如何处理时空 latent？为什么更适合规模化？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

视频 DiT 先把 Video VAE 输出的时空 latent 切成 3D patch，再投影为 token。时间步、文本等条件通过 AdaLN、Cross-Attention 或联合 token 序列进入 Transformer blocks；输出头把每个 token 映射为对应 patch 的噪声、干净 latent 或 velocity，最后还原成原时空网格。数据流见图2-5。

> **配图占位（图2-5）**：展示“带噪视频 latent → 3D patchify → 时空 token 与位置编码 → 多层 Transformer block”，并画出时间步调制、文本 Cross-Attention 两条条件路径；末端展示“输出投影 → unpatchify → 与输入同形状的预测张量”。明确标注 DiT 是生成主干，Diffusion 或 Flow Matching 是训练目标，两者不在同一分类层级。

<p align="center">图2-5 视频 DiT 的时空 token 化、条件注入与输出还原流程</p>

**规模化优势来自规则化 block**

规则、重复的 block 使 DiT 可以通过深度、宽度和 token 数较直接地增加计算量，也便于采用 Transformer 已有的并行与算子优化。原始 DiT 工作验证的是图像 latent diffusion 中质量随计算量扩展的经验规律；把这一结论迁移到视频时，还要处理更长的 token 序列，不能直接推出“同等算力下视频 DiT 一定更好”。

**视频侧的瓶颈是 token 预算**

视频长度或分辨率增加后，token 数会快速增长，全时空 attention 的计算和显存可能成为主瓶颈。实际模型往往采用空间与时间分解、局部窗口或稀疏 attention。具体注意力方案与位置编码属于 4.2.5，本题只需抓住一条主线：patch 大小决定 token 预算，attention pattern 决定 token 之间如何交换信息。

**实现先检查 patchify 与 unpatchify**

实现中最先核对 patchify 与 unpatchify 是否严格互逆，包括维度顺序、时间 patch、padding 和位置索引。这里一旦写错，常见现象是帧顺序异常、周期性块状伪影，或者改变帧数后质量突然下降，这些问题无法靠增加训练步数可靠修复。

“Video Transformer”是更宽泛的名称，也可能指自回归或掩码预测模型。本节所说的视频 DiT，特指在视频时空 token 上预测扩散或流模型训练目标的 Transformer 主干。

> **面试速答**：视频 DiT 把时空 latent 切成 3D patch token，经 Transformer 预测每个 patch 的去噪量或速度场，再还原为视频 latent 网格。规则化 block 便于扩大深度、宽度和 token 数，但视频 token 很长，规模化收益要和 attention 成本、数据量及训练算力一起判断。

<h2 id="4.2.4.3_面试问题：U-Net-与视频-DiT-应如何选择？Transformer-一定更优吗？">4.2.4.3 面试问题：U-Net 与视频 DiT 应如何选择？Transformer 一定更优吗？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

Transformer 没有脱离训练规模、token 预算和任务约束的普遍优势。U-Net 与视频 DiT 都可以预测 Diffusion 或 Flow Matching 的目标，选型依据是计算拓扑是否匹配现有资源和系统资产。主要差异见表2-4。

<p align="center">表2-4 U-Net 与视频 DiT 的工程选型维度</p>

| 维度 | U-Net | 视频 DiT |
| --- | --- | --- |
| 特征组织 | 多尺度 feature map，编码器与解码器通过 skip connection 对应 | 时空 patch token，标准实现以重复 Transformer block 为主 |
| 归纳偏置 | 局部性和多尺度先验较强 | 对视觉局部结构的先验较弱，更依赖数据和位置表示 |
| 扩展方式 | 需要同时调整各分辨率层的通道、深度与 attention | 较容易沿深度、宽度和 token 数规则扩展 |
| 视频化路径 | 可在图像 U-Net 中插入时间模块，也可构建时空 U-Net | 直接对时空 token 做联合或分解式 attention |
| 资产复用 | 便于继承已有图像 U-Net、ControlNet 或 motion module | 可继承图像 DiT，但 patch、位置编码和时空 attention 通常需要适配 |
| 主要成本 | 多尺度激活与高分辨率层计算 | token 数量及 attention 的计算、显存开销 |

**什么时候更倾向于哪一种主干**

已有图像 U-Net 和控制分支较多、视频数据或训练预算有限时，沿 U-Net 增加时间模块通常更容易得到稳定基线。数据和算力能够支撑规模化训练，且任务需要长程交互或统一多模态 token 接口时，视频 DiT 更有吸引力。这些是工程倾向，并非由架构名称保证的结果；时空 U-Net 也能建模长程关系，DiT 也可能因数据不足或位置设计不当而训练不充分。

**如何做公平比较**

公平比较至少要固定 VAE、训练数据、生成目标、输出分辨率与时长，并在相近训练计算量和采样 NFE 下观察生成质量。只对齐参数量不够：两类主干的 token 或 feature map 数量、激活显存、每步延迟和硬件利用率并不相同。实践中应同时记录训练吞吐、峰值显存、单步推理延迟，以及单帧质量、运动和时序一致性。

> **面试速答**：U-Net 的多尺度和局部先验较强，也便于复用已有图像扩散资产；视频 DiT 的 block 更规则，更适合按深度、宽度和 token 数扩展。Transformer 并不天然胜出，最终要在相同 VAE、数据、训练计算量和采样预算下比较质量、显存与延迟。

<h1 id="4.2.5_时空建模模块：Temporal-Layer、3D-Conv、时空注意力与位置编码">4.2.5 时空建模模块：Temporal Layer、3D Conv、时空注意力与位置编码</h1>

> 视频模型在多帧输入基础上，还需要让主干显式或隐式建模时间关系、运动变化和跨帧一致性。

<h2 id="4.2.5.1_面试问题：为什么不能把图像生成主干简单复制到每一帧？">4.2.5.1 面试问题：为什么不能把图像生成主干简单复制到每一帧？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

把图像生成主干独立应用到每一帧，只能约束每帧自身是否合理，无法直接约束帧与帧之间如何变化。

**逐帧建模缺少帧间依赖**

独立逐帧生成本质上是在建模：

```math
\prod_{t=1}^{T}p(x_t\mid c)
```

这种分解没有显式建模帧间依赖。结果可能是每一帧单独看都合理，但连起来会出现闪烁、身份变化、背景漂移和动作不连续。

**视频生成需要联合时序分布**

视频生成需要建模联合分布：

```math
p(x_{1:T}\mid c)
```

这要求模型理解同一主体如何跨帧保持一致、动作如何连续发生、相机和物体运动如何共同影响画面。

> **面试速答**：逐帧图像模型只约束单帧分布，没有显式建模帧间依赖。视频主干需要对多帧联合建模，才能同时约束主体一致性、动作连续性以及相机与物体运动。

<h2 id="4.2.5.2_面试问题：Temporal-Conv、Temporal-Attention-和-Full-Spatiotemporal-Attention-各解决什么问题？">4.2.5.2 面试问题：Temporal Conv、Temporal Attention 和 Full Spatiotemporal Attention 各解决什么问题？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

三类模块都用于建立跨帧交互，主要差别在时间感受野、时空连接范围和计算成本，具体见表2-5。

<p align="center">表2-5 Temporal Conv、Temporal Attention 与全时空 Attention 的作用范围和成本</p>

| 模块 | 核心思想 | 优势 | 局限 |
| --- | --- | --- | --- |
| Temporal Conv | 沿时间维做局部卷积 | 成本低，适合局部运动 | 长程依赖弱 |
| Temporal Attention | 同一空间位置或 token 跨时间 attention | 建模跨帧关系 | 对空间-时间耦合不足 |
| Full Spatiotemporal Attention | 所有时空 token 共同 attention | 建模能力强，全局一致性好 | 成本最高 |

Temporal Conv 用固定大小的时间核聚合邻近帧，Temporal Attention 能让同一位置或相关 token 跨帧交互，Full Spatiotemporal Attention 则允许任意空间和时间位置直接交互。

**为什么常用分解式 Attention**

实际视频模型常用 factorized attention 降低成本，例如先做 spatial attention，再做 temporal attention：

```text
spatial attention -> temporal attention
```

> **面试速答**：Temporal Conv 成本低，但时间感受野偏局部；Temporal Attention 直接建立跨帧依赖；Full Spatiotemporal Attention 的连接范围最广，计算成本也最高。实际系统常用空间与时间分解式 Attention 控制 token 开销。

<h2 id="4.2.5.3_面试问题：为什么视频-Transformer-需要时空位置编码？3D-RoPE-的作用是什么？">4.2.5.3 面试问题：为什么视频 Transformer 需要时空位置编码？3D RoPE 的作用是什么？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

Transformer 本身对 token 顺序不敏感。视频 token 不仅有空间位置，还有时间位置，因此模型必须知道每个 token 来自哪一帧、哪个空间区域。

**位置编码要同时描述时间与空间**

视频 token 的位置可以表示为：

```math
(t,h,w)
```

如果没有时空位置编码，模型很难区分“同一个物体在不同时间的位置变化”和“不同空间区域的不同物体”。

**3D RoPE 把相对位置写入 Attention**

3D RoPE 可以理解为把旋转位置编码扩展到时间、高度和宽度三个维度，使 attention 在计算 token 关系时包含相对时空位置信息。它的价值在于：

1. 提供时间顺序信息。
2. 提供空间相对位置关系。
3. 有利于不同分辨率或帧数下的外推。
4. 帮助模型区分时间位移和空间位移。

长度或分辨率外推并不是 3D RoPE 自动保证的能力，还会受到训练分布、坐标缩放和频率设计影响。

> **面试速答**：视频 Transformer 需要时空位置编码来区分 token 的帧序和空间坐标。3D RoPE 将时间、高度和宽度方向的相对位置信息带入 Attention；它有利于长度和分辨率扩展，但外推效果仍取决于训练范围与位置缩放方式。

<h1 id="4.2.6_AI-视频生成系统架构总览：从条件输入到视频输出">4.2.6 AI 视频生成系统架构总览：从条件输入到视频输出</h1>

> 完整的视频生成系统由条件编码器、Video VAE、生成主干、采样器、条件控制模块和解码器共同组成。

<h2 id="4.2.6.1_面试问题：一个典型-AI-视频生成系统的端到端流程是什么？">4.2.6.1 面试问题：一个典型 AI 视频生成系统的端到端流程是什么？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

典型视频生成系统可以概括为：

```text
text / image / video / audio / control condition
-> condition encoders
-> noisy video latent initialization
-> denoising / flow generation backbone
-> latent video
-> Video VAE decoder
-> output video
```

**任务差异主要发生在条件端**

如果是 T2V，条件主要来自文本；如果是 I2V，条件包括参考图或首帧；如果是 V2V，条件还包括源视频 latent、mask 或结构控制。不同任务的差异主要体现在条件输入和约束方式上，核心生成链路相对稳定。

> **面试速答**：典型链路是条件编码、视频 latent 初始化、主干迭代预测、采样更新和 VAE 解码。T2V、I2V 与 V2V 的主要差别位于条件输入和约束方式，生成主链路基本一致。

<h2 id="4.2.6.2_面试问题：视频生成系统的核心组件如何协同工作？">4.2.6.2 面试问题：视频生成系统的核心组件如何协同工作？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

核心组件的协同关系见表2-6。

<p align="center">表2-6 视频生成系统核心组件的职责与接口</p>

| 组件 | 负责内容 |
| --- | --- |
| Condition Encoder | 把文本、图像、音频、结构信号转成条件表示 |
| Video VAE Encoder / Decoder | 在像素视频和 latent video 之间转换 |
| Generation Backbone | 在 noisy latent 上进行去噪或流场预测 |
| Temporal Module / Attention | 建模运动和跨帧一致性 |
| Scheduler / Sampler | 控制从噪声到视频 latent 的生成路径 |
| Control Module | 注入 pose、depth、mask、trajectory、reference 等条件 |

**协同的关键是接口匹配**

视频质量由这些组件共同决定。条件编码器影响 prompt following，VAE 影响细节和压缩效率，主干影响时空建模能力，采样器影响速度和质量，控制模块影响可控性。

> **面试速答**：条件编码器负责表达控制意图，VAE 决定视频表示和信息上限，生成主干预测去噪量或速度场，采样器执行状态更新。组件能否协同，取决于表示形状、条件作用域和训练推理配置是否匹配。

<h2 id="4.2.6.3_面试问题：从架构角度看，视频生成系统最核心的设计权衡是什么？">4.2.6.3 面试问题：从架构角度看，视频生成系统最核心的设计权衡是什么？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

视频生成系统的核心设计权衡可以概括为五组关系，见表2-7。

<p align="center">表2-7 视频生成系统的主要架构权衡</p>

| 权衡 | 说明 |
| --- | --- |
| 压缩率 vs 细节保真 | latent 越小越快，但细节和运动可能丢失 |
| 全局注意力 vs 计算成本 | 全时空建模强，但 token 成本高 |
| 条件强度 vs 生成自由度 | 增强条件可能提高约束遵循，过强时会压缩多样性 |
| 主干规模 vs 推理延迟 | 更大主干通常具有更高容量，也会增加训练和推理成本 |
| 统一架构 vs 专用模块 | 共享主干可以减少独立模型，但多任务干扰更难控制 |

**任务目标决定权衡方向**

这些权衡决定了不同视频系统的架构选择。研究模型可能更重视生成质量和扩展性，工业系统还必须考虑速度、稳定性、成本和可控性。

> **面试速答**：视频生成架构需要同时权衡表示压缩、时空交互、条件约束、主干规模和部署成本。研究设定通常更关注质量与扩展性，实际部署还要把延迟、显存、稳定性和可控性纳入同一组约束。
