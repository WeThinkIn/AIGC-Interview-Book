## 1. 从长序列计算到混合记忆

<a id="sota-section-1-question-1"></a>
### 面试问题：为什么前沿模型混用递归状态与全局注意力？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

全局注意力允许当前位置直接读取任意历史 Token，但长上下文的预填充计算和解码 KV 存储持续增长。递归状态只保存固定维度的压缩记忆，解码不必把所有旧 Token 当成 KV 逐一读取；代价是压缩可能丢失需要精确回溯的细节。因此，混合架构把“便宜的持续记忆”和“昂贵的精确寻址”分给不同层。

以 Kimi Delta Attention（KDA）为例，单头状态 $S_t$ 的更新可写成：

$$
S_t=(I-\beta_t k_tk_t^{\mathsf T})\mathrm{Diag}(\alpha_t)S_{t-1}+\beta_tk_tv_t^{\mathsf T},\qquad o_t=S_t^{\mathsf T}q_t.
$$

$\alpha_t$ 是逐通道遗忘系数，$\beta_t$ 控制写入强度；前一项先衰减旧状态并修正与当前键相关的旧内容，后一项写入新键值。

> **注**：固定大小的 $S_t$ 不能保证保留任意数量的独立事实。

| 公开实例 | 混合方式 | 解决的瓶颈 | 缺点 |
| --- | --- | --- | --- |
| [Kimi Linear](https://arxiv.org/abs/2510.26692) / [Kimi K3](https://arxiv.org/abs/2607.24653) | KDA 与 MLA/Gated MLA 混用；K3 每组为 3 层 KDA、1 层 Gated MLA，末尾另有全局层 | 减少长序列状态与 KV 访问 | 递归层的精确回溯能力有限，混合核更复杂 |
| [Qwen3.8-Flash-Next](https://arxiv.org/abs/2608.30320) | 每 4 层中 3 层 Gated DeltaNet（GDN）、1 层全局注意力；继续预训练时后者换为 QSA | 用固定状态承担大部分 Token 混合 | 稀疏索引的训练与服务成本仍需计算 |

<a id="sota-section-1-question-2"></a>
### 面试问题：动态稀疏注意力为什么仍可能很慢？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

稀疏主注意力若每个查询只看 $k$ 个历史位置，核心计算可从约 $O(L^2)$ 降为 $O(Lk)$，但选出这 $k$ 个位置也要成本。

| 路线 | 如何减少索引或主注意力成本 | 缺点 |
| --- | --- | --- |
| [NSA](https://arxiv.org/abs/2502.11089) | 压缩表示、选择性块和局部窗口结合 | 压缩或块选择可能漏掉细粒度证据 |
| [DSA](https://arxiv.org/abs/2512.02556) | 轻量索引器选历史 Top-k，再执行稀疏注意力 | 索引器与不规则访存可能成为瓶颈 |
| [IndexCache](https://arxiv.org/abs/2603.12201) | 多层复用一层选出的索引 | 层间需要的位置未必相同，复用过度会漏检 |
| [QSA](https://arxiv.org/abs/2608.30320) | 对压缩后的微块打分；压缩比为 $r$ 时索引计算约为 $O(L^2/r)$ | 仍有随长度增长的索引开销和块级误选 |

## 2. 从层数堆叠到跨层信息流

<a id="sota-section-2-question-1"></a>
### 面试问题：AttnRes、mHC 和 GR 分别改进了残差路径的什么问题？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

普通前置归一化残差把以前各层的信息不断累积到一个状态 $h_l$；网络越深，后层只能从这一个累积表示读取历史。

| 方法 | 核心做法 | 缺点 |
| --- | --- | --- |
| [Attention Residuals（AttnRes）](https://arxiv.org/abs/2603.15031) | 对前面层的输出按内容计算权重，再聚合为当前层输入 | 全层版本需保存并读取多层输出 |
| [mHC](https://arxiv.org/abs/2512.24880) | 扩宽残差流，并约束分支混合矩阵以维持稳定的信息传递 | 约束与分支混合有额外计算、访存开销 |
| [Gated Residual（GR）](https://arxiv.org/abs/2608.30320) | 扩宽为多分支残差流，用逐元素门控读取，不做完整分支混合 | 更宽的残差状态仍占用内存；要与优化器共同验证稳定性 |

## 3. 从参数扩张到有效容量

<a id="sota-section-3-question-1"></a>
### 面试问题：高稀疏 MoE 的瓶颈为什么会转向通信和稳定性？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

专家总量增大后，单 Token FLOPs 仍可能可控，但专家所在设备间的 Token 调度、热门专家偏斜、激活异常和权重访存会先成为瓶颈。

MoE系统的总参数影响权重存储，每 Token 激活参数近似反映专家计算，端到端时延还包含专家通信、共享路径、路由器、空闲设备和批处理效率。此外，路由通道先投影到较窄潜空间，再交给专家处理，连续投影和门控进一步放大数值不稳定风险。

- Kimi使用投影前归一化、SiTU-GLU 和 Quantile Balancing 缓解。[Kimi K3 技术报告](https://arxiv.org/abs/2607.24653)
- MoonEP 则在系统侧通过动态冗余专家放置与静态计算形状应对偏斜。 [MoonEP 官方仓库](https://github.com/MoonshotAI/MoonEP)
- DeepSeek-V3 的无辅助损失负载均衡减少了平衡损失对语言建模目标的干扰。[DeepSeek-V3 技术报告](https://arxiv.org/abs/2412.19437) 

<a id="sota-section-3-question-2"></a>
### 面试问题：N-gram 嵌入为何能增加容量，却未必提高下游能力？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐ (3/5)**

Qwen3.8-Flash-Next 把确定性寻址的 N-gram 嵌入表放在加速器外，按需预取，通过查表增加存储容量，但让每 Token 不必执行等量的矩阵乘法。但关键限制是“存储更多常见片段”不等于“学会更强的组合推理”。[Qwen3.8-Next 报告第 2.3 节](https://arxiv.org/html/2608.30320v1)

- 在保持 MoE 参数量不变、额外扩大 N-gram 表的实验中观察到训练 Loss 持续下降，但多个下游指标趋于饱和或波动；
- 在固定总参数预算、用 N-gram 表替换部分专家的实验中，Loss 也非单调下降。

> **注**：论文报告其主干为 125B 总参数、6B 激活参数，另有 51B N-gram 嵌入参数。

## 4. 从单步预测到训练与解码协同

<a id="sota-section-4-question-1"></a>
### 面试问题：MTP 如何服务推测解码？何时能保持目标分布不变？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

多 Token 预测（MTP）：

- 在训练时为未来若干位置提供辅助预测信号；

- 在推理时，附加模块可充当草稿生成器，一次提出多个候选 Token，目标模型再并行验证。

DeepSeek-V3 公开将 MTP 用作辅助训练目标；Qwen3.8-Next 报告还说明其 MTP 模块复用稀疏注意力索引以降低草稿成本；Kimi K3 将据此微调预训练的 MTP 层作为草稿模型，使用接受率的负对数损失。

训练目标可以概括为主损失加辅助损失：

$$
\mathcal L=\mathcal L_{\mathrm{next}}+\lambda\sum_{j=2}^{K}w_j\mathcal L_{t+j}.
$$

真实加速取决于连续接受长度与验证成本。单步接受率可写成 $\sum_x\min(p(x),q(x))$。草稿越弱，验证后能省掉的串行目标步数越少；batch 较大或内存带宽不再是主瓶颈时，收益也可能变小。

<a id="sota-section-4-question-2"></a>
### 面试问题：优化器与低精度为什么必须和架构一起设计？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

新架构改变矩阵形状、激活分布和有效批量后，原先最优的学习率、批大小和精度策略可能失效。

- Muon 对部分二维权重的动量矩阵做近似正交化。Qwen3.8-Next 将主二维映射使用 Muon，嵌入、输出头、路由器等仍用 AdamW，并在新架构下重新拟合学习率与批大小；Kimi K3 则对注意力投影采用按头分块的 Muon 正交化，避免把不同头强行作为一个矩阵处理。

- DeepSeek-V3 公开 FP8 训练方案；Kimi K3 报告在后训练阶段讨论 MXFP4 量化感知训练。

<a id="sota-section-4-question-3"></a>

### 面试问题：思考预算为什么要按任务分配，而不是一律拉满？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

测试时增加推理 Token、工具调用或并行候选，可能提高困难任务的成功率；但简单任务的额外计算通常只增加延迟和费用，长推理还可能积累错误

- Qwen3 报告公开 thinking/non-thinking 模式与可设定思考预算；
- Kimi K3 报告按任务给初始预算，对超出预算倍数的训练轨迹施加惩罚，再把不同推理强度的专家能力蒸馏到统一模型；
- DeepSeek-V3.2 则强调工具调用之间保留必要推理状态，避免每次收到工具结果都重新推导全部问题。

共同目标是把每单位额外计算换来的成功率增量最大化

闭源产品也公开了接口层的预算控制：

- OpenAI 的 `reasoning.effort` 和 Claude 的 `output_config.effort` 用于调整思考强度。

工程上可比较不同预算 $B$ 下的任务成功率 $S(B)$ 和成本 $C(B)$，选择边际收益仍足以覆盖边际成本的区间；不同任务难度的曲线不同，不存在统一的最佳思考难度。

## 5. 从单轮推理到长程 Agent 训练

<a id="sota-section-5-question-1"></a>
### 面试问题：异步 Agent RL 为什么提高吞吐又带来策略偏移？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

长程 Agent 的不同任务可能分别耗时数秒到数小时。同步收齐一批轨迹时，训练设备必须等待最慢任务。

- GLM-5 报告将采样/执行与模型更新解耦，持续生成轨迹后送入训练器，从而减少这种等待；代价是轨迹可能由旧策略 $\pi_{\mathrm{old}}$ 生成，而梯度更新使用较新的 $\pi_\theta$。$\Delta\pi$ 越大，直接把旧轨迹当作当前策略样本的偏差风险越高；实际系统需要定期同步权重、跟踪轨迹的策略版本，并控制或屏蔽严重离策略样本。GLM-5 报告还强调保留生成时的精确 Token 流，避免训练端重新分词造成边界错位。[GLM-5 技术报告](https://arxiv.org/abs/2602.15763)
- Kimi K3 报告说明百万 Token 级交互轨迹需要部分 rollout、外部 KV 保留和可恢复沙盒，才能在有限资源下延续环境与模型状态。[Kimi K3 技术报告](https://arxiv.org/abs/2607.24653)

<a id="sota-section-5-question-2"></a>
### 面试问题：上下文压缩为何必须进入训练，而不只是推理技巧？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

长任务超过窗口上限时，系统可把旧历史压成摘要，再继续执行。但摘要是有损状态：遗漏约束、文件路径或工具失败信息，会在后续步骤放大。只在推理时压缩、训练时始终给完整历史，会造成训练与执行分布不一致。

CompactionRL 把生成摘要和继续完成任务放进同一条训练轨迹，让最终任务奖励影响摘要策略；同时处理压缩造成的片段长度不均和跨片段信用分配。

该论文在其 SWE-bench Verified 设置下报告 GLM-4.5-Air 相比“仅推理时压缩”提升 7.0 个百分点。[CompactionRL 论文](https://arxiv.org/abs/2607.05378)

## 6. 如何判断一项跨周期技术值得采用？

<a id="sota-section-6-question-1"></a>
### 面试问题：如何比较不同报告中的质量、效率和成本？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

| 维度 | 关注点 | 
| --- | --- | --- |
| 能力 | 相同数据、提示、工具权限、推理预算下的下游评测（长文本需看证据位置） | 
| 训练效率 | 激活参数、训练 Token、实际 FLOPs、GPU 利用率与稳定性 |
| 服务效率 | 同硬件、同 batch/上下文/输出长度的预填充、解码和整请求时延 | 
| 系统可靠性 | 索引漏检、路由偏斜、数值异常、Agent 失败恢复 | 
| 证据等级 | 技术报告、模型卡、代码、可复现实验与闭源产品声明分别是什么 |
