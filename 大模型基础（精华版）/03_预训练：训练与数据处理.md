## 15. 如何估算大语言模型的训练资源与成本？

<a id="pretraining-section-15-question-01"></a>
### 面试问题：训练大语言模型的核心资源要素有哪些？为什么说它是资本密集型工程？

**难度评分：⭐⭐ (2/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

- **核心资源要素**包括：（1）算力资源，如 GPU/TPU 集群、高速互联网络、分布式训练系统；（2）数据资源，如高质量通用文本、代码数据、数学数据、领域专用数据和偏好数据；（3）基础设施资源，如数据中心、存储系统、网络系统、任务调度系统；（4）人力资源，如算法工程师、系统工程师、数据工程师、平台工程师和安全合规团队；（5）软件工具资源，如训练框架、并行训练框架、数据治理平台、监控系统和评估系统。

- **资本密集型原因**：（1）投入规模大，前沿超大模型训练需要大量高端 GPU 和长期训练周期，单轮训练成本可能达到数千万到数亿美元量级；（2）技术门槛高，高端芯片、高速互联、分布式训练框架和万卡集群运维都有很高复杂度；（3）风险成本高，硬件故障、数据污染、训练不稳定、NaN、通信异常或检查点损坏都可能导致大规模训练中断，造成显著算力浪费；（4）迭代速度快，模型架构、数据配比和后训练方法快速演进，训练投入还伴随较高的技术路线风险。

<a id="pretraining-section-15-question-02"></a>
### 面试问题：如何用 6ND 公式估算稠密与混合专家（MoE）预训练的浮点数计算次数（FLOPs）？

**难度评分：⭐⭐ (2/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

#### 1. 最常用的粗估公式是什么？

稠密仅解码器变换器（Decoder-only Transformer）的预训练算力常用近似为：

```math
\text{FLOPs}_{\text{train}} \approx 6 \times N \times D
```

其中，$N$ 是每个词元（token）训练时参与计算的有效参数量，稠密模型中可近似为总参数量；$D$ 是训练 token 总数。系数 6 来自经验分解：前向约 $2ND$，反向和参数梯度约 $4ND$。这是面试中最常用的一级估算，但它是粗估，不精确包含通信、数据加载、填充、激活检查点、软最大值、层归一化和失败重训等开销。

#### 2. 混合专家（MoE）模型为什么不能直接用总参数量估算？

MoE 的总参数量可能很大，但每个 token 只激活部分专家，因此应按**每个 token 实际激活的参数量**估算：

```math
\text{FLOPs}_{\text{train}} \approx 6 \times \left(N_{\text{dense}} + k \times N_{\text{expert-single}}\right) \times D
```

$N_{\text{dense}}$ 是每个 token 都会经过的稠密参数， $k$ 是每个 token 激活的专家数， $N_{\text{expert-single}}$ 是单个专家参数量。

<a id="pretraining-section-15-question-03"></a>

### 面试问题：如何分析分组注意力（GQA）、多头注意力（MQA） 和多头潜在注意力（MLA）对训练 FLOPs 的影响？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐ (3/5)**

#### 1. 先区分投影计算与 Attention 计算

分组注意力和多头注意力（GQA/MQA）主要减少 **键值（K/V）投影参数**，并降低生成阶段的状态与访存压力（部署细节见推理部署篇），不代表整个注意力 FLOPs 会按 K/V 头数等比例下降。粗略分析时可区分两部分：

- 线性投影计算：K/V 投影会随 KV 头数减少而下降；
- 注意力分数计算：仍主要受查询（Q）头数、序列长度 $S$ 和隐藏尺度（hidden size）影响，标准密集注意力仍近似有 $O(S^2)$ 成本。

对于 MLA，需要结合潜在层的维度、投影矩阵结构和具体实现估算，不能简单套用 GQA 比例。面试中可以先给 $6ND$，再说明这些结构需按有效激活参数和具体算子修正。

<a id="pretraining-section-15-question-04"></a>
### 面试问题：如何从理论浮点数计算次数（FLOPs）估算训练时间和项目成本？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

#### 1. 从理论算力到实际训练时间

理论 FLOPs 不是训练耗时。训练时间常用近似：

```math
T \approx \frac{\text{FLOPs}_{\text{train}}}{G \times \text{FLOPs}_{\text{GPU-peak}} \times \text{MFU}}
```

其中 $G$ 是 GPU 数量，MFU 是模型浮点运算利用率。MFU 受并行策略、批量规模（batch size）、序列长度、通信重叠、算子融合、显存带宽和数据管线影响。快速注意力（Flash Attention）通常不是减少理论 FLOPs，而是减少 HBM 读写、提升实际吞吐；FP8/BF16 主要提升硬件有效吞吐和降低显存；激活检查点会省显存但增加重算开销。

训练成本可进一步估算为：

```math
\text{Cost}_{\text{GPU}} \approx T_{\text{hours}} \times G \times \text{Price}_{\text{GPU-hour}}
```

真实成本还要加上存储、网络、数据处理、评估、集群运维、人力和失败重训成本。

## 16. 如何搜集和处理大语言模型的训练数据？

<a id="pretraining-section-16-question-01"></a>
### 面试问题：大语言模型预训练为什么需要多来源数据？不同数据来源各有什么作用和风险？

**难度评分：⭐⭐ (2/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

#### 1.为什么大语言模型与训练需要多来源数据？

大语言模型带来的变化在于：预训练数据规模更大、来源更复杂、能力目标更通用，因此通常需要混合 **网页、书籍、百科、论文、代码、问答社区、对话数据、领域语料、合成数据和机器转写文本** 等多类语料。Common Crawl 提供广覆盖的原始 Web 供给，但不是可直接训练的“高质量数据集”。从原始语料到训练配方，需经历正文抽取、语言识别、去重及质量与合规过滤等步骤；这些步骤的严格程度最终决定了入选语料的规模。

**不同来源对应不同能力**：网页提供通用知识和语言覆盖，书籍和论文提升长文本理解与知识密度，代码增强程序生成、符号结构和逻辑模式，问答与社区对话数据提升解释表达和交互风格，领域语料决定垂直模型的专业上限。**多来源数据的核心价值，是让模型在通用语言能力、知识覆盖、推理能力、代码能力、多语种能力和领域能力之间取得更好的平衡。**

从训练目标看，大语言模型通常做下一词元预测（next token prediction），即 $P(x_t \mid x_{<t})$。

训练本质是在拟合训练数据分布。某类数据占比越高，它对梯度更新的贡献越大，模型就越容易学习该类数据中的语言模式、知识结构、表达风格和推理方式。因此数据不能简单理解为越多越好，而是要看**质量、分布和目标能力是否匹配**。

#### 2.不同来源的数据有什么贡献和风险？

| 数据来源   | 主要贡献                     | 优点                   | 风险或缺点                 |
| ---------- | ---------------------------- | ---------------------- | -------------------------- |
| 网页 | 通用知识、语言覆盖、多样表达 | 规模大、覆盖广、更新快 | 噪声、广告、重复内容多     |
| 书籍       | 长文本、表达质量、逻辑连贯性 | 结构完整、语义密度高   | 更新慢、版权风险高         |
| 百科       | 事实知识、实体关系           | 结构清晰、事实密度高   | 表达形式单一、覆盖有限     |
| 论文       | 专业知识、科研表达、复杂推理 | 专业性强、术语规范     | 解析复杂、领域偏窄         |
| 代码       | 编程能力、符号结构、逻辑模式 | 结构严格、可验证       | 许可证、重复仓库、低质代码 |
| 问答/社区对话 | 解释表达、交互风格、问题形式 | 接近真实用户提问方式   | 质量不稳定，可能引入偏见   |
| 领域语料   | 行业知识、业务流程、专业术语 | 专业密度高             | 获取难、标注贵、合规要求高 |
| 合成数据   | 长尾任务、稀缺场景、格式控制 | 可控、成本低、易扩展   | 可能放大幻觉和模板化       |
| 机器转写文本 | 光学字符/自动语音识别得到的文本资料、扫描文档转写 | 扩展文本语料覆盖范围       | 转写错误和噪声         |

工业界通常采用多源混合，而不是依赖单一来源。配比调优很关键：高质量代码、数学、论文和领域数据占比提高，可能增强特定能力，但也可能牺牲通用表达、多样性或多语种覆盖。因此，大语言模型预训练数据治理的重点不只看“收集更多数据”，而是建立与目标能力匹配的数据分布。

<a id="pretraining-section-16-question-02"></a>
### 面试问题：数据规模是否越大越好？如何理解数据规模、模型参数量与缩放定律（Scaling Law）的关系？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

在既定算力约束下，一次训练所能消耗的 token 总量是有限的，这便构成了一道“算力—数据”的预算边界，最重要的是否有足够多的高质量、低重复、并与目标能力相契合的内容。

同时，模型参数量与训练 token 数量之间需要保持大致匹配。参数量很大而训练数据不足，模型未能充分拟合语料中的规律，就会出现欠训练；反过来，模型规模较小而数据量过大，新增 token 能够提供的边际收益会不断降低，继续训练也难有实质提升。

**工程上判断数据规模与模型规模是否匹配**，可以从以下几个信号入手：

- 训练损失与验证损失：观察其是否仍在持续、平稳地下降；若已趋于平坦或出现回升，说明当前数据规模可能接近收益极限。
- 下游任务能力：知识问答、代码生成、数学推理、逻辑推理和长文本处理等能力是否随训练同步提升。
- 去重率与清洗保留率：若原始语料经过去重和过滤后保留比例很低，说明账面规模存在较大虚增，实际有效语料远少于表面数量。
- 单位算力收益：继续扩充训练数据所换来的性能提升，是否依然值得投入相应的计算成本。
- 目标能力覆盖面：如果当前模型在某些能力维度上仍存在明显短板，往往并非只是数据总量不足，而是特定类型或特定质量的语料占比不够，需要调整配比而非简单增加规模。

## 17. 如何治理和评估大语言模型预训练数据质量？

<a id="pretraining-section-17-question-01"></a>
### 面试问题：LLM 预训练语料清洗与传统数据清洗有什么不同？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

大语言模型预训练语料清洗的不同在于：数据规模很大，来源包括网页、书籍、论文、代码、社区问答、多语种语料和领域文档，清洗目标不只是让数据“干净”，还要提高训练集中的**有效 token 密度**，减少乱码、广告、模板页、重复文本、低质回答、隐私信息、有害内容和评测集污染对训练的干扰。

- 有效 token 密度：在相同训练算力下，让模型看到更多有信息量、可学习、与目标能力匹配的 token。大语言模型训练成本很高，低质量 token 不仅浪费算力，还可能让模型学习到错误事实、模板化表达、垃圾网页模式、隐私泄露模式或不安全内容。

标准流程通常是：

```text
原始数据采集 → 格式解析 → 语言识别 → 编码修复 → 乱码/空文本过滤 → 正文抽取 → 去重 → 质量过滤 → 隐私与敏感信息处理 → 安全过滤 → 评测污染检测 → 版权与许可证审查 → 人工抽检与版本入库
```

清洗强度不能简单越强越好。过弱会保留噪声、重复和风险内容，过强则可能误删长尾知识、少数语言、代码片段、公式、法律条文、医学术语、口语表达和领域文档，导致模型知识覆盖变窄、风格单一或领域能力下降。

实际工程中更常用**分层过滤 + 质量打分 + 加权采样**：高质量数据提高权重，中等质量数据降权，低质量或高风险数据删除，特殊领域数据使用领域规则单独处理。

<a id="pretraining-section-17-question-02"></a>
### 面试问题：为什么 LLM 预训练中特别重视数据去重？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

大语言模型预训练中特别重视去重，是因为预训练直接按 token 消耗算力，重复样本会浪费训练预算、降低数据多样性、增强模型记忆化，并增加评测集污染（benchmark contamination）的风险。

从训练目标看，大语言模型通常做 next token prediction。若训练集中大量出现重复文本，模型会反复看到相同模式，其梯度贡献会被放大，导致模型更容易记住具体表述，而不是学习可泛化的语言、知识和推理规律。对于网页转载、模板页、代码仓库分支、题库答案和评测集泄漏，去重尤其重要。

先做 **URL/来源级过滤和文档级粗去重**，快速降低规模；再做 **段落级去重**，删除模板、导航栏、版权声明、页脚等局部重复；最后对评测集、题库和高价值数据做更严格的 **n-gram重叠度或 嵌入向量的相似度污染检测**。

去重也不是越强越好。阈值过低会误删同一事件的不同报道、同一 API 的不同实现、同一概念的不同解释、法律条文、论文公式和代码模板；阈值过高又会漏掉大量转载、采集页和模板内容。实际工程中通常会按数据类型设置不同阈值，并在重复样本中保留来源更可信、格式更完整、质量更高的一份。**大语言模型预训练去重的重点不是追求“完全无重复”，而是在算力效率、数据多样性、模型记忆风险和评测可信度之间取得平衡。**

<a id="pretraining-section-17-question-03"></a>
### 面试问题：为什么 LLM 训练语料需要重点处理隐私、版权和隐私？如何降低模型记忆风险？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

模型可能在预训练中记忆部分训练样本，并在特定 prompt 下复述姓名、电话、邮箱、地址、API Key、内部文档、病历、合同文本、版权书籍或版权代码片段。因此，大语言模型训练语料治理的目标不仅是满足合规要求，还要降低模型记忆和泄露敏感信息的风险。常见高风险对象包括手机号、邮箱、身份证号、银行卡号、地址、姓名、API Key、访问令牌、医疗记录、合同文本、内部文档、版权书籍和版权代码。

隐私信息（PII）往往是低频但高风险 token，对通用语言能力帮助很小，却可能被模型记住并在特定 prompt 下复现。因此原则是：**能删除就删除，确实需要保留语义结构时才做脱敏替换**。例如把真实手机号替换为 `[PHONE]`，把邮箱替换为 `[EMAIL]`，把姓名、地址等上下文隐私替换为通用占位符，既保留文本结构，又降低泄露风险。

工程上通常按风险分级处理：身份证、银行卡、API Key、访问令牌、病历、合同和内部文档直接删除；姓名、地址、联系方式根据任务需要脱敏；版权不明确的数据进入隔离区，等待授权、来源确认或人工审核；授权明确且许可证允许的数据才进入可训练集合。

降低模型记忆风险通常需要训练前、训练中和训练后共同治理。训练前要做 PII 检测、脱敏、版权审查和来源过滤；训练中要减少高风险文本重复出现，避免低频敏感样本被过度记忆；训练后还要通过记忆探测、红队测试、安全评测和输出侧拦截，降低模型复述私人信息、密钥、内部文档或版权长文本的概率。**大语言模型语料合规的重点不能简单理解为“删敏感词”，而是在数据可用性、模型能力、隐私保护、版权风险和输出安全之间取得平衡。**

<a id="pretraining-section-17-question-04"></a>
### 面试问题：LLM 预训练数据质量如何评估？为什么质量比单纯规模更重要？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

大语言模型预训练数据质量评估的特殊之处在于：模型训练按 token 消耗算力，低质量 token 不仅浪费训练预算，还可能让模型学习到错误事实、垃圾网页模式、模板化表达、隐私泄露模式或不安全内容。

因此，大语言模型预训练数据质量评估的核心，不只是判断文本是否“干净”，而是判断样本能否提供 **有效训练信号**。高质量数据通常具有信息密度高、表达自然、结构完整、事实相对可靠、重复度低、与目标能力匹配等特点。相比单纯扩大数据规模，提高有效 token 密度往往能更直接地提升训练效率和模型能力。

通常结合**规则、分类器、困惑度评估、强模型打分和人工抽检**进行质量评估，而不是依赖单一指标。

> **注**：**困惑度需要特别谨慎**：困惑度过高可能说明文本是乱码、异常字符或低质量采集内容，也可能只是因为它属于代码、论文、医学术语、法律条文、数学公式或少数语言；困惑度过低则可能说明文本高度模板化、重复严重，甚至存在训练集泄露或评测集污染。

<a id="pretraining-section-17-question-05"></a>
### 面试问题：如何避免评测集污染（benchmark contamination）？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

Benchmark contamination 指训练数据中包含评测题、答案、解析或高度相似内容，导致模型依靠记忆而不是泛化能力答题，从而让评测分数虚高。它在数学、代码、考试题、知识问答等任务中尤其常见，因为公开题库经常被博客、论坛、GitHub 和教程转载。

```text
收集公开 benchmark → 建立题目/答案/解析指纹库 → 对训练数据做精确匹配、n元语法（n-gram）、最小哈希（MinHash）、相似哈希（SimHash） 或 嵌入向量检测 → 删除或降权高度相似样本 → 使用私有测试集和动态评测复核
```

| 方法              | 作用                             | 适用场景               |
| ----------------- | -------------------------------- | ---------------------- |
| Exact Match       | 检测完全重复题目或答案           | 原题、标准答案         |
| n-gram overlap    | 检测连续片段重叠                 | 数学题、考试题、代码题 |
| MinHash / SimHash | 检测大规模近似重复               | 网页、文档级污染       |
| 嵌入向量相似度    | 检测语义改写和同义题             | 高价值 benchmark       |
| 时间切分          | 避免训练数据包含评测发布后的题解 | 新题、动态评测         |

> **注**：第一，不能只检测题目，也要检测答案和解析；第二，不能只做精确匹配，因为很多污染来自翻译、改写和题解；第三，发布级评估不能只依赖公开 benchmark，还要保留私有测试集、动态评测集和时间后验数据。

<a id="pretraining-section-18"></a>
## 18. 如何组织预训练数据配比、版本和样本构造？

<a id="pretraining-section-18-question-01"></a>
### 面试问题：分词器（Tokenizer）、词表大小与切分度（fertility）如何影响预训练效率和多语言能力？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

Tokenizer 决定模型看到的离散单位，进而决定序列长度、词表 softmax 与语言间的 token 预算公平性 。Unigram从候选子词集合中删除贡献小的项；SentencePiece 是直接处理原始 Unicode 文本的训练/编码框架，可实现 BPE 或 Unigram。多语言场景要监控 fertility，即单位原始文本产生的平均 token 数：

```math
\text{fertility}(\ell)=\mathbb{E}_{x\sim\ell}\left[\frac{n_{\text{token}}(x)}{n_{\text{word/char}}(x)}\right]
```

fertility 高会更快耗尽上下文，并提高 Attention 和训练 token 成本。增大词表通常降低 fertility，却使输入 embedding 和未绑定 LM head 各增加约 $Vd$ 参数；词表过小则让低资源语言、代码和罕见词被切得过碎。应按语言分别评估 fertility、覆盖率与下游能力。

<a id="pretraining-section-18-question-02"></a>
### 面试问题：不同来源、不同质量的数据如何做混合配比？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

#### 1.什么是数据混合配比？

数据混合配比决定模型能力偏向。通用基座模型需要平衡网页、书籍、百科、论文、代码、数学、问答和对话数据；代码模型会提高代码仓库、技术文档和编程问答比例；行业模型会提高领域语料权重，同时保留通用数据，避免语言能力退化。

多源混合可以表示为：

```math
p_{\text{mix}} = \sum_i \alpha_i p_i
```

其中 $p_i$ 是第 $i$ 类数据分布， $\alpha_i$ 是采样权重。提高某类数据的权重，本质上就是提高它对梯度更新的贡献，使模型更倾向于学习该类数据中的知识、表达和推理方式。

| 模型类型      | 配比重点                                   | 目标                         |
| ------------- | ------------------------------------------ | ---------------------------- |
| 通用基座模型  | 网页、书籍、百科、论文、代码、数学均衡混合 | 建立通用语言、知识和基础推理 |
| 代码模型      | 代码仓库、技术文档、编程问答、单元测试     | 提升代码生成、调试和工具调用 |
| 数学/推理模型 | 数学题、证明过程、代码、可验证答案         | 提升多步推理和答案正确率     |
| 行业模型      | 医疗、金融、法律等领域语料 + 通用数据      | 增强专业性并避免通用能力退化 |
| 对话助手模型  | 指令、问答、多轮对话、偏好数据             | 提升指令跟随、交互和安全性   |

#### 2.怎么做数据混合配比？

- 经验划分；
- DoReMi：先训练小型参考/代理模型，以跨数据域的最坏**超额损失**为信号，用 Group DRO 更新域权重，再用所得权重训练大模型（在没有指定下游任务时，如何减少最差数据域的相对损失）。
- RegMix 则在多种配比上训练许多小模型，将“配比 $\rightarrow$ 验证表现”拟合为回归问题，预测未试配比，再把候选最优配方放大验证。

配比没有固定公式，通常通过实验迭代确定：

```text
设定目标能力 → 数据分桶与质量打分 → 设置初始采样权重 → 小规模训练 → 验证集和 benchmark 评估 → 消融分析 → 调整配比并扩大训练
```

判断依据包括**验证集 loss、下游任务表现、质量分数、重复率、污染风险、目标能力缺口和通用能力回归**。

很多训练还会采用**阶段式配比**：早期使用覆盖广的通用数据建立基础语言和世界知识，中期提高书籍、论文、代码、数学等高质量数据比例，后期加入更多指令、领域或能力增强数据，使模型向目标能力收敛。

<a id="pretraining-section-18-question-03"></a>
### 面试问题：为什么 LLM 预训练的数据版本管理比普通机器学习更复杂？如何保证可复现？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

大语言模型预训练的数据版本管理更复杂，是因为训练数据通常达到百亿到万亿 token 级别，来源多、处理链路长、清洗规则频繁变化，并且词元化 （tokenization）、样本打包（packing）、混洗（shuffle）和数据混合比例都会直接改变最终训练样本。大模型训练数据应像代码一样做版本化管理。每次训练都要能追踪使用了哪些原始数据、经过哪些处理流程、采用什么过滤阈值、使用什么数据配方、如何混合采样，以及最终生成了哪些训练样本。否则当模型能力变化、出现评测污染、隐私泄露或版权争议时，很难回溯问题来自哪一批数据或哪一次处理规则变更。

<a id="pretraining-section-18-question-04"></a>
### 面试问题：如何为低资源领域的 LLM 构造高质量训练数据？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

在医疗、法律、金融、工业等低资源或高合规领域，高质量数据往往少、标注贵、获取难、合规要求高，通常需要结合专家、模型、规则和权威资料构造训练样本。主要目标是提高**领域知识密度、任务覆盖度、事实正确性、表达多样性和输出格式真实性**，同时避免引入未经验证的专业建议、隐私信息或版权风险。

| 方法          | 核心思路                       | 优点             | 局限                 | 适用场景               |
| ------------- | ------------------------------ | ---------------- | -------------------- | ---------------------- |
| 专家标注      | 由领域专家构造或审核样本       | 质量最高         | 成本高、周期长       | 医疗、法律、金融       |
| 真实数据脱敏改写 | 对业务日志、案例或文档脱敏后改写 | 贴近真实场景     | 合规要求高、流程复杂 | 客服、金融、工业、政企 |
| Self-Instruct | 用大模型生成指令和回答         | 扩展快、覆盖广   | 可能空泛、重复、幻觉 | 指令微调、长尾任务     |
| RAG 生成      | 基于领域文档检索后生成问答     | 事实依据更强     | 依赖检索质量         | 知识密集型领域         |
| 回译          | 翻译后再翻译回来               | 增加表达多样性   | 不增加新知识         | 低风险改写             |
| 模板生成      | 基于规则批量生成样本           | 稳定可控         | 容易模板化           | 表单、客服、结构化任务 |
| 弱监督标注    | 用规则、词典或旧模型自动打标签 | 成本低           | 标签噪声较大         | 分类、抽取、检索       |
| 知识蒸馏      | 用强模型生成训练样本           | 可迁移强模型能力 | 依赖教师模型质量     | 小模型、行业模型       |
| 人机协同改写  | 模型生成，专家审核修正         | 兼顾规模和质量   | 需要流程管理         | 高质量 SFT 数据        |

**合成数据必须做质量控制**，否则会形成错误反馈链路，把生成模型的幻觉、偏差和模板化表达重新注入训练集。常见控制包括 **事实校验、去重过滤、一致性检查、专家抽检、模型打分、verifier 校验和来源追踪**。（例：对数学、代码、规则类任务，可以用程序、单元测试或判题器验证答案；对医疗、法律、金融等高风险领域，通常需要专家审核，或基于权威文档的 RAG 生成，并明确定位为辅助性数据构造，而不是替代专业判断。）

>  **注**：实际工程中通常采用“少量高质量真实数据 + 专家规则 + RAG 生成 + 强模型蒸馏 + 人工抽检”的组合方式。

<a id="pretraining-section-18-question-05"></a>
### 面试问题：LLM 如何将原始语料组织成 token 序列、训练样本和上下文窗口？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

大语言模型的训练通常按 token 消耗算力，上下文窗口更长，padding 浪费更明显，因此原始语料不能直接进入训练，而要经过文本规范化、tokenization、添加特殊 token、截断或拼接、padding 或 packing，以及构造 attention mask、causal mask 和 loss mask 等步骤，最终生成 input_ids、labels、mask 等训练张量。

预训练阶段通常将清洗后的文档转成 token 序列，再按照固定上下文窗口切分或 packing 成训练样本，并对所有有效 token 做 next token prediction。多个无关文档拼接时通常需要插入 EOS 或文档分隔 token，避免模型把不相关内容误学成连续上下文。

不同训练阶段的 loss mask 不同。预训练通常让所有有效 token 参与 loss；SFT 阶段则通常只让 assistant 输出部分参与 loss, system 和 user 内容作为条件输入。

<a id="pretraining-section-18-question-06"></a>
### 面试问题：数据课程学习、退火与合成数据应如何进入预训练配方？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

数据课程不是简单的“先易后难”，而是让混合分布随已训练 token $t$ 变化：

```math
p_t(x)=\sum_i\alpha_i(t)p_i(x)
```

常见策略是早期用覆盖广、低重复的通用语料建立语言统计，中期提高代码、数学、书籍和论文比例，末期数据退火到高质量、长文本和目标域样本，同时配合学习率衰减。末期高质量数据的价值在于把有限的小步长更新投入更可信的 token；风险是配方过窄会造成通用能力回退，因此必须用多桶验证集做回归。

合成数据应当被当作一个独立的、经验可控的数据领域来对待，而不是简单地把生成内容倒进原始语料就当作扩容。可写为：

```math
q(x)=\lambda p_{\text{real}}(x)+(1-\lambda)p_{\text{synthetic}}(x)
```

> **注 **：**多桶验证集**是把验证数据按领域/难度等切成多个子集，分别评估模型在每个子集上的表现。它能体现“不同配比对不同能力的影响”，避免用单一总分掩盖偏科，从而找到更均衡、更可靠的数据配比。

<a id="pretraining-section-19"></a>
## 19. 如何预训练大语言模型？

<a id="pretraining-section-19-question-01"></a>
### 面试问题：什么是大语言模型预训练？

**难度评分：⭐⭐ (2/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

**大语言模型预训练，是在海量无标注文本上训练模型，使模型学习通用语言规律、世界知识、代码模式、基础推理能力和文本生成能力**。它是模型获得通用能力的基础阶段，后训练和对齐通常是在这个基础上加强指令跟随、安全性和人类偏好。

主流预训练目标是**自回归语言建模**，也就是给定前文预测下一个 token：

$$
P(x_t \mid x_{<t})
$$

训练时最大化真实文本序列出现的概率，等价于最小化交叉熵损失：

$$
\mathcal{L}(\theta)=-\sum_t \log P_\theta(x_t \mid x_{<t})
$$

虽然目标看起来只是“预测下一个词”，但为了预测准确，模型必须从上下文中学习语法、语义、事实、指代关系、代码结构和推理线索。因此，预训练可以看作用大规模自监督信号，让模型拟合自然语言和知识分布。

<a id="pretraining-section-19-question-02"></a>
### 面试问题：为什么主流 LLM 预训练通常采用自回归（下一词元预测）？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

当模型规模、数据规模和计算规模足够大时，下一词元预测（next token prediction ）成为一种可以利用海量未标注文本训练通用能力底座的统一目标。

自回归语言模型的训练目标是最大化文本序列的联合概率。根据链式法则：

$$
P(x_1,x_2,\dots,x_T)=\prod_{t=1}^{T}P(x_t \mid x_{<t})
$$

所以训练可以转化为每个位置根据前文预测当前词元，也就是下一词元预测。它属于自监督学习，因为文本本身就提供标签：前面的词元（token）是输入，后一个词元是监督信号。

这种目标成为主流，主要有三个原因：

- **不依赖人工标注**：任意文本都能转成训练样本，适合扩展到万亿词元。
- **训练形式统一**：续写、问答、代码生成、对话、摘要等任务都可以表示成条件上下文下的下一个词元预测。
- **可扩展性强**：在足够规模和高质量数据下，模型为了降低预测损失，会学习大量语法、语义、知识、代码、格式和推理相关模式。

在 Decoder-only 模型中，因果掩码（causal mask）会保证每个位置只能看到历史词元，看不到未来词元，从而让训练目标和推理时逐词元生成保持一致。

但下一词元预测也有局限。它可以看作在拟合训练文本分布，不天然保证事实正确、指令跟随、安全拒答或人类偏好最优。因此预训练模型通常只是“会续写”，还需要 SFT、偏好优化、RLHF/RLAIF、安全对齐和工具使用训练等后训练手段，让它从基础语言模型变成更可靠的任务型助手。

<a id="pretraining-section-19-question-03"></a>

### 面试问题：大语言模型预训练中的词元级交叉熵（token-level cross entropy）如何计算？它和下一个词元预测（next token prediction）、困惑度（perplexity）有什么关系？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

#### 1.什么是词元级交叉熵？

大语言模型把每个词元（token）位置都看作一次“大词表多分类”，根据前文预测下一个真实词元，并在所有有效词元上计算平均交叉熵。大语言模型预训练最常用的是 **token-level 交叉熵损失**。对于长度为 $T$ 的序列，训练目标可以写成：

$$
\mathcal{L}(\theta)=-\frac{1}{T}\sum_{t=1}^{T}\log P_\theta(x_t \mid x_{<t})
$$

其中， $ P_\theta(x_t \mid x_{<t}) $ 表示模型在看到前文 $ x_{<t} $ 后，对真实 token $x_t$ 分配的概率。

这个目标正好对应下一个真实词元（next token prediction）：每个位置都用前面的词元预测当前位置的词元。

模型在每个位置输出词表上的 logits，经 softmax 得到概率分布：

```math
p_i=\frac{e^{z_i}}{\sum_j e^{z_j}}
```

真实标签可以看作 one-hot 分布，交叉熵为：

```math
H(y,p)=-\sum_i y_i\log p_i
```

因为只有真实 token 对应位置为 1，所以可简化为：

```math
H(y,p)=-\log p_{\text{true}}
```

也就是说，模型给真实词元的概率越高，损失越低；如果真实词元概率很低，损失会迅速增大。最小化词元级交叉熵，等价于最大化训练语料在模型下出现的似然，因此它非常适合自回归语言建模。

#### 2.困惑度和交叉熵有什么联系和区别？

困惑度（perplexity, PPL）可以看作交叉熵损失的指数形式。如果交叉熵使用自然对数计算，则：

```math
\text{PPL}=\exp(\mathcal{L})
```

直观理解，PPL 越低，表示模型对下一个词元的预测越“有把握”；PPL 越高，表示模型平均面对的候选不确定性更大。但 PPL 只能反映模型对某个数据分布的拟合程度，不能直接等价于综合能力。

> **注**：损失低或困惑度低只能说明模型更好地拟合了对应数据分布，可能仍存在数据污染、重复记忆、能力不均衡、分布不匹配或对齐不足。不同分词器；不同验证集和不同数据清洗规则下的损失/困惑度也不一定能直接横向比较。

<a id="pretraining-section-19-question-04"></a>
### 面试问题：因果语言建模（CLM）、掩码语言建模（MLM）、前缀语言建模（PrefixLM）、UL2 和中间填充（FIM）的目标函数有什么区别？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

预训练目标定义“哪些 token 可见、哪些 token 计入损失”。

| 目标 | 预测形式 | 适用场景 | 主要权衡 |
|---|---|---|---|
| CLM | $p(x_t\mid x_{<t})$ | 续写、对话、代码生成 | 只能看左上下文 |
| MLM | 预测被遮盖的 $x_M$ | 双向表征、填空 | 与左到右解码不完全一致 |
| PrefixLM | prefix 双向可见，suffix 因果预测 | 条件生成 | mask 更复杂 |
| UL2 | 混合多种去噪模式 | 兼顾理解与生成 | 需要设计模式比例 |
| FIM | $p(m\mid p,s)$ | 代码补全、插入编辑 | 需要训练时重排样本 |

UL2 的核心是**去噪器混合**（mixture-of-denoisers）：**不要在预训练中去争论“哪一种目标函数普适最优”，而应该在同一训练过程中针对不同样本，切换不同的去噪任务**

<a id="pretraining-section-20"></a>
## 20. 如何组织大语言模型预训练样本与训练批次？

<a id="pretraining-section-20-question-01"></a>
### 面试问题：大语言模型预训练中如何组织批次（batch）、打包序列（sequence packing）并提升词元吞吐量（token throughput）？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

大语言模型的训练成本通常按词元（token）消耗，模型和上下文窗口都很大，核心目标是尽量提高 **有效词元占比** 和 **词元吞吐量**，也就是单位时间内实际参与训练的有效词元数。预训练数据会先经过分词器（tokenizer）转成词元id，再按照固定的打包序列组织成训练样本，例如 2K、4K、8K 或 32K。基本流程是：

```text
清洗后文本 → tokenization → 拼接或截断 → 按 sequence length 切分 → padding / packing → 构造 input_ids、labels、mask → 组成 batch
```

其中，padding 用来把同一 batch 内的样本补齐到相同长度，便于 GPU 做规则张量计算；packing 则是把多个短样本拼到一个长序列里，减少 padding 浪费，提高有效 token 占比和训练吞吐。

在 大语言模型训练中，还需要区分几个 batch 概念：

| 概念                  | 含义                                     | 作用                       |
| --------------------- | ---------------------------------------- | -------------------------- |
| Micro batch size      | 单次前向/反向在每张 GPU 上处理的样本数   | 受显存限制最大             |
| Global batch size     | 所有 GPU、所有梯度累积步合起来的总 batch | 影响优化稳定性和训练规模   |
| Gradient accumulation | 多次 micro batch 累积梯度后再更新参数    | 在显存有限时扩大等效 batch |
| Token batch size      | 一个 batch 中实际训练的 token 数         | 更适合衡量 LLM 训练负载    |
| Token throughput      | 单位时间训练的有效 token 数              | 衡量训练效率和系统吞吐     |

Sequence length 决定模型一次能看到的上下文长度。长度越大，越有利于学习长文档、长对话、代码文件和复杂推理链，但标准 attention 对序列长度的计算和显存开销约为：

```math
O(S^2)
```

长上下文会明显增加显存和计算开销，并降低词元吞吐量。训练时需要在上下文能力、吞吐、显存和成本之间权衡。

packing 虽然能提高效率，但需要正确处理文档边界。如果把多个无关文档直接拼接在同一个上下文窗口中，通常要插入 EOS 或文档分隔 token，避免模型把不相关文档误学成连续上下文。

提升 token throughput 通常依赖多种手段组合：减少 padding、使用 sequence packing、合理选择 sequence length、增加 global batch size、使用 gradient accumulation、优化数据加载、减少 CPU/GPU 等待，并配合混合精度、Flash Attention、并行训练和高效通信。

> **注**：更严格的做法还可以使用块对角注意力（block diagonal attention），让同一个 packed sequence 中的不同样本互相不可见，但实现成本更高。

<a id="pretraining-section-20-question-02"></a>
### 面试问题：全局批大小（global batch）、梯度累积与临界批大小（critical batch size）应如何共同确定？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

LLM 的 batch 应按有效 token：

```math
B_{\text{global}}=n_{\text{DP}}\cdot n_{\text{acc}}\cdot B_{\text{micro}}\cdot S\cdot r_{\text{valid}}
```

$B_{\text{global}}$ 为全局有效 batch，单位是 token，表示一次参数更新真正用到的有效 token 总数； $n_{\text{DP}}$ 为数据并行规模，即同时参与训练的设备数量； $n_{\text{acc}}$ 为梯度累积步数，表示累积多少个 micro-batch 的梯度后才更新一次参数； $B_{\text{micro}}$ 为单卡单次 micro-batch 的序列数，即每张卡每次前向/反向传播处理的样本条数； $S$ 为序列长度，单位是 token，通常指每条 packed 序列的固定长度，若长度可变则取平均值； $r_{\text{valid}}$ 为有效 token 占比，即由于 padding、掩码等原因，实际参与 loss 计算的 token 占全部 token 的比例，取值范围为  $0<r_{\text{valid}}\le 1$。

在语言模型训练中，批大小的确定与调整应以有效 token 数为计量单位，并遵循逐级放大的原则。评估不同批大小配置时，应在相同的 token 预算下进行比较，观察验证集损失曲线、梯度范数、模型算力利用率（MFU）以及实际训练耗时（wall-clock）。

> **注**：序列长度、样本打包率及数据混合比例的变化，都会在未显式调整批大小的情况下改变一次参数更新所对应的有效 token 数量，进而影响训练动态。因此，每当上述因素发生变化时，均应重新校准学习率及相应的训练调度，以确保模型训练的收敛质量与计算效率。

<a id="pretraining-section-21"></a>
## 21. 如何保证大语言模型预训练的优化稳定性？

<a id="pretraining-section-21-question-01"></a>
### 面试问题：大语言模型预训练中如何选择优化器？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

#### 1. 大语言模型预训练中如何选择优化器？

大语言模型参数量巨大、训练成本高、训练周期长，因此优化器不仅影响收敛速度和最终效果，还会明显影响显存占用、训练稳定性和工程风险。

| 优化器    | 核心特点                    | 优点               | 局限                   | 适用场景                |
| --------- | --------------------------- | ------------------ | ---------------------- | ----------------------- |
| AdamW     | 自适应学习率 + 解耦权重衰减 | 稳定、成熟、泛化好 | 优化器状态显存较大     | 大多数 LLM 预训练和微调 |
| Adafactor | 对二阶矩做因子化近似，减少状态存储 | 显存占用低         | 稳定性和调参难度较高   | 显存受限训练            |
| Lion      | 按动量方向的 sign 更新 | 状态较少、实现简单 | 学习率与权重衰减敏感 | 需严格对照的训练实验 |

<a id="pretraining-section-21-question-02"></a>
### 面试问题：大语言模型预训练中为什么需要学习率预热（warmup）、衰减（decay）和基于词元的调度（token-based schedule）？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

大语言模型训练规模巨大、训练周期长、全局批次大，而且通常更关心模型已经看过多少token，因此学习率调度常常按 **已训练词元数** 而不是传统 epoch 来设计。

大模型训练中最常见的学习率调度是 **warmup + decay**，其中 warmup + cosine decay 很常用。

- **Warmup**：学习率从较小值逐步升到峰值，避免训练初期更新过猛。
- **Cosine decay**：warmup 后按余弦曲线平滑下降，减少后期震荡。
- **Token-based schedule**：按照已经消耗的 token 数调整学习率，例：warmup 前若干 billion tokens，总训练若干 trillion tokens 后衰减到目标学习率。
- **Linear decay**：线性下降，简单可控，但平滑性不如 cosine。
- **Constant schedule**：warmup 后保持固定学习率，部分大规模训练也会使用。

对长训练，WSD（warmup-stable-decay）把“稳定平台”显式保留下来：先 warmup，再以常数 LR 训练主体 token，最后在退火阶段 decay。它便于改变总训练预算或末期数据配方，但仍须按有效 token 而不是 epoch 计时。余弦衰减可写为：

```math
\eta(t)=\eta_{\min}+\frac{\eta_{\max}-\eta_{\min}}{2}\left[1+\cos\left(\pi\frac{t-t_w}{T-t_w}\right)\right]
```

其中 $t_w$ 是 warmup token 数。学习率、数据退火和 global batch 的任何一项改变，都应作为一次新的训练配方验证。

<a id="pretraining-section-21-question-03"></a>
### 面试问题：μP / μTransfer 如何降低大模型超参数搜索成本？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

标准参数化下，改变网络宽度会改变激活、输出和参数更新的绝对尺度，导致同一学习率在不同宽度下效果不同；μP 通过对每类参数单独设计初始化、乘子与学习率的缩放规则，使特征更新幅度始终保持在 O(1)，从而让最优超参数不随宽度漂移，实现从小模型到大模型的可迁移性。

μTransfer 是在最大化更新参数化（μP）理论框架下，为规避大模型高昂调参成本而提出的一种超参数迁移方法。

- 其核心实践是：在采用同一 μP 规则的小宽度代理模型上，针对学习率、初始化尺度及学习率调度等超参数进行搜索，并将所得最优超参数以零样本方式直接应用于目标大规模模型。

该方法能将超参数搜索的成本从大模型转移到小模型，从而显著降低训练试错开销，但其有效性依赖于尺度外推的前提条件，一旦模型深度、序列长度、数据规模、正则化策略或并行实现方式等因素发生改变，迁移结果仍可能失效。因此，在实际应用中，μTransfer 应被视为一种高效的初始超参选择手段，而非对最终训练方案的完全替代，目标模型上的验证与必要微调仍是不可或缺的环节。

> **注**：；尺度外推：小宽度模型的最优超参可以通过某种理论规则可靠地推算到大宽度模型



<a id="pretraining-section-21-question-04"></a>
### 面试问题：大语言模型训练为什么常用 BF16/FP16 混合精度？它如何影响显存、吞吐和稳定性？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

#### 1. 大语言模型训练为什么常用 BF16/FP16 混合精度？

混合精度训练是指训练中同时使用不同数值精度：大部分矩阵计算使用 FP16 或 BF16，以降低显存并提升吞吐；关键状态如优化器状态、梯度累积、归一化层或部分数值敏感算子保留 FP32 或更高精度，以保证稳定性。

大语言模型训练中特别依赖混合精度，因为模型参数、激活值、梯度和优化器状态占用巨大，如果全部使用 FP32，显存成本和计算成本都会非常高。

#### 2. 如何影响显存、吞吐和稳定性？

混合精度的价值主要体现在三个方面：第一，降低显存占用，使更大的模型、更大的 batch size 和更长的上下文窗口成为可能；第二，利用 GPU Tensor Core 提升矩阵乘法吞吐，提高训练速度；第三，在保留关键状态高精度的前提下，尽量兼顾效率和数值稳定性。

大规模大语言模型预训练通常优先使用 BF16，因为 BF16 和 FP16 一样通常占 16 bit，但 BF16 的指数位更多，动态范围接近 FP32，因此比 FP16 更不容易出现 上溢（overflow）或下溢（underflow），训练稳定性通常更好，也通常不需要强依赖损失缩放。

FP16 的损失缩放会先把 loss 乘以 $s$ 后反传，再将梯度除以 $s$；发现 Inf/NaN 时跳过该更新并降低 $s$。FP8 通常把前向权重/激活置于 E4M3（精度较好、范围较窄）或 E5M2（范围较宽、精度较低），并使用每张量/块缩放与更高精度累积。

<a id="pretraining-section-21-question-05"></a>
### 面试问题：大语言模型训练中为什么容易出现损失尖峰（loss spike）、NaN 和梯度异常？如何监控与缓解？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

#### 1. 大语言模型训练中为什么容易出现 loss spike、NaN 和梯度异常？

大语言模型的参数量、序列长度、全局批大小、训练 token 数和分布式规模都更大，训练成本也更高，因此**一个坏 batch、一次数值溢出或一次 checkpoint 恢复异常，都可能造成大量算力浪费**。大模型预训练常见稳定性问题包括 loss spike、梯度爆炸、NaN/Inf、激活异常、数据异常、优化器状态异常、valid loss 异常和分布式通信异常。根本原因是**训练规模变大后，优化、数值、数据和系统问题都会被放大**。

梯度裁剪是最后一道幅度保护：

```math
g\leftarrow g\cdot\min\left(1,\frac{\tau}{\lVert g\rVert_2}\right)
```

其他介入手段还包括：z-loss，在目标中加入 $\lambda(\log\sum_i e^{z_i})^2$ 抑制 log-partition 漂移；logit soft-capping，用 $c\tanh(z/c)$ 限制极端 logits。

#### 2. 如何监控与缓解？

工程上通常会持续监控训练损失、验证损失、梯度范数、参数范数、激活范数、学习率、NaN/Inf、tokens/sec、MFU、显存占用、通信耗时和数据加载耗时。对于多源数据训练，还可以按数据来源或数据类型监控 loss，帮助定位某一类数据是否导致异常。

一旦出现异常，需要**先判断是优化、数值、数据问题还是分布式系统问题**。

- 优化问题通常通过降低学习率、增加 warmup、梯度裁剪或调整 batch size 缓解；
- 数值问题通常通过 BF16、稳定 softmax、检查归一化层和 loss scaling 处理；
- 数据问题需要定位异常 batch、回溯样本来源并修复清洗规则；
- 系统问题则需要检查通信、节点状态和 checkpoint 一致性。

大规模大语言模型训练通常还会建立自动恢复机制，例如定期保存 checkpoint、异常时回滚到最近稳定版本、自动跳过坏 batch、记录异常样本 ID、保存训练日志和数据 shard 元信息。稳定性治理的重点不是等训练崩溃后再排查，而是通过监控、告警、回滚和数据追踪，把 loss spike、NaN 和梯度异常控制在可定位、可恢复的范围内。

<a id="pretraining-section-21-question-06"></a>
### 面试问题：大语言模型训练中的 checkpoint、断点恢复和监控为什么更复杂？如何设计？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐ (3/5)**

#### 1. 大语言模型训练中的 checkpoint、断点恢复和监控为什么更复杂？

大语言模型的预训练周期长、数据规模大，并且通常依赖数据并行、张量并行、流水线并行、ZeRO 或 FSDP 等分布式策略，因此 checkpoint 的保存、加载、一致性校验和故障恢复都更复杂。其 checkpoint **不应只保存模型权重，而要保存完整训练状态**，保证中断后可以从尽量相同的训练轨迹恢复。

大语言模型 checkpoint 的**工程难点在于体积和一致性**。大模型不仅权重大，优化器状态也很大，AdamW 通常还要保存一阶动量和二阶矩，混合精度训练中还可能保存 FP32 master weights。分布式训练下，checkpoint 可能被切分在多个 rank 或多个节点上，保存时要保证所有分片来自同一个 global step，恢复时也要保证并行策略、rank 映射和分片布局一致。

<a id="pretraining-section-22"></a>
## 22. 怎么优化和加速大语言模型训练过程？

<a id="pretraining-section-22-question-01"></a>
### 面试问题：大模型预训练的主要瓶颈是什么？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

#### 1. 大模型预训练的主要瓶颈是什么？

大模型预训练的主要瓶颈包括 **计算、显存、通信和数据加载瓶颈**。

- **计算瓶颈**：GPU 算力不足，矩阵乘法和 attention 计算耗时高。
- **显存瓶颈**：模型参数、梯度、优化器状态和激活值占用显存过大。
- **通信瓶颈**：多卡训练中参数、梯度同步等通信开销高。
- **数据加载瓶颈**：CPU、磁盘、网络或 tokenizer 处理速度跟不上 GPU 计算。

#### 2. 为什么训练瓶颈会随规模变化？

大模型训练吞吐由最慢环节决定。不同规模下，瓶颈通常不同：

- 小模型或单机训练中，模型能放进显存，主要瓶颈可能是 GPU 计算。
- 模型变大后，参数、梯度、优化器状态和激活值快速增长，显存成为主要限制。
- 多机多卡训练中，参数同步和梯度通信开销变大，通信瓶颈更明显。
- 如果数据处理链路不够快，GPU 会等待 batch，数据管线就会成为瓶颈。

因此，大模型优化不是单点优化，而是计算、显存、通信和数据管线之间的平衡。优化前必须先做性能分析，确认真正瓶颈在哪里，再选择对应优化策略。

#### 3. 常见瓶颈表现与优化方向

| 瓶颈类型 | 典型表现 | 常见优化方向 |
|---|---|---|
| 计算瓶颈 | GPU 利用率高，但墙钟时间（step time）长 | 混合精度、Flash Attention、提高批量大小 |
| 显存瓶颈 | OOM，batch size 或 sequence length 无法增大 | ZeRO/FSDP分布策略、混合精度、梯度累积 |
| 通信瓶颈 | 多卡扩展效率低，GPU 等待同步 | 优化并行策略、通信重叠、减少 all-reduce、使用高速互联 |
| 数据瓶颈 | GPU 利用率低，等待数据加载 | 预 tokenization、异步加载、本地缓存、packing |
| 存储瓶颈 | checkpoint 保存慢，数据读取慢 | 分布式存储、数据分片、异步 checkpoint、压缩格式 |

<a id="pretraining-section-22-question-02"></a>
### 面试问题：为什么大语言模型训练需要多种并行策略？数据并行、张量并行、流水线并行分别解决什么问题？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

#### 1. 为什么大语言模型训练需要多种并行策略？

大语言模型训练需要多种并行策略，核心原因是单张 GPU 很难同时承载模型参数、激活值、梯度、优化器状态和大 batch 训练所需的显存与计算量。因此，大语言模型训练通常采用 **数据并行、张量并行、流水线并行**，甚至进一步结合 ZeRO、序列并行、专家并行等方法，形成多维并行训练方案。

#### 2. 数据并行、张量并行、流水线并行分别是什么？

大模型训练中常见并行方式包括 **数据并行、张量并行和流水线并行**。

- **数据并行（Data Parallelism, DP）**：按 batch 维度切分数据，每张 GPU 保存一份完整模型，不同 GPU 处理不同 mini-batch，反向传播后同步梯度。
- **张量并行（Tensor Parallelism, TP）**：按张量或矩阵维度切分单层计算，把一个大的矩阵乘法拆到多张 GPU 上共同完成。
- ****流水线并行（Pipeline Parallelism, PP）**：按模型层切分，把不同 Transformer 层放到不同 GPU 上，不同 micro-batch 像流水线一样依次经过不同设备。

#### 3. 三者分别解决什么问题？

- **数据并行解决“数据太多、训练吞吐不够”的问题**：不同 GPU 处理不同 batch，提高样本处理速度。
- **张量并行解决“单层太宽”的问题**：例如 attention 和 MLP 中的大矩阵乘法太大，需要拆到多卡上计算。
- **流水线并行解决“模型太深”的问题**：Transformer 层数很多时，可以把不同层分配到不同 GPU 上。

在实际大语言模型训练中，三者往往不是互斥关系，而是组合使用。例如一个训练集群可以在节点内使用张量并行，在节点间使用流水线并行和数据并行，从而同时解决显存、计算和吞吐问题。

<a id="pretraining-section-22-question-03"></a>
### 面试问题：大语言模型训练中为什么需要 ZeRO 和 FSDP？它们如何切分参数、梯度和优化器状态？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

#### 1. 大语言模型训练中为什么需要 ZeRO 和 FSDP？

**ZeRO** 和 **FSDP** 都是大模型分布式训练中的显存优化方法。它们的基本思路是将 **模型参数、梯度和优化器状态** 分片存储到不同 GPU 上，避免每张卡都保存完整训练状态，从而降低数据并行中的显存冗余。

传统数据并行会在每张 GPU 上复制一份完整模型参数、梯度和优化器状态。对于小模型，这种冗余可以接受；但在 大语言模型预训练中，参数量、优化器状态和梯度都非常大，单卡显存往往无法承受，因此需要 ZeRO/FSDP 这类分片训练方案。

ZeRO 常分为三个阶段：

- **ZeRO-1**：切分优化器状态。
- **ZeRO-2**：切分优化器状态和梯度。
- **ZeRO-3**：切分优化器状态、梯度和模型参数。

| 阶段 | 切分内容 | 显存节省 | 通信开销 | 适用场景 |
|---|---|---|---|---|
| ZeRO-1 | Optimizer states | 中等 | 较低 | 模型能放下，但优化器状态占用大 |
| ZeRO-2 | Optimizer states + Gradients | 更高 | 中等 | 梯度和优化器状态都成为瓶颈 |
| ZeRO-3 | Optimizer states + Gradients + Parameters | 最高 | 较高 | 模型参数本身也无法完整放入单卡 |

ZeRO-3 显存节省最明显，但训练时需要频繁全收集（all-gather）参数和归约散播（reduce-scatter）梯度，因此通信成本更高。实际选择时通常要在显存节省、通信开销、吞吐和工程复杂度之间权衡。

**FSDP** 是 PyTorch 生态中的全分片数据并行方案，思想与 ZeRO-3 接近，会对参数、梯度和优化器状态进行分片，并在前向/反向计算时按需 all-gather 参数，用完后释放非本地参数，从而降低峰值显存。

> **注**：All-gather：每张卡把自己持有的一份数据广播出去，最终每张卡都拿到所有卡的数据并拼接起来。Reduce-scatter：先对所有卡的数据做归约（如求和/平均），再把归约后的结果**按分片分配**，每张卡只保留属于自己的那一段。

#### 2. 什么是 FSDP？

FSDP（Fully Sharded Data Parallel）可以看作 PyTorch 原生的全分片数据并行方案。它会将参数、梯度和优化器状态按 rank 分片保存。

训练时大致流程是：

```text
前向传播前：all-gather 当前层参数
前向计算：使用完整参数计算
前向后：释放非本地参数
反向传播前：all-gather 当前层参数
反向计算：计算梯度
反向后：reduce-scatter 梯度并释放参数
优化器更新：只更新本 rank 持有的参数分片
```

这样，每张 GPU 不需要长期持有完整模型参数，而是在计算某一层或某个模块时临时聚合所需参数。计算完成后释放非本地参数，用通信换显存。

#### 3. ZeRO 和 FSDP 有什么附加开销？

ZeRO/FSDP通过通信换显存，因此会带来额外通信开销，尤其是 ZeRO-3/FSDP 需要频繁 all-gather 参数和 reduce-scatter 梯度。如果网络带宽、拓扑或重叠度策略不好，训练吞吐可能明显下降。

另外，ZeRO/FSDP 会让工程复杂度上升：

- checkpoint 保存和恢复更复杂，因为参数和优化器状态是分片的；
- 调试更困难，因为每张卡只持有部分训练状态；
- 对通信性能更敏感，需要高速互联；
- 需要合理设置预取、重新分片、桶大小等参数；
- 和 激活检查点、混合精度、张量并行、流水线并行等其他优化组合时要仔细验证。

ZeRO/FSDP 主要解决 **参数、梯度和优化器状态的显存冗余**，不直接消除所有显存压力。大语言模型训练中的激活显存、attention 显存和长上下文开销，还需要配合其他技术一起优化，比如activation checkpointing、FlashAttention、sequence parallel、张量并行和合理的 batch/sequence length设计。

<a id="pretraining-section-22-question-04"></a>

### 面试问题：大语言模型训练中如何通过混合精度、梯度累积和激活检查点节省显存？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)**

大模型训练显存主要来自 **模型参数、梯度、优化器状态和激活值**。常见显存优化方法包括：

#### 1.怎么计算大语言模型需要的显存量？

以混合精度的AdamW 为例，未分片模型状态可粗略拆为 BF16 参数 $2P$ bytes、可选 FP32 master 参数 $4P$、梯度 $2P$ 或 $4P$、FP32 一阶/二阶矩 $8P$，合计通常约 $16P$ 到 $18P$ bytes；激活、临时 buffer 和碎片另计。ZeRO/FSDP 按数据并行度分片的是长期模型状态，激活并不会按同样比例下降。

```math
M_{\text{peak}}\approx M_{\text{params}}+M_{\text{grads}}+M_{\text{optimizer}}+M_{\text{activations}}+M_{\text{temporary}}
```

#### 2.怎么节省显存？

- **混合精度训练**：用 FP16/BF16 代替 FP32 存储和计算，降低参数、梯度和激活显存。
- **梯度累积**：用多个 micro-batch 累积梯度，模拟更大的 global batch，降低单次前向/反向的显存峰值。
- **Activation checkpointing**：不保存所有中间激活，只保存部分关键激活，反向传播时重新计算，减少激活显存。

三者通常和 ZeRO/FSDP、FlashAttention 一起使用，以支持更大模型、更长上下文或更大 batch size。

<a id="pretraining-section-23"></a>
## 23. 如何优化训练显存、注意力计算和数据管线？

<a id="pretraining-section-23-question-01"></a>
### 面试问题：Flash Attention 为什么能加速大语言模型中的 Attention？它主要优化的是计算量还是显存访问？

**难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

#### 1. Flash Attention 为什么能加速 Attention？

**Flash Attention** 主要优化的是 **显存访问（Memory IO）和中间矩阵存储**，而不是改变 Attention 的数学定义。

标准 Attention 需要显式计算并保存完整的注意力矩阵，长序列下，Attention 往往不是纯计算瓶颈，而是 **显存访问瓶颈**。

Flash Attention 通过 **分块计算（tiling）** 和 **online softmax**，避免将完整 attention matrix 写入显存，从而提升训练和推理速度，并降低显存占用。

#### 2. Flash Attention 的核心原理

Flash Attention 的核心是把 Q、K、V 按块加载到更快的 SRAM 中，在块内完成 attention 计算，并使用 online softmax 维护归一化结果。

它避免了两件事：

- 不显式保存完整的 $S \times S$ attention matrix；
- 减少 attention score 在 HBM 和计算单元之间的反复读写。

可以简单理解为：

```text
标准 Attention：
QK^T → 写入 HBM → softmax → 写入 HBM → 乘 V

FlashAttention：
分块加载 Q/K/V → 块内计算 attention → online softmax → 直接累积输出
```

因此，Flash Attention 的数学结果与标准 attention 等价，但计算组织方式更高效。

#### 3. 它优化的是 FLOPs 还是显存访问？

Flash Attention 通常不明显减少理论 FLOPs。它的主要收益来自：

- 减少 HBM 读写；
- 减少中间 attention matrix 存储；
- 提高 SRAM 和 Tensor Core 利用率；
- 降低长序列训练的显存峰值；
- 改善实际吞吐。

Flash Attention 是 **IO-aware attention**，它优化的是实际硬件执行效率，而不是把 Attention 的数学计算量大幅减少。

<a id="pretraining-section-23-question-02"></a>
### 面试问题：大语言模型预训练中如何优化数据加载和数据管线，避免 GPU 等待数据？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

#### 1. 为什么数据管线会成为瓶颈？

大模型训练时 GPU 计算非常快。如果 CPU 分词、磁盘读取、网络传输、数据解码或 batch 构造速度跟不上，GPU 就会空闲等待数据。

#### 2. 大语言模型预训练中如何优化数据加载和数据管线，避免 GPU 等待数据？

数据管线优化的目标是让 GPU 不等数据，提高端到端训练吞吐。常用方法包括：

- **预 tokenization**：提前把文本转成 token id，避免训练时在线分词。
- **二进制数据格式**：减少 JSON、CSV、文本解析成本。
- **mmap**：通过内存映射读取大文件，降低 IO 开销。
- **本地缓存**：减少远程存储或网络读取延迟。
- **异步数据加载器**：CPU 在 GPU 计算当前 batch 时准备下一批数据。
- **多进程加载**：并行读取、解码和组 batch。
- **shuffle buffer**：保证数据随机性，同时避免全量 shuffle 成本过高。
- **packing**：提高有效 token 占比，减少 padding 浪费。
- **分布式数据切分**：让不同 worker 读取不同 shard，避免重复训练和负载不均。

<a id="pretraining-section-23-question-03"></a>

### 面试问题：主流大模型训练框架如何组合并行策略？

**难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

实际选型通常取决于模型是否单卡放得下、单层矩阵是否过宽、层数是否过深、优化器状态是否超显存、是否包含 MoE，以及跨节点网络是否足够快。

| 框架 / 训练栈 | 主要工程定位 | 典型组合方式 |
|---|---|---|
| Megatron-LM / Megatron-Core | 适合超大稠密模型和 MoE 的高性能训练核心 | TP + PP + DP，进一步结合 SP / CP / EP |
| DeepSpeed | 强在 ZeRO、Offload、显存分片和工程化训练 | DP + ZeRO，或 PP + ZeRO |
| Megatron-DeepSpeed | 结合 Megatron 的模型切分与 DeepSpeed 的状态分片 | TP + PP + DP + ZeRO |
| PyTorch FSDP | PyTorch 原生分片训练，生态集成好 | FSDP + DP，必要时叠加 TP / PP |
| Colossal-AI | 多维混合并行实验和教学友好 | DP + TP + PP + ZeRO / SP |
| NVIDIA NeMo / Megatron-Core 生态 | Megatron-Core 的产品化封装和 NVIDIA 生态集成 | TP + PP + DP，进一步结合 SP / CP / EP |

> **注**：序列并行（SP）：在TP 组内把序列长度维度也切开，让 LayerNorm / Dropout 等按 token 独立操作的激活不再被每张卡重复保存，从而只解决“长序列导致激活显存翻倍”的问题，而不改变参数量和通信模式。 上下文并行（CP）：把极长的序列沿时间维（token 维）真正切分到不同设备上，每张卡只持有自己负责的那段 KV / 中间状态，配合环型或分布式的注意力计算，使上下文长度可以远远超过单卡显存上限——目标是“把单序列长度推到几十万甚至百万 token”。 专家并行（EP）：在 MoE 模型中不复制所有专家到每张卡，而是把不同的专家部署在不同设备上，由路由器（router）把每个 token 动态分发到它需要的专家所在的设备上，算完后再送回来。
