# 我是传统 CV 转大模型，怎么补？

> 路线定位：面向已有分类、检测、分割、OCR、训练调优或部署经验，希望转向 LLM、多模态大模型或 AI Agent 的算法工程师。建议周期 6-10 周。

[返回核心教程总览](README.md) | [返回项目主页](../README.md)

## 先改一个认知：你不是从零开始，而是在迁移能力坐标

传统 CV 经验并没有失效。数据治理、表示学习、损失设计、训练稳定性、评测、部署和误差分析仍然是大模型工程的底层能力。真正需要补齐的是：**序列建模语言、Transformer/LLM 机制、后训练范式、检索与工具增强、生成式评测，以及面向系统的产品闭环**。

建议先建立这张迁移关系：

| 传统 CV 能力 | 可迁移价值 | 需要补齐的大模型能力 |
|---|---|---|
| 数据清洗、标注与增强 | 数据质量意识、长尾与偏差处理 | 语料去重、Token 化、指令数据与偏好数据 |
| CNN/ViT 表示学习 | 模型结构与特征抽象能力 | Decoder-only、因果注意力、位置编码、KV Cache |
| 迁移学习与微调 | 参数更新、过拟合与域适配经验 | SFT、LoRA/QLoRA、DPO/GRPO |
| 指标与误差分析 | 基线、消融、失败归因 | 生成评测、LLM-as-Judge、事实性与安全评测 |
| 推理部署 | 性能、显存、服务稳定性 | Prefill/Decode、连续批处理、PagedAttention |

### 实践任务

用一个小模型完成以下实验：观察 Token 化结果；修改 temperature/top-p；记录首 Token 延迟与生成速度；对同一问题比较短上下文和长上下文。最终画出“文本 -> Token -> Transformer -> Logits -> 采样 -> 输出”的数据流图。

### 通过标准

能从数学机制和工程后果两层解释：为什么因果掩码必要、为什么长上下文成本高、为什么 KV Cache 用显存换计算。

### 实践任务

用一个小型开源模型完成 LoRA/QLoRA 微调。至少保留：原始基线、数据说明、训练曲线、关键超参数、固定评测集、失败样例和微调前后对比。不要只展示几条“看起来不错”的生成结果。

### 转型叙事模板

面试中不要否定过去，也不要把转型说成追热点。更可信的表达是：

1. 过去在 CV 中积累了什么可验证能力。
2. 这些能力如何迁移到大模型的数据、训练、评测或部署。
3. 为补齐差异，系统学习并实践了哪些 LLM 机制。
4. 新项目如何证明你已经完成能力迁移。
5. 为什么目标岗位需要“CV + LLM/多模态/系统”的复合视角。

## 最终验收清单

- [ ] 我能画出 CNN/ViT 与 Decoder-only LLM 的结构差异和共同点。
- [ ] 我能解释 Token、因果注意力、位置编码、生成策略与 KV Cache。
- [ ] 我能区分 Prompt、RAG、LoRA、全量微调和偏好对齐的边界。
- [ ] 我完成了一个带基线、评测和失败分析的大模型项目。
- [ ] 我能把传统 CV 经验翻译成目标岗位认可的数据、训练、评测或部署能力。
- [ ] 我能回答“为什么转型”以及“为什么你不是从零开始”。

这条路线的关键不是抹掉 CV 标签，而是把它升级为你进入多模态与大模型系统的差异化起点。
