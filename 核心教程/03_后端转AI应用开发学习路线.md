# 我是后端转 AI 应用开发，怎么学？

> 路线定位：面向已有 Java、Go、Python、C++ 或云原生后端经验，希望转向 LLM 应用、RAG、AI Agent、模型服务或企业 AI 平台的开发者。建议周期 6-8 周。

[返回核心教程总览](README.md) | [返回项目主页](../README.md)

## 先确定能力边界：AI 应用开发不是“会调模型 API”

后端工程能力是很强的起点：API、数据库、缓存、消息队列、权限、并发、可观测性和发布治理都能直接迁移。需要补齐的，是传统确定性软件里较少出现的五件事：

1. **模型输出具有概率性**：同一个输入不一定得到完全相同的结果。
2. **上下文是运行时状态**：Prompt、检索结果、工具返回和历史消息共同决定行为。
3. **质量不能只靠单元测试**：需要离线评测、轨迹评测、人工评审和线上反馈。
4. **错误会跨组件传播**：检索错、工具错、模型错和编排错可能表现为同一种“答错”。
5. **安全边界更复杂**：自然语言输入可能改变工具调用、数据访问和执行路径。

完成路线后，你应当能独立构建一个**可评测、可追踪、可降级、可部署**的 AI 应用，而不只是一个聊天界面。

## 第 1 阶段：第 1 周，建立够用的大模型运行认知

### 学习目标

后端转型不需要先训练大模型，但必须理解 Token、上下文、生成参数、幻觉和推理成本，否则无法设计稳定接口、容量和错误处理。

### 实践任务

封装一个统一模型客户端，至少支持：系统提示、消息历史、超时、重试、流式输出、结构化输出、Token/费用记录、错误分类和模型切换。用固定样本比较两个模型或两组生成参数。

### 通过标准

能解释为什么“HTTP 200”不代表 AI 请求成功，并给出模型超时、格式错误、内容不可信、限流和供应商故障的不同处理策略。

## 第 2 阶段：第 2 周，从 Prompt 到可测试的模型接口

### 学习目标

把 Prompt 当作需要版本化和评测的程序接口，而不是临场写作。重点掌握指令层级、任务边界、输入隔离、结构化输出和安全风险。

### 核心问答

- [系统提示、开发者提示和用户输入的区别](<../大模型基础（精华版）/05_提示工程：应用大模型的高级方法.md#面试问题：什么是提示？系统提示、开发者提示和用户输入有什么区别？>)
- [如何构造清晰、稳定、可评估的提示](<../大模型基础（精华版）/05_提示工程：应用大模型的高级方法.md#面试问题：如何构造一个清晰、稳定、可评估的提示？>)
- [任务拆解、格式约束与澄清机制](<../大模型基础（精华版）/05_提示工程：应用大模型的高级方法.md#面试问题：角色提示、任务拆解、格式约束、反问澄清和结构化输出分别解决什么问题？>)
- [生成参数如何影响输出](<../大模型基础（精华版）/05_提示工程：应用大模型的高级方法.md#面试问题：temperature、top-p、max tokens 等生成参数如何影响提示工程效果？>)
- [Prompt Injection 与 Jailbreak 的区别](<../大模型基础（精华版）/05_提示工程：应用大模型的高级方法.md#面试问题：Prompt Injection 和 Jailbreak 有什么区别？为什么提示安全不能只靠提示词声明？>)

### 实践任务

为一个信息抽取或内容审核任务建立 Prompt 测试集：至少 30 个正常样本、10 个边界样本、5 个攻击样本。输出必须通过 Schema 校验，并记录准确率、格式通过率、拒答率和单次成本。

### 通过标准

能够把 Prompt 变更接入回归测试；当效果下降时，能区分是提示、模型版本、参数还是测试样本发生变化。

### 实践任务

构建一个领域知识库。至少保留 50 条人工标注问题，并分别评测：召回命中率、重排效果、答案事实性、引用正确率、无答案拒答率、延迟和成本。对失败样本按“数据缺失、切分错误、召回错误、排序错误、生成错误”分类。

### 通过标准

当系统答错时，能用 trace 判断错误发生在哪一层；能说明为什么只优化最终答案分数会掩盖检索问题。

## 面试表达主线

后端转 AI 应用开发时，最有说服力的叙事不是“我会某个 Agent 框架”，而是：

> 我把后端系统中的接口、状态、权限、可靠性和可观测性能力，延伸到了概率性模型系统；我不仅能接入模型，还能定位模型、检索、工具和编排链路中的质量问题，并通过评测与反馈让系统持续变好。

## 最终验收清单

- [ ] 我能解释模型 API 与普通确定性 API 的根本差异。
- [ ] 我能把 RAG 错误拆成数据、召回、排序和生成问题。
- [ ] 我能说明 Workflow、Agent、MCP、Memory 各自的边界。
- [ ] 我的项目具备评测、Trace、权限、降级与部署方案。
- [ ] 我能画出完整架构，并解释至少三处关键工程取舍。
- [ ] 我能用后端优势建立差异化，而不是把过去经验清零。
