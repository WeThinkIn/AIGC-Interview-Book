<h1 id="q-001">1. 树结构为什么是面试和 AI 系统中的高频基础？</h1>

<h2 id="q-002">面试问题：二叉树、二叉搜索树和平衡树有什么区别？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

二叉树只限制每个节点最多有两个孩子。二叉搜索树进一步要求左右子树与根之间满足键的顺序关系；平衡搜索树再通过维护高度或颜色等约束，避免树高随插入顺序退化。三个概念逐层增加条件，不能互相替代。

对互异键，BST 要求左子树所有键小于根，右子树所有键大于根。条件作用于整棵子树，不只是左右孩子。若允许重复键，可以给节点增加计数，或用 `(key,唯一ID)` 排序；只说“重复值随便放两边”，会让查找和删除语义变得含糊。

BST 的查找、插入、删除都与树高 h 相关，通常为 $`O(h)`$。按递增顺序向普通 BST 插入 1、2、3、4，可能形成一条链，查找退化为线性。平均对数表现需要随机插入等分布假设；AVL、红黑树等通过维护规则给出最坏对数高度。

树不只有二叉形式。B 树、B+ 树是多路平衡搜索树，通过一个节点保存多个键降低层数，更适合页式存储；它们不属于“平衡二叉树”。堆虽然也常画成完全二叉树，却只维护父子堆序，不能用 BST 的左小右大规则搜索任意键。

工程建模时先问是否真的需要有序搜索。AST、目录和层级任务通常只需要父子关系，不需要平衡；时间戳范围索引需要顺序；数据库页访问还要考虑扇出和 I/O。树形外观相似，维护的不变量可以完全不同。

<h2 id="q-003">面试问题：二叉树前序、中序、后序遍历的递归逻辑是什么？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

三种遍历的差别在于何时处理当前根节点：前序为根、左、右，中序为左、根、右，后序为左、右、根。递归函数的契约是“完整访问以当前节点为根的子树”，空节点直接返回，左右子问题按约定顺序完成。

对根 A、左孩子 B、右孩子 C 的树，三个结果分别是 ABC、BAC、BCA。前序适合先输出父信息再展开子树；中序在合法 BST 上得到有序序列；后序适合先汇总孩子再计算父节点，例如目录大小、表达式求值和树形动态规划。

每个节点只处理常数次，时间 $`O(n)`$，递归栈空间 $`O(h)`$。结果数组还需要 $`O(n)`$，应与辅助栈分开。Python 写成 `[root] + left_result + right_result` 会反复复制结果，链状树上可能产生二次搬移；共享输出列表或迭代追加更合适。

显式栈可以保存 `(节点,阶段)`：阶段 0 记录前序并准备左子树，阶段 1 记录中序并准备右子树，阶段 2 记录后序。这样能用同一套状态转换理解三种顺序，也能避开深树的语言递归限制。[三语言实现](07_三语言代码模板与AI场景实现高频考点.md#q-013)采用这种方式。

计算图的反向传播与“依赖完成后再处理”有相似思路，但一般计算图可能有共享节点和多条梯度路径，不能直接当树后序遍历。共享贡献需要累加，处理顺序也需要满足图的依赖关系。

<h2 id="q-004">面试问题：层序遍历为什么通常用队列实现？</h2>

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

层序遍历要求先处理深度较小的节点。把根放入队列，每次弹出队首节点并将孩子追加到队尾，就能保证新发现的下一层排在当前层剩余节点之后。这个先进先出的不变量，比记住几行模板更重要。

如果需要按层返回结果，在每轮开始时记录当前队列长度 s，只处理这 s 个节点。处理时加入的孩子属于下一层，不能让循环上界随着队列长度一起变化。否则不同深度会混进同一组。

时间复杂度为 $`O(n)`$，辅助队列空间与最大层宽相关，为 $`O(w)`$，最坏可达 $`O(n)`$；输出另占线性空间。DFS 栈与树高相关，BFS 队列与层宽相关，没有一种遍历总是更省内存。

对真正的树，不需要 visited，因为每个非根节点只有一个父节点。推广到图以后，同一节点可能被多个前驱发现，必须在入队时标记，防止重复扩展。对带权图，按层访问只保证边数少，不保证总权重小。

任务系统有时也分层展示依赖，但“同一深度”不代表可以忽略资源限制一起执行。层序是遍历顺序，实际并行调度还需要依赖完成状态、资源配额和失败处理。把二者分开，才能既解释算法，也避免对系统行为作过度推断。

<h2 id="q-005">面试问题：树结构在 AI 场景中有哪些真实应用？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐ (3/5)**

树适合表达层级划分与共享路径。代码解析后的 AST 用节点表示语法结构；决策树根据特征条件逐层划分样本；层级标签用父类包含子类；前缀树则让相同开头的符号序列共享路径。这些应用维护的语义不同，不能因为都画成树就使用同一种算法。

例如代码 Agent 定位函数时，AST 能区分函数定义、调用表达式和字符串中的相同文字，比纯字符串查找更了解语法。但 AST 本身未必包含完整类型、跨文件引用或运行时调用信息，通常还需要符号表、类型检查器和依赖图。

前缀缓存中，Radix tree 把连续的单分支路径压缩成一条边，索引 token 前缀到 KV 状态。只有具有相同计算上下文的公共前缀才可复用；词面相同的中间片段不能自动共享。细节集中在[字符串与索引章节](05_字符串与高级数据结构高频考点.md#q-022)。

Tokenizer 的实现也要具体分析。WordPiece 的某些匹配流程可以利用前缀结构，BPE 则还受合并排名约束，最长词表匹配并不能替代所有 BPE 规则。树提供一种索引能力，分词算法决定怎样使用它。

规划任务可以先表示为树，但如果两个任务共享依赖，或执行存在循环与反馈，就需要图或状态机。判断建模是否合适，可以检查“每个节点是否真的只有一个父节点”和“同一个状态是否被重复展开”。这比给所有层级图都贴上任务树标签更可靠。

<h2 id="q-022">面试问题：树状数组和线段树怎样处理动态区间查询？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

静态数组的前缀和可以常数时间回答区间和，但单点更新会影响许多后续前缀。树状数组与线段树把聚合结果分成层级维护，使更新与查询都只触及对数个片段。

树状数组通常采用从 1 开始的内部下标。`lowbit(i)=i&(-i)` 表示 i 的最低有效 1 位对应的长度，tree[i] 保存以 i 结尾、长度为 lowbit(i) 的区间和。查询前缀时不断减去 lowbit，把前缀拆成互不重叠的片段；单点增加时不断加 lowbit，更新包含该点的祖先片段。每次更新和查询都是 $`O(\log n)`$。

本板块接口采用外部从 0 开始的下标，并把前缀查询定义为 `[0,end)`，内部再加一，减少调用侧的 off-by-one。区间 `[l,r)` 的和等于 prefix(r)-prefix(l)。这种相减要求聚合支持相应逆运算，不能把所有 min/max 查询直接套进同一个模板。

线段树把区间二分，每个节点保存左右子区间的聚合。只要合并运算满足结合律并定义单位元，就能支持很多区间查询；区间修改通常还要设计可组合的懒标记，并证明标记如何作用于聚合结果。它更通用，但内存与实现常数通常更大。

频次累计、动态排名和离散时间统计可以使用这些结构。若要从前缀频次中找第 K 个元素，还需要频次非负以保持前缀单调。整数总和可能溢出，三语言共同接口需规定数值范围；数据结构的对数复杂度不会替代数值安全。

<h1 id="q-006">2. 堆为什么适合维护最值和 Top K？</h1>

<h2 id="q-007">面试问题：堆如何用数组表示？</h2>

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

二叉堆利用完全二叉树的紧凑形状，把节点按层连续放进数组。下标从 0 开始时，节点 i 的左孩子为 `2*i+1`，右孩子为 `2*i+2`，非根节点的父节点为 `(i-1)//2`。访问孩子前必须判断下标是否小于堆长度，根节点没有父节点。

小顶堆要求每个父节点不大于其孩子，因此根是全局最小值；大顶堆反之。它不要求左子树所有值都小于右子树，也不保证数组本身有序。例如 `[1,4,2,9,6]` 可以是小顶堆，但直接遍历不会得到排序结果。

数组表示省去了左右孩子指针，父子位置可以计算得到。查看堆顶是 $`O(1)`$，沿高度上浮或下沉是 $`O(\log n)`$。查找任意指定值仍可能需要 $`O(n)`$，不能因为堆“有序”就对堆数组二分。

若优先队列需要按 ID 修改优先级，可以维护 ID 到堆下标的映射，并在每次交换时同步更新；另一种做法是加入新版本、弹出时丢弃过期版本。前者实现复杂，后者可能积累额外内存，需根据更新频率选择。

生产实现还要注意索引乘法溢出、比较器是否形成一致顺序，以及对象生命周期。存储整数候选时紧凑数组很有效；对大对象，堆中保存小型索引或句柄可能更合适，但间接访问也有成本。

<h2 id="q-008">面试问题：堆的插入、删除和建堆过程是什么？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

插入时先把新元素放在数组末尾，保持完全二叉树形状，再与父节点比较并向上移动，直到满足堆序。删除堆顶时，把末尾元素放到根的位置，然后不断与更优的孩子交换或移动，直到恢复堆序。小顶堆要选两个孩子中较小的，不能随便选一个。

两种操作最多沿树高移动，时间为 $`O(\log n)`$。实现可以用“空穴”方式：暂存待放元素，让父或子逐层移动，最后只写一次暂存元素，减少交换造成的多次赋值。这个优化保持同样的不变量，收益取决于元素类型和数据分布。

对已有数组建堆，不必逐个插入。最后一个非叶节点在 `n//2-1`，从它开始向前逐个下沉。叶子已经天然是堆，处理某节点时其左右子树也已经是堆，因此只需修复当前根。

线性建堆的成本来自不同节点的高度分布：大约一半节点是叶子，四分之一节点只下沉一层，越高的节点越少。总工作量受以下级数控制：

```math
\sum_{h\ge1} O\!\left(\frac{n}{2^{h+1}}h\right)=O(n).
```

逐个插入的最坏成本是 $`O(n\log n)`$，自底向上建堆是 $`O(n)`$，二者不能混淆。Top K 的前 K 项可先线性建堆，后续超过堆顶的元素只需替换并下沉一次，避免不必要的先弹出再插入。

<h2 id="q-009">面试问题：堆排序、优先队列和 Beam Search 有什么关系？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

堆排序是一种排序过程，优先队列是一种操作接口，Beam Search 是限制候选宽度的搜索策略。堆能实现优先队列，也能用于 Beam Search 的候选选择，但这三者不在同一抽象层。

堆排序先建堆，再反复把堆顶与末端交换并缩小堆区间。数组版本可做到常数辅助空间、最坏 $`O(n\log n)`$ 时间，通常不稳定。优先队列则持续接受插入和取最优操作，不要求一次性输出所有元素。

Beam Search 在每一步扩展当前 B 条序列，再按累计得分保留候选。若每个父序列扩展词表 V 项，候选规模可能达到 B×V。可以用堆、选择算法或设备专用 Top K kernel，但还需要保存父序列索引，以便回溯对应 token 与状态。

候选评分通常基于累计对数概率，结束符处理、长度归一化与约束会影响排序。Beam Search 只保留有限宽度，提前丢弃的路径以后无法恢复，因此一般不保证全局最优序列。宽度增加也不等于任务质量单调提高，评分函数与评价目标可能不一致。

Top P 采样和 Beam Search 又有不同语义：前者从按概率质量截取的集合中抽样，后者保留评分靠前的路径。介绍工程实现时应先明确输出策略，再解释候选管理结构，避免把所有生成方法都统称为优先队列搜索。

<h1 id="q-010">3. 图结构解决什么问题？</h1>

<h2 id="q-011">面试问题：邻接矩阵和邻接表如何选择？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

先定义图的顶点数 V、边数 E，以及边是否有向、是否带权、是否允许重边。邻接矩阵为每对顶点保留位置，空间 $`O(V^2)`$，判断某条边存在通常为常数时间；邻接表只保存实际邻居，空间 $`O(V+E)`$，遍历一个节点的邻居与其度数相关。

无向图的邻接表通常把一条边保存两次，计算内存时要包含这一常数。带权矩阵还要区分“没有边”和“权重为零”，不能都用 0 表示。重边在矩阵里是保留最小权、累计值，还是单独存列表，也需要明确。

若主要操作是反复遍历稀疏图，邻接表更自然；若图很稠密且高频判断任意两点是否相连，矩阵或位集矩阵可能更合适。邻接表中查边，使用未排序数组需要扫描，使用哈希集合可改善期望查询，但增加内存和维护成本。

静态大图常用 CSR：一个 offset 数组指出每个顶点邻接区间，另一个连续数组保存邻居。它减少小对象分配并改善扫描局部性，但插入边可能需要重建或增量区，适用更新频率与普通邻接链表不同。

图算法复杂度必须与表示配套。BFS 用邻接表为 $`O(V+E)`$，用矩阵寻找每个节点的邻居可能达到 $`O(V^2)`$。AI 文档图、调用图和依赖图通常较稀疏，但仍应检查真实度数分布，少数超高连接节点会改变遍历成本与负载均衡。

<h2 id="q-012">面试问题：BFS 和 DFS 如何对比？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

BFS 使用队列逐层展开，DFS 使用递归或显式栈优先深入一条分支。对邻接表表示的图，两者完整遍历的时间都为 $`O(V+E)`$，但访问顺序、保存的前沿和适合解决的问题不同。

无权最短路适合 BFS。某节点第一次被发现时，所有更浅层已经处理，所以得到的层数就是最少边数距离。DFS 即使先找到一条路径，也不能说明它最短：一条很长的分支可能先被访问，较短路径还留在另一侧。

DFS 适合递归依赖分析、连通分量、回边检测和回溯。对有向图判环，需要区分“当前路径中”和“已完成”的节点；仅看 visited 会把共享后继误判成环。对无向图，还要正确处理父边、重边和自环，不能直接照搬有向图规则。

空间上，visited 通常都要 $`O(V)`$。树上的 BFS 队列与层宽有关，DFS 栈与高度有关；一般图的显式 DFS 若在弹出时才标记，也可能压入大量重复项。因此比较空间时要说明具体实现，不宜概括为 DFS 总是更省。

知识图谱的 k 跳邻域扩展适合 BFS，AST 的子树处理适合 DFS。Agent 中使用这些遍历方式时，还要定义“状态相同”的条件，避免把不同权限、预算或环境状态仅按节点名称合并。遍历算法只处理给定图，建模错误不会被遍历本身修复。

<h2 id="q-013">面试问题：如何判断二分图？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

二分图的顶点可以划分成两个集合，每条边都跨越这两个集合。判断时对每个连通分量任选起点染色 0，用 BFS 或 DFS 给邻居染相反颜色；若发现某条边连接同色顶点，就产生矛盾。

从未访问的每个顶点都要启动一次遍历，否则断开图中可能漏掉有奇环的分量。三角形要求颜色依次为 0、1、0，最后一条边连接两个 0，因而不是二分图；四边形可以交替染色。无向图可二分当且仅当不存在奇环，自环就是长度为 1 的奇环。

实现中在入队时赋色，能保证每个节点只入队一次。邻接表上的时间 $`O(V+E)`$、辅助空间 $`O(V)`$。边的端点范围需要检查，孤立顶点可放入任一侧，空图也满足二分条件。代码库输入无向边表，由函数构建双向邻接，避免调用者漏写反向边。

用户与物品、标注员与样本等天然分成两类对象的关系可以建成二分图。不过“是二分图”和“已经找到最优匹配”是两件事：染色只检查可分组性，最大匹配、带权匹配或容量约束需要专门算法。

任务分配若包含一个任务占用多个资源、资源容量大于一或时间冲突，简单的一对一匹配也可能不足。先确认节点两侧与边的业务含义，再判断是否需要匹配、流或更一般的优化模型。

<h2 id="q-021">面试问题：并查集如何高效维护动态连通性，它的边界是什么？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

并查集维护互不相交的集合，支持查询元素属于哪个集合，以及合并两个集合。每个集合用一棵父指针树表示，根节点是代表。判断两点是否连通，就是检查它们的根是否相同。

单纯把一棵树挂到另一棵树下，可能形成长链。按大小合并让小树挂到大树，控制高度；路径压缩在 find 时把访问路径上的节点连接到更靠近根的位置，缩短后续查询。二者结合，操作序列的摊还复杂度接近常数，常记为 $`O(\alpha(n))`$，α 是增长极慢的反阿克曼函数。它不等同于每次操作严格只做常数步。

例如依次加入无向边 `(0,1)、(2,3)、(1,2)`，前三个合并让 0、1、2、3 属于同一集合。再加入 `(0,3)` 时，两端已有相同根，可用于检测这条边是否形成环。孤立点初始各自成一个集合。

并查集适合只增加连接的离线聚类、Kruskal 最小生成树与连通组件维护。它不保存真实路径，也不回答最短路，更不直接维护有向可达性。任意删边会把集合拆开，而普通并查集没有拆分能力，需要离线处理、回滚或更复杂的动态结构。

数据去重中，可以把确认等价的样本关系合并成组，但近似相似并不一定满足传递性。A 像 B、B 像 C，不代表 A 和 C 也足够相似；选择把相似图连通分量作为去重簇，是业务决策，不能归功于并查集替你证明了语义等价。

<h1 id="q-014">4. DAG 和拓扑排序为什么在 AI 工程中很重要？</h1>

<h2 id="q-015">面试问题：Kahn 算法如何实现拓扑排序？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

拓扑序要求每条依赖边 u→v 中，u 出现在 v 之前。Kahn 算法利用入度表示尚未解除的前置依赖：先把入度为 0 的节点放入队列，取出一个节点后删除其出边；某个后继入度减为 0，就成为新的可处理节点。

正确性来自一个直接事实：当前入度为 0 的节点在剩余图中没有前驱，因此可以安全排在剩余节点之前。重复这个过程，若最终取出了全部 V 个节点，就得到合法拓扑序；若队列耗尽但还有节点，剩余部分必然存在环。

在邻接表上，统计入度与删除出边各处理每条边一次，时间 $`O(V+E)`$，辅助空间 $`O(V)`$。同一图可能有多种合法拓扑序。若要求字典序最小，可把普通队列换成最小堆，但引入对数维护成本。重边若保留，入度统计与删除次数必须一致。

空图有合法的空拓扑序，而有环图是失败状态，接口应区分。配套实现用可空返回表示有环，避免把两者都编码成空列表。检测到环后，Kahn 未输出的节点还可能包括被环阻塞的下游，不能声称它们全部位于环中。

调度系统可以借用入度思想，但真正执行时，只能在前置任务成功完成后释放后继，不能在任务刚入队时就减少依赖。失败、重试、取消和资源约束都属于拓扑序之外的执行语义，静态排序无法替代完整调度器。

<h2 id="q-016">面试问题：DFS 如何做拓扑排序和环检测？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

有向图 DFS 使用三种状态：未访问、正在当前搜索路径中、已经完成。进入节点时标为正在访问，递归处理后继，退出时标为完成并追加到结果。若某条边指向正在访问的节点，就回到了当前路径上的祖先，形成有向环。

指向已经完成节点的边不代表环。例如 A→C、B→C，处理 B 时 C 可能早已完成，这只是共享后继。把所有 visited 节点都视为环，会错误拒绝这样的 DAG。

在没有环时，节点退出的顺序是后序：每条 u→v 中，v 会在 u 之前完成，或者它此前已经完成。因此将完成序列反转，就得到 u 在 v 前的拓扑序。遍历必须覆盖所有节点，包括没有从首个起点可达的分量。

时间为 $`O(V+E)`$，状态数组与搜索栈为 $`O(V)`$。深依赖链可能使递归栈溢出，显式栈需要保存当前节点以及下一条待处理边的位置，不能只存节点值。若需要输出环路证据，可以在遇到回边时沿父指针或当前路径重建。

代码导入图、构建依赖和任务前置关系都适用这套方法。带显式循环语义的工作流不一定设计错误，应把循环体、终止条件或时间展开后的状态另行建模。拓扑排序的适用对象是 DAG，不能靠忽略回边把一个循环程序“变成”合法 DAG。

<h2 id="q-017">面试问题：Dijkstra、A* 和最短路在 AI 系统中有哪些应用？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

最短路先要定义可累加的路径代价。BFS 适合无权或等权边，Dijkstra 适合非负边权，Bellman–Ford 可以处理负边并检测源点可达的负环，Floyd–Warshall 常用于较小规模的全源问题。算法选择由边权条件与查询形式决定。

Dijkstra 维护从源点出发的暂定距离，每次确定当前最小距离节点，再尝试用它改进邻居。非负边保证未处理路径绕行后不会突然降低已确定节点的距离，这是贪心成立的关键。若允许负权，这个证明就失效。

二叉堆实现可以不做 decrease-key，而是在改进距离时加入新条目，弹出时跳过与当前 dist 不一致的旧条目。这样编码简单，但堆可能保存 $`O(E)`$ 条记录。一般可写为 $`O((V+E)\log(V+E))`$，在常见简单图条件下常简化为 $`O((V+E)\log V)`$。距离相加需要防溢出，不可把溢出后的负数误认为更短路径。

A* 按 $`f(v)=g(v)+h(v)`$ 排序，g 是已走代价，h 是到目标的估计。可采纳启发式不高估剩余最优代价；若图搜索不重新打开已经关闭的节点，通常还需要一致性等条件。仅说“h 不高估所以任何 A* 实现都最优”不够严谨。h=0 时，A* 退化到类似 Dijkstra 的搜索。

机器人导航、状态空间规划与成本可加的工具路径都能使用最短路。但文档相似度不是天然可加的路径代价，工具结果又可能改变状态和成功概率。应先证明图与代价模型符合任务，再谈最短路的最优性。

<h1 id="q-018">5. 为什么说大模型系统越来越像图系统？</h1>

<h2 id="q-019">面试问题：计算图、知识图谱、RAG 图检索和 Agent Workflow 如何对应到图算法？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

把系统表示成图的价值，是把关系和依赖显式化。先定义节点与边，才能选择算法：算子间的数据依赖、实体间的关系、文档间的引用和任务间的执行约束，虽然都能画箭头，含义却不相同。

<div align="center">

| 图的用途 | 节点与边 | 典型算法及边界 |
|---|---|---|
| 一次展开执行的数据依赖 | 算子、张量与依赖 | 拓扑排序；共享结果需要引用与生命周期管理 |
| 知识图谱 | 实体与有类型关系 | 邻域扩展、路径查询；边存在不等于事实可信 |
| 文档或 RAG 图 | chunk、实体、引用 | k 跳扩展、社区检索；需控制噪声与证据来源 |
| 任务工作流 | 任务、完成依赖或转移 | DAG 调度或状态机；循环需明确执行语义 |
| 代码依赖图 | 文件、符号与调用 | 可达性、影响分析；静态信息可能不完整 |

</div>

计算图通常可以对某次已展开的依赖进行拓扑处理，但包含循环控制流的程序表示不必是普通 DAG。自动微分还要累积共享节点收到的多路梯度，不能将它简单等同于反转一个数组。

图检索可能补充仅靠向量相似度难以覆盖的关系链，也可能把错误实体连接传播到上下文。评估时要看加入的关系是否改善证据覆盖与答案质量，不能用“多跳更多”代替有效性证明。

GNN 进一步在图上学习表示：通过邻居聚合更新节点特征，再用于节点、边或整图预测。它与 BFS 扩展可以访问同一邻接结构，但训练目标、聚合函数与采样预算不同，不能把图遍历本身称为图神经网络。

Agent 的并行、条件分支和反馈可以用图表达，回滚却不由 DAG 自动提供。执行过的外部操作是否可撤销、重试是否幂等，都需要额外规则。图提供结构，运行时与业务约束决定这些边真正意味着什么。

<h2 id="q-020">面试问题：图算法在模型部署和任务调度中如何落地？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

可以从依赖正确性、资源安排和影响分析三个层面回答。依赖图决定哪些任务先完成；资源模型决定当前可执行任务中哪些能同时运行；可达性分析决定某个节点变更会影响哪些下游。三者经常结合，但不能由一次拓扑排序全部解决。

例如解析文档、生成 embedding、更新索引构成依赖链。Kahn 式入度维护可以找到就绪节点；若 embedding 节点有一百个，而 GPU 只能同时处理十个，就还需要队列与容量约束。完成一个任务后更新后继状态，失败时则依据重试与取消策略处理，而不是直接视作依赖已经满足。

任务耗时已知时，DAG 上的最长依赖路径给出关键路径长度，是完成时间的一个下界。有限设备、通信和共享内存会增加实际耗时；一般资源受限调度可能很难求全局最优，所以常使用优先级与启发式，并用真实负载验证。

计算图编译还涉及算子融合、常量折叠与张量生命周期。融合可以减少中间写回，也可能增大寄存器压力；内存复用要求两个张量的有效存活区间不冲突。图上的局部变换需要保持计算语义，并不只是减少节点数量。

变更一个数据源或模型后，沿依赖边找到受影响节点可以指导重新计算与回归测试。若边记录不完整，影响分析会漏项；若一律全连，又会失去筛选价值。工程落地要维护图本身的版本、来源和更新规则。
