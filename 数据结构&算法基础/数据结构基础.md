# 按操作需求选择数据结构

先写出最频繁的操作，再看规模、更新方式与内存预算。下表可用作查阅入口，完整学习路线见[板块目录](readme.md)。

<div align="center">

| 需求 | 先考虑什么 | 进一步阅读 |
|---|---|---|
| 下标读取与数值计算 | 连续存储、类型、stride | [数组与 Tensor](02_线性数据结构高频考点.md#q-001) |
| 按完整 key 查值 | 哈希成本、负载、完整键核验 | [哈希](03_排序查找哈希高频考点.md#q-017) |
| 精确查值并维护新旧顺序 | 哈希映射与双向链表一致性 | [LRU](02_线性数据结构高频考点.md#q-008) |
| 顺序处理与缓冲突发 | 容量、背压、取消 | [背压](02_线性数据结构高频考点.md#q-017) |
| 连续窗口极值 | 支配关系与过期下标 | [单调队列](02_线性数据结构高频考点.md#q-015) |

一份数据可以同时拥有多个索引。它们改善查询，也增加内存、写入和失效成本。保留数组扫描或标准库基线，再测真实分布，有助于判断收益。

落到程序时，使用[三语言代码目录](codes/README.md)，把输入条件、返回语义与数值范围一起带入实现。
