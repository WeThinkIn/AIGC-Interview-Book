<h1 id="q-001">1. 算法思想为什么比背题更重要？</h1>

<h2 id="q-002">面试问题：递归的三要素是什么？</h2>

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

递归要写清函数含义、终止条件和问题规模如何下降。函数含义决定每一层可以依赖子调用返回什么；终止条件覆盖最小问题；规模下降保证过程最终结束。只写一个 `if n==0`，却没有证明参数会走向零，仍可能无限递归。

二叉树深度是一个简单例子。定义 depth(root) 返回以 root 为根的子树最大深度，空树深度为 0，非空树深度为左右子树深度较大者加 1。每次调用进入更小子树，因此在有限无环树上会终止。若输入其实是含环对象图，就需要额外状态，原证明不再适用。

分析递归成本时，既看调用次数，也看每次调用内部的工作。树中每个节点访问一次是线性时间；朴素斐波那契递归反复计算相同子问题，调用数会迅速增长；每层复制整个剩余数组还会引入额外开销。递归外形相似，不代表复杂度相同。

递归栈保存待恢复状态。深链可能超过语言或系统栈限制，可以用显式栈或自底向上迭代改写，但必须保留原来隐含的阶段、局部变量和返回位置。显式栈改善控制与安全边界，不自动降低理论空间复杂度。

AST、树形配置和任务分解都适合先用递归契约建模。面对有副作用的任务，还要区分“计算一个子问题”与“执行一次外部动作”；重复调用可能重复写入，不能因为递归结构正确就认为业务可安全重试。

<h2 id="q-003">面试问题：分治、减治和二分查找有什么关系？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

分治把问题拆成多个子问题，分别求解后合并；减治只继续解决一个更小问题。归并排序必须排完左右两半，二分查找则依据中点比较排除一半候选，只进入剩余一侧。两者递归树的形状不同，复杂度也不同。

若每次拆成两个一半规模的子问题，并花线性时间合并，递推为 $`T(n)=2T(n/2)+O(n)`$；若只保留一半且判断为常数时间，则为 $`T(n)=T(n/2)+O(1)`$。前者得到 $`O(n\log n)`$，后者得到 $`O(\log n)`$。不能看到“每次减半”就直接写对数复杂度。

算法选择还依赖可组合性。分片统计词频后，可以合并各片的计数；分片各自求 P99 后，不能简单平均得到全局 P99，因为子结果丢失了必要分布信息。分治的难点常在合并步骤，而非把数据切成几份。

二分答案则依赖可证明的单调谓词，例如固定内存模型下的最大可行容量。模型质量与温度、学习率之间没有通用单调保证，版本质量也可能多次回退又恢复，不能随意二分寻找“首个坏版本”。若使用 git bisect 式方法，就要明确假设边界只有一次且测试足够稳定。

工程中应先写出子问题与合并规则，再评估拆分收益。并行执行会引入通信、复制与负载不均衡；CPU 核心多并不意味着任意递归拆分都能线性加速。

<h2 id="q-004">面试问题：怎样从归并过程推导递归复杂度，并判断能否并行？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

归并排序提供了观察递归成本的清楚例子。每层把总共 n 个元素分散到若干子区间，每个元素在该层参与常数次比较或写入，因此一层的总工作为线性；从长度 n 切到单元素大约需要对数层，总工作为 $`O(n\log n)`$。

这个推导隐含线性合并。若把一个元素插入输出数组中部，或每次删除列表头导致整体搬移，就改变了合并成本。分析时应把实际容器操作代入递推，而不是只按函数名字套结论。

左右子区间独立，理论上可以并行排序，完成后再合并。但若合并本身仍串行，关键路径包含每一层合并中的等待，增加工作线程会逐渐遇到上限；内存带宽、任务创建与同步也会限制收益。小区间继续分派线程常得不偿失。

同样的思路可用于大规模数据处理：先按可独立单元分片，局部计算，再合并。要检查每个局部结果是否保留全局计算需要的信息，以及结果大小会不会使合并成为瓶颈。K 路有序流归并只保存每路当前候选，适合流式输出；需要全局随机访问的后续计算则可能仍要保存全部结果。

代码与基本排序性质集中在[归并排序章节](03_排序查找哈希高频考点.md#q-006)。这里更重要的是掌握“每层工作量、层数、关键路径、合并信息”四个分析角度，用来判断其他分治算法是否真的适合并行或分布式执行。

<h1 id="q-005">2. 回溯算法的核心思想是什么？</h1>

<h2 id="q-006">面试问题：回溯模板如何写，为什么要撤销选择？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

回溯把候选解逐步构造成一条路径。当前层先枚举一个可选动作，修改路径与约束状态，进入下一层；返回后撤销修改，再尝试同层其他动作。撤销的目的，是让相邻分支都从相同父状态出发，避免前一条路径污染后一条。

以从 1..n 中选 k 个数为例，path 保存已选数字，start 限定下一次只能选择更大的数字，因此每个组合只出现一次。若还需选择 r 个数，起点 x 最大只需到 `n-r+1`；更靠后的起点剩余元素不足，可以直接剪枝。

保存答案时必须复制当前路径，或向外发送一个具有明确生命周期的不可变结果。若把同一个可变列表引用反复放进答案，最后所有记录可能都变成空路径或最后一条路径。Java 中把结果数组作为对象字段，还容易在第二次调用时残留旧答案。

组合、排列和含重复值的枚举需要不同状态。排列要记哪些位置已经使用；组合通过递增起点消除顺序重复；含重复元素时需要决定按值去重还是按输入位置区分。不能把 used 数组和“跳过相同值”无条件套到所有问题。

枚举全部答案的成本至少受输出量限制，组合问题有 $`\binom nk`$ 个结果，复制每条 k 项答案就要相应时间与空间。大规模场景可以用生成器或回调逐条消费，但消费方仍需承担全部输出成本。外部工具调用不是内存变量，不能靠 `pop()` 撤销已经发生的真实操作。

<h2 id="q-007">面试问题：回溯、DFS、穷举和剪枝有什么区别？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

DFS 描述优先深入的遍历顺序，穷举描述覆盖候选空间的范围，回溯描述选择、深入和恢复状态的搜索过程，剪枝描述提前排除部分分支。它们可以组合，但不是同义词。遍历一个连通分量的 DFS，不一定需要撤销选择；回溯也可以在安全剪枝后仍保持解的完备性。

剪枝要区分证明性条件和启发式条件。组合问题剩余元素不够，是可证明没有解；分支定界中，某分支的最优可能下界已差于当前解，可以排除；模型给某条推理路径打低分，则只是估计，剪掉它可能丢失真实最优答案。

调整搜索顺序通常不会损害完整搜索的完备性，例如先尝试约束最多的变量；直接保留评分前几个分支则改变了搜索范围。把这两种做法都称为“启发式剪枝”，却不说明是否可能漏解，会让性能与正确性边界模糊。

重复状态处理也要谨慎。若不同路径到达完全相同的状态且后续收益只由状态决定，可以复用结果；若剩余预算、已访问约束或环境状态不同，单纯按当前位置去重会误删有效路径。状态定义是搜索能否正确压缩的基础。

Agent 规划中可限制步数、成本和工具集合，提前阻止确定不可行的路径，并用模型评分安排探索顺序。若使用固定 beam 或提前停止，就应把它视为预算内的近似搜索，保留验证与回退机制，而不是宣称穷举了所有可能方案。

<h2 id="q-008">面试问题：搜索算法在 AIGC 生成和 Agent 规划中如何使用？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

生成可以理解为在状态空间中逐步扩展候选，但不同策略保留的信息不同。Greedy 每步选最高分 token，Beam Search 保留有限条路径，Top K/Top P 先限制采样集合再随机抽样。它们对多样性、计算预算和评分误差的响应并不相同。

推理增强通常在模型外增加生成、评估与选择循环。多个候选解可以通过测试、约束检查或外部环境反馈验证；若只用同一模型给自己打分，评分偏差可能被搜索放大。扩大搜索量也会增加工具调用、延迟和费用，并不保证真实正确率总是提高。

规划状态应包含足以影响后续决策的信息，例如当前任务、已获取证据、剩余预算、工具状态和已发生的操作。两个文本描述看似相同的节点，如果对应不同外部状态，就不能直接合并。可重复执行的纯计算与有副作用的动作应采用不同缓存及重试规则。

一个可落地的循环是：生成有限候选、先做便宜的确定性检查，再做昂贵评估，保留结果与证据，按预算决定是否继续。代码修复可以用编译和测试淘汰候选；检索规划可以检查证据覆盖；涉及真实操作的分支则需要模拟、沙箱或明确的补偿过程。

评价搜索要同时报告质量和预算。一次答案正确但花了百倍成本，与相同预算下更可靠是不同结论。长期有用的能力是定义状态、评分、验证与停止条件，使搜索过程可以检查、复现和调度。

<h2 id="q-021">面试问题：未知长度的数据流如何做等概率抽样？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

蓄水池抽样在只能扫描一次、事先不知道总长度的数据流中，保存 k 个样本。先把前 k 项放入蓄水池；处理第 i 项时，从 1..i 等概率选一个整数 j，若 j≤k，就替换第 j 个位置，否则跳过。只需要 $`O(k)`$ 样本存储。

正确性可用归纳证明。第 i 项被选入的概率为 k/i；此前任意一项在前 i-1 项中被保留的概率为 k/(i-1)，本轮不被替换的概率为 (i-1)/i，两者相乘同样为 k/i。因此处理完 n 项后，每个输入位置被包含的概率相同。

这里抽样单位是输入位置，不是去重后的值。某个样本重复出现多次，会按出现次数获得更多机会；若目标是对唯一文档等概率抽样，需要先定义身份和去重策略。随机数生成器、种子与数据顺序应记录，便于复现实验。

并行分片不能简单从每个分片各取相同数量再拼接，因为分片大小可能不同。可采用正确的加权合并方案，或为每个元素生成独立随机优先级并保留全局前 k 个；优先级碰撞与生成方式也要处理。加权抽样则有自己的算法，不应随意修改基础替换概率。

它适合从海量日志或训练数据中构建审查样本。抽样能控制处理成本，但稀有事件可能未被抽到；用于故障分析或分布覆盖时，可以结合分层抽样，并明确结果代表的是整体比例还是各层的观察机会。

<h1 id="q-009">3. 动态规划为什么是高频面试难点？</h1>

<h2 id="q-010">面试问题：如何设计 DP 的状态、转移和初始化？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

动态规划先决定哪些历史可以压缩成同一个状态。只要后续决策所需信息已经包含在状态里，就可以复用该子问题的结果；若漏掉重要条件，两个看似相同的状态可能有不同未来，转移就不成立。DP 不只用于最优值，也可用于计数、可达性和概率求和。

以 0/1 背包为例，前 i 件物品、容量不超过 c 的最大价值可以定义为 dp[i][c]。当前物品要么不选，要么在容量允许时选一次，分别对应前一层状态。初始条件表达“没有物品时价值为零”，如果题目要求恰好装满，则不可达容量应使用负无穷或显式不可达标记，不能全部填零。

转为一维数组后，容量需要从大到小更新，确保读取的是上一轮状态；从小到大更新会让当前物品被重复使用，变成另一种问题。空间压缩改变了读写时序，因此必须重新检查依赖关系，而不是删掉一个数组维度就结束。

一般设计顺序是定义状态含义、列出互斥且完整的最后一步选择、设置边界、确定计算顺序，再定位最终答案。计算顺序应保证依赖先完成，自顶向下记忆化与自底向上填表是两种组织方式。

复杂度通常由状态数乘每个状态的转移成本估算，输出路径还需要记录选择或额外重建。状态过多时，应先检查是否有冗余、特殊单调性或可用的数据结构优化，避免把所有问题都塞进一个巨大 DP 表。

<h2 id="q-011">面试问题：编辑距离、LCS、LIS 分别考察什么？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

编辑距离比较两个序列通过插入、删除、替换变成相同序列的最小代价；LCS 求最长公共子序列，元素保持相对顺序但不必连续；LIS 在一个序列内求严格上升子序列。三者都涉及顺序，但目标与转移不同。

单位代价编辑距离令 dp[i][j] 表示 a 的前 i 项变成 b 的前 j 项的最小操作数，边界为 dp[i][0]=i、dp[0][j]=j。转移为：

```math
dp[i][j]=\min\{dp[i-1][j]+1,\ dp[i][j-1]+1,\ dp[i-1][j-1]+[a_{i-1}\ne b_{j-1}]\}.
```

三个分支分别对应删除、插入、匹配或替换。LCS 在两项相等时取对角状态加一，否则在跳过其中一项的状态中取最大值。两者朴素时间都为 $`O(nm)`$，只求数值时可压缩行；恢复完整对齐或子序列还需要额外信息。

LIS 的基础 DP 考虑所有更早且更小的前驱，时间 $`O(n^2)`$。优化做法维护每个长度的最小可能结尾 tails，用 lower_bound 更新，得到 $`O(n\log n)`$。tails 的整条数组不一定就是一个实际子序列；要恢复路径需记录前驱。非降序版本对相等值的边界选择不同。

ASR 的 WER 通常按词计算编辑操作，OCR 的 CER 常按字符单位，代码 diff 也可能按行或 token。编辑距离度量的是指定单位与操作的差异，不直接衡量语义正确性。把同义改写与错误答案放在一起只比字符距离，可能得到误导性的评价。

<h2 id="q-012">面试问题：DP 在语音识别、NLP 和大模型系统中有哪些应用？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

很多序列任务需要在大量对齐或路径中聚合信息，DP 通过共享前缀状态避免逐条枚举。Viterbi 在满足相应状态依赖假设的模型中寻找最大概率路径，前向算法则对路径概率求和。两者可能使用相似状态图，但“取最大”与“求和”对应不同问题。

CTC 在输入帧数与目标标签长度不一致时，考虑插入 blank、重复标签与折叠规则允许的多条对齐路径。前向后向递推对这些合法路径累积概率，转移中必须区分相同相邻标签，不能把所有跳转都无条件放开。实现通常在对数域使用 log-sum-exp，避免长序列概率连乘下溢。

编辑距离用于词或字符级错误统计；某些分词模型把切分位置看成路径，用 DP 寻找最优切分；版本比较使用与序列对齐相关的算法，但真实 diff 工具未必直接构造完整 LCS 表。具体实现可能为内存、局部性和输出可读性做其他选择。

强化学习中的 Bellman 关系也体现状态价值递推，但循环状态转移往往需要迭代求固定点，与一次按 DAG 顺序填表不同。状态是否足够表达未来、折扣与收敛条件都要单独说明。

Transformer 的前向计算不能笼统归类为传统序列 DP，不过其训练与服务周边仍大量使用对齐、预算分配和路径聚合。理解这些经典方法，有助于识别哪些状态可以复用，哪些历史信息不能被安全丢弃。

<h1 id="q-013">4. 贪心、双指针和滑动窗口解决什么问题？</h1>

<h2 id="q-014">面试问题：贪心算法什么时候可靠？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

贪心每一步做局部选择，但全局正确需要证明。常见证明方式是交换论证：把任意最优解逐步变换成包含当前贪心选择的最优解，且不降低质量；或者证明某个选择必须属于某个最优解，再递归处理剩余问题。

最大数量的无重叠区间调度，可以优先选择结束最早的区间。若最优解第一项结束更晚，用结束最早者替换不会挤掉后续活动，因此至少存在一个最优解包含该选择。若区间带不同价值，目标改为总价值最大，这个规则就可能失效，需要加权区间调度等方法。

硬币面额 1、3、4，凑金额 6 时，总选最大面额会得到 4+1+1，最优却是 3+3。这个反例说明“每次看起来更大更好”没有普遍保证。Dijkstra 的贪心则依赖非负边权，Huffman 合并最小频次节点也有专门证明。

AI 工程中的很多规则属于启发式：优先保留最近上下文、按相关性分数挑 chunk、先执行短任务。它们可能有效，但目标还可能涉及覆盖、冗余、公平性和完成时限，不能把单个排序分数自动当成完整优化目标。

面试可以先给出规则，再说明它成立的条件，最后给出一个改变条件就失效的反例。对无法证明最优的策略，应明确它的预算优势，并通过对照实验检查质量与成本，而非把“工程常用”当成最优性的证明。

<h2 id="q-015">面试问题：双指针和滑动窗口有什么区别？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

双指针是用两个位置协同推进的一类技巧，滑动窗口是维护连续区间的常见形式。相向指针可用于有序数组两数之和，快慢指针可用于链表，同向指针可用于合并；它们不都在维护一个窗口。

最长无重复子串中，右端扩张时记录字符最近出现的位置。若当前字符此前出现在窗口内部，就把左端移到那次位置之后。左端只能前进，不能被窗口之外的旧位置拉回去。`abba` 是一个有效反例：处理最后一个 a 时，左端不应从第二个 b 后退回第一个 a 后面。

线性复杂度通常来自每个指针单调移动至多 n 次，而不是因为“有两个指针”。维护窗口统计也需要成本：计数哈希常为期望常数，窗口最大值需要单调队列，精确分位数则需要更复杂的结构。若每次移动都重扫窗口，就可能仍是二次时间。

经典“和至少为 S 的最短子数组”滑窗在元素非负时容易证明：扩张使和不减，收缩使和不增。加入负数后，这种单调性失效，需要前缀和与其他结构。题目表面仍是连续区间，算法却不能照搬。

处理文本时还要指定字符单位，处理流式数据时要说明过期规则与能否回看。滑窗不是任意历史依赖的通用压缩；只有窗口外的信息可以安全丢弃，维护的状态才足以支持正确答案。

<h2 id="q-016">面试问题：长上下文、chunking 和 token budget 如何用窗口思想理解？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

窗口为有限预算下的局部处理提供结构。固定长度切片实现简单，重叠切片保留边界上下文，按段落或标题切片更贴近文档结构，但可能造成长度不均。不同策略改变召回粒度、重复比例和模型可见的信息，不能只比较 chunk 数量。

若窗口长度为 W、重叠为 O，步长为 W-O，需要保证 $`0\le O\lt W`$，否则窗口不前进。长文档的切片数量近似与 $`L/(W-O)`$ 相关，重叠越大，索引和 embedding 成本越高；这个开销应与减少边界断裂的收益一起评估。

prompt 预算要同时容纳系统指令、用户问题、工具描述、检索证据和预留输出。token 数需由目标 tokenizer 与实际对话模板计算，字符数不能直接替代；聊天模板和结构标记也可能占用预算。

滑动对话历史会删除旧信息，摘要会引入压缩与遗漏，检索记忆则依赖召回。它们都改变模型获得的证据，不能宣称简单截断始终等价于完整上下文。某些模型原生使用滑窗注意力，与应用层随意丢弃 KV 又是不同的机制。

一个实用流程是先保留必须信息，再按任务目标选择证据，合并重复片段，检查总 token 数和引用完整性，最后在真实任务上评估答案。上下文管理的长期问题是如何在有限预算内保存足够信息，窗口只提供一种组织手段。

<h2 id="q-022">面试问题：RAG 的 token 预算分配为什么不总能按分数贪心？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

检索分数高并不代表单位 token 的价值最高，也不代表多个高分 chunk 放在一起就覆盖了问题。预算分配同时涉及长度、相关性、互补性和重复内容。只有先明确目标函数，才能判断排序截断是否合理。

最简单的模型把每个 chunk 看成一个不可拆分物品，长度为成本，价值为收益，在 token 预算内最大化总价值，这类似 0/1 背包。按价值或价值密度贪心都不保证最优；容量为 10，候选成本价值分别为 `(6,12)、(5,9)、(5,9)`，密度贪心先取第一项只得 12，后两项组合得到 18。

若收益是独立可加的整数价值，可以用容量 DP；但真实证据之间可能重复、互相补充或矛盾，简单可加模型并不完整。可以加入覆盖目标与冗余惩罚，或者采用经过验证的启发式。模型越复杂，求解与标注目标的成本也越高。

还有必须满足的硬约束：保留系统指令、用户问题、预留生成空间、完整引用以及不能被随意裁剪的表格或代码。预算单位需由目标 tokenizer 计算；一段文本的字符长度不是 token 成本。

实践中可以用小规模精确求解作为对照，检验按分数截断、按密度选择和去重后选择的损失，再选符合延迟预算的方案。跨周期价值在于把上下文当作有限资源分配，并用覆盖与质量验证选择规则，而不是默认“排在前面的都塞进去”。

<h1 id="q-017">5. 为什么 AI 算法岗也会考数值算法和综合设计？</h1>

<h2 id="q-018">面试问题：如何用牛顿迭代求平方根，并处理浮点边界？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

求 $`\sqrt{x}`$ 可以转成求 $`f(t)=t^2-x`$ 的正根。用切线在当前点附近近似函数，得到：

```math
t_{k+1}=t_k-\frac{t_k^2-x}{2t_k}
=\frac12\left(t_k+\frac{x}{t_k}\right).
```

对正 x 和合适的正初值，迭代接近根后收敛很快。x=0 应单独处理，负数在实数接口下无解；NaN 与无穷还需要明确策略，不能让它们悄悄进入比较并返回偶然结果。

常见写法以 `abs(t*t-x)<eps` 停止，有两个问题：极大 t 的平方可能溢出，极小 x 又可能在初值很差时已经满足固定绝对误差。迭代到浮点精度极限后，结果还可能不再变化，而残差条件仍不成立，形成死循环。

稳健教学实现先用二进制指数分解 $`x=m2^e`$，把 e 调整为偶数，让 m 留在有界区间，再对 m 迭代，最后恢复 $`2^{e/2}`$ 的尺度。这样避免在极端数量级上直接平方；用相对步长变化和迭代上限判断停止，覆盖次正规数。

这仍不意味着手写实现比硬件或标准库 sqrt 更快，也不自动保证所有输入上正确舍入。本代码用标准库平方根作对照，在包含最小次正规数与最大有限数的输入上检查若干 ULP 内误差。生产数值计算通常优先采用成熟库，手写版本用于理解缩放与收敛条件。

<h2 id="q-019">面试问题：高斯消元如何求解线性方程组？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

对方阵系统 $`A\mathbf{x}=\mathbf{b}`$，高斯消元通过行变换把 A 化为上三角矩阵，再从最后一个方程回代求解。每一列选择主元，用它消去下方各行对应系数，右侧 b 必须同步变换。

若直接用当前位置作主元，遇到零或很小的系数会失败或放大误差。部分选主元在当前列剩余行中选择绝对值最大的项并交换行；行缩放或均衡化可以进一步减少数量级差异。它们改善常见数值行为，但不能保证任何病态矩阵都得到高精度解。

例如两条方程几乎线性相关时，输入的微小扰动可能导致解明显变化，这是问题条件数的影响。小残差不必然意味着解很接近真实解。验证时可计算 $`\lVert A\hat x-b\rVert`$，并相对 $`\lVert A\rVert\lVert\hat x\rVert+\lVert b\rVert`$ 缩放，同时在需要时估计条件数。

稠密消元时间 $`O(n^3)`$，存储通常 $`O(n^2)`$。同一个 A 对多个 b 求解时，可以先做带主元的 LU 分解，再重复三角求解，避免每次从头消元。最小二乘问题不一定适合先构造正规方程，因为这会恶化条件数，QR 或 SVD 往往更稳健。

配套代码只求有限数值输入下的方阵唯一解，拒绝数值上过小的主元，不返回无穷多解的参数表达式。稀疏大系统、秩亏问题和精确有理数计算需要其他接口。把这个简化求解器的边界讲清，比把几十行代码称为通用线性代数库更重要。

<h2 id="q-020">面试问题：如何用算法思维优化 RAG、训练数据处理和 LLM 推理？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

先把端到端耗时与内存拆到具体阶段，再改变其中的工作量或表示。若主要时间花在数据解码，优化向量搜索没有意义；若大量请求等待显存，减少几次 Python 字典查找也未必改变吞吐。基线、瓶颈和评价指标应先于算法选择。

RAG 可以用倒排与向量索引减少扫描，用精确 ID 集合处理过滤，用候选合并与重排控制质量。每一步都要保留文档身份与版本，建立相同过滤下的精确召回基线。量化、ANN 和缓存分别引入不同误差或失效条件，应单独测量。

训练数据处理可以通过长度分桶减少 padding，用有界预取隐藏 I/O，用哈希候选加精确比较完成去重，用外部归并处理超内存数据。去重误删会改变数据分布，按长度排序会改变采样顺序，所以吞吐改善还要检查数据质量与训练行为。

推理中，KV Cache 复用历史投影，前缀缓存避免公共前缀重复 prefill，动态组批提高设备利用率，选择 kernel 减少无用排序。推测解码则让草稿提出候选、目标模型验证，在接受率和执行开销合适时加速；它仍有验证计算，并非简单减少目标模型工作到零。

最终比较应在相同质量与资源限制下进行，记录吞吐、首 token 延迟、每 token 延迟、尾延迟和峰值内存。算法优化的目标是减少真实瓶颈中的无用工作，而不是让系统中的结构名称越来越多。
