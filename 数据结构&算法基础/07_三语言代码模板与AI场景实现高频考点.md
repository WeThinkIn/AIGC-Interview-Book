<h1 id="q-001">1. 哪些数据结构与算法问答需要配套代码？</h1>

<h2 id="q-002">面试问题：哪些问题需要可执行代码，怎样安排学习顺序？</h2>

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

概念题需要解释定义与取舍，算法实现题还必须把不变量变成可执行操作。会说“二分每次排除一半”，不代表能正确处理空数组和重复值；会背“哈希表加双向链表”，也不代表更新、淘汰与缺失值语义已经一致。因此应把解释、实现和验证连起来学习。

建议先掌握下标与指针：二分边界、链表中点、单调栈和窗口；再学习组合结构：LRU、堆、图遍历、拓扑和最短路；最后练习状态较复杂的字符串、DP、几何与数值算法。每题先手推一个正常样例和一个反例，再编码，能比直接抄模板更早发现遗漏的条件。

系统设计题不宜靠一段代码包办。HNSW、前缀缓存与动态组批需要解释数据流、质量和生命周期；教学代码可以验证局部机制，却没有替代成熟系统的并发、持久化与故障恢复能力。概念讲解在 01—06 章，完整实现集中在 [codes](codes/README.md)，本章负责把两者对应起来。

三语言使用相同任务语义与共同数值域。每次修改都用固定边界、随机小输入参考算法及语言间结果检查验证。C++ 还检查内存与未定义行为；性能基准单独运行，避免把正确性测试进程的解析和输出开销算进算法时间。

学习目标是能够说明“为什么正确、代价在哪里、什么时候不能使用”。标准库已经解决的生产问题，应优先比较标准库；手写实现保留其教学价值与可检查性，而性能选择要服从测量结果。

<h2 id="q-003">面试问题：Python、C++、Java 的实现如何保持语义一致？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

跨语言最容易出错的是契约，不是语法。Python 整数可以增长，C++ 有符号溢出属于未定义行为，Java 整数溢出会回绕；Python str 按码点处理，C++ string 常见用法按字节，Java String 常用下标按 UTF-16 代码单元。若不先统一口径，相同算法可能产生不同结果。

本代码库约定整数序列使用共同的有符号 64 位取值域；字符串算法接收整数符号序列，返回符号下标。Python 可用 `[ord(c) for c in text]` 转码点，Java 可用 `text.codePoints().asLongStream().toArray()`；C++ 调用者应采用可靠的 Unicode 解码器，或直接提供 token ID，不能把 UTF-8 字节强行当码点。

容器缺失状态也保持清楚：LRU 的 Python 返回 None，Java 返回可空 Long，C++ 返回 optional；合法值 -1 不与未命中冲突。Top K 都保留重复值并降序返回；拓扑排序把有环失败与空图的合法空结果区分开；几何判断返回外部、边界、内部三个状态。

C++ 采用 C++20，使用 RAII 容器管理内部存储，链表与树的指针接口借用节点、不负责释放调用者对象。Java 优先在窗口、堆等热循环使用基本类型数组，减少装箱。Python 使用 deque、heapq 等成熟原生或库结构，避免为了形式统一而重复手写低效容器。

本章“C/C++”语言组提供的是经过编译验证的 C++ 实现，不能当作 C17 源码直接编译。纯 C 需要重新定义分配、所有权与错误返回，不能仅更换文件后缀。具体 API、限制及运行命令见[代码契约](codes/README.md)。

<h2 id="q-026">面试问题：怎样组织三语言测试，避免三个版本一起写错？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

语言间结果一致只能证明它们相互一致，不能证明答案正确。因此代码库先建立独立参考：排序用标准库，二分用 bisect，窗口用暴力扫描，编辑距离用二维 DP，最短路用小图 Bellman–Ford，二分图用小规模穷举染色。参考算法可以慢，关键是逻辑与被测优化路径不同。

固定边界覆盖空输入、重复值、极端整数、非法窗口、负边权、零容量和浮点特殊值；随机差分覆盖更多组合；变形性质检查反转多边形顶点等不应改变结果的操作。深树与长 Trie 额外检查递归和释放风险。

统一输入协议把同一用例交给三种语言，输出使用 JSON 表达数组、布尔、空值和失败。测试适配器不是业务 API，也不参与计时；它只负责把用例转换成函数调用。C++ 编译启用警告并视为错误，另运行 AddressSanitizer 与 UndefinedBehaviorSanitizer。

异常路径应与正常路径同等重视。错误发生在参数验证、分配还是数值计算阶段，需要保证对象状态不被破坏。测试能发现已覆盖错误，但不能证明不存在所有并发或资源问题；本代码明确为单线程算法库，并不声称已经做了生产服务验收。

可运行入口为 [tests/verify.py](codes/tests/verify.py)，命令见 [codes/README.md](codes/README.md)。用固定随机种子保存失败输入，修复后重跑相关与完整必要检查，让每次性能调整都保留正确性依据。

<h2 id="q-027">面试问题：怎样阅读三语言性能基准，避免把语言排名当成算法结论？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

先比较同一语言内、同一输出契约的实现，再讨论跨语言结果。Python 的标准库常在原生代码中运行，手写循环在解释器中执行；Java 有 JIT 与装箱成本；C++ 受编译优化和模板实例影响。直接比较一次启动脚本的总时间，可能主要测到了运行时启动和输入解析。

本基准在计时前生成固定输入并校验完整输出，预热后重复测量，使用三个独立进程保留多组样本。计时包含为不修改原输入而需要的复制及结果分配，排除数据生成、编译、进程启动和 JSON 输出。结果通过可观察方式消费，避免无用计算被删掉。

排序分别测试随机、有序、逆序和重复值输入；Top K 改变 K/n；窗口比较单调队列与逐窗扫描。CPU、编译参数、Java 版本、预热次数与中位数都保存在[基准记录](codes/BENCHMARKS.md)。这是一组有限的本机微基准，未覆盖所有规模、线程配置和生产负载。

看见某种方法更快后，应解释原因：少做了完整排序、减少装箱、复用缓冲，还是标准库利用了已有顺序。若只是换了返回顺序或漏算输入复制，速度差就不能支持原结论。近似算法还要把准确率对齐，数值算法要对齐误差。

性能优化的可交付结果应包括代码、输入生成规则、正确性验证和比较范围。一个脱离这些条件的“全球最快”标签无法复现；能够复现的分布变化和切换点，才方便后续在新机器与新任务上继续优化。

<h1 id="q-004">2. 线性结构有哪些高频代码模板？</h1>

<h2 id="q-005">面试问题：如何用三种语言实现链表中点和环入口？</h2>

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

`middle_node / middleNode` 让快指针每轮走两步、慢指针走一步，返回偶数长度的后一个中点。空链表返回空值，输入必须无环，函数不修改连接。四节点 `[10,20,30,40]` 返回值为 30 的那个节点，返回的是节点身份而非复制出来的数值。

`cycle_entry / cycleEntry` 先用 Floyd 快慢指针寻找相遇，再让一个指针回头、两个指针同步前进，定位入口。比较必须按对象或指针身份，两个值相同的不同节点不算相遇。辅助空间都是常数，时间与可达节点数线性相关。

Python 的 ListNode 使用 `eq=False`，避免自动生成的结构相等比较沿 next 递归；Java 用 `==` 比较对象身份；C++ 直接比较节点指针。三个版本都不分配新链表，也不承担输入节点的释放责任。

测试先在无环链表上检查中点，再连接尾节点形成不同入口的环，检查返回的入口下标；空表、单节点自环、重复值都在覆盖范围内。不能把中点函数直接用于可能有环的输入而期待它自行终止。

完整实现：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。在文件中定位 `middle_node/middleNode` 与 `cycle_entry/cycleEntry`，可对照快指针每次读取前的空检查。

<h2 id="q-006">面试问题：如何用三种语言实现 LRU Cache？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

三个版本都提供容量、get 和 put。get 命中会更新访问顺序，put 已有键会更新值与顺序，新增键超容量时淘汰最久未访问项。容量为零时不保存任何记录，负容量抛出参数错误；缓存允许保存值 -1，缺失另用可空返回表达。

Python 使用 OrderedDict 的 `move_to_end` 与 `popitem(last=False)`；Java 组合 `LinkedHashMap(...,true)`，让访问更新顺序，并只暴露所需接口；C++ 使用 list 保存条目，unordered_map 保存迭代器，`splice` 移动节点，不重新分配被访问节点。

C++ 有一个容易被忽视的所有权问题：默认复制 list 与 map 后，map 内迭代器仍可能指向源对象的链表。因此此实现禁用复制，避免生成表面可用、实际关联错误的缓存。插入哈希映射分配失败时，也会回滚刚添加的链表节点，保持两种结构一致。

哈希操作通常是期望或平均常数时间，链表移动是常数时间，总内存与容量线性相关。这些实现是单线程、按条目计数、无 TTL 的缓存；字节容量、异步计算合并与并发访问需要另外设计。不能用它们直接替换带共享引用的 KV 块管理器。

完整实现的类名均为 `LRUCache`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。验证使用独立的访问顺序参考模型，检查更新、淘汰、容量为零以及缺失值，避免只测试一次命中。

<h2 id="q-007">面试问题：如何用三种语言实现单调栈和滑动窗口最大值？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

单调栈函数 `next_greater_index / nextGreaterIndex` 返回每个位置右侧第一个严格更大元素的下标，没有则为 -1。用下标而非值作结果，既能计算距离，也不会把合法值 -1 与缺失混淆。相等元素不会触发严格更大关系。

窗口函数 `window_max / windowMax` 保存递减候选下标，先删除过期队首，再从队尾删除被当前元素支配的候选，最后入队。输入 `[1,3,-1,-3,5,3,6,7]`、k=3 的结果为 `[3,3,5,5,6,7]`。要求 `1<=k<=n`，非法窗口直接报错。

Python 使用 deque；C++ 和 Java 使用容量 k 的环形下标缓冲，避免为每个候选创建节点，Java 也避免 Integer 装箱。环形队列同时维护 head 与 count，能区分满与空，并保证只有当前有效候选占槽。每个下标入队和出队至多一次，时间线性，辅助空间 $`O(k)`$，输出另计。

栈和队列维护的性质不同。下一个更大元素依赖未来第一次击败当前元素的位置；窗口最大值还需要处理过期。两种模板不能只改容器名就互换，更不能直接用于 P99。

完整实现：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。测试与逐窗口暴力最大值、逐位置向右扫描进行差分，包含全相等、递增、递减与 k=1、k=n。性能基准同时保留重复扫描作为成本对照。

<h1 id="q-008">3. 排序查找类问题有哪些高频代码模板？</h1>

<h2 id="q-009">面试问题：如何用三种语言实现可控分配的归并排序？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

三个版本都采用自底向上的归并：先合并长度为 1 的相邻有序段，再合并长度为 2、4、8 的段，直到覆盖整个输入。每轮从源数组读、向目标缓冲写，完成后交换两块缓冲的角色。这样避免递归切片和层层创建临时列表。

合并时相等元素优先取左侧，保留稳定顺序。API 返回新数组，不修改调用者输入；内部需要两块线性大小的工作存储。最坏时间 $`O(n\log n)`$，辅助存储 $`O(n)`$，没有递归栈。实际接口使用整数，稳定规则为扩展到记录键比较提供正确基础。

边界上，长度不一定是二次幂，右侧片段可能较短或不存在，所以 mid 和 hi 都要截到 n。空数组和单元素直接返回相应副本。C++ 使用大小类型，Java 用更宽的局部变量计算倍增边界，避免单纯用 int 倍增时溢出。

这个实现用于展示线性合并的工作量，并不自动胜过标准库。Python 的原生排序对解释器循环有很大优势，已有顺序的输入还能被成熟自适应排序利用。基准同时比较 `sorted`、`std::stable_sort` 和 `Arrays.sort`；Java 的整数数组没有可观察的相同键记录顺序，但若改为对象排序，需重新检查稳定性要求。

完整实现定位 `merge_sort / mergeSort`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。不要在 Python 合并循环里反复 `pop(0)`，否则线性搬移会破坏本题依赖的复杂度分析。

<h2 id="q-010">面试问题：如何用三种语言实现二分查找左边界？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

`lower_bound / lowerBound` 返回升序数组中第一个不小于 target 的位置。它可以返回 n，表示所有元素都更小；空数组返回 0。函数不负责检查整个输入是否有序，否则一次查询就要额外线性扫描，有序性由调用者保证。

实现使用 `[left,right)`，初始为 `[0,n)`。若 `a[mid]<target`，中点及其左侧都不可能是答案，令 left=mid+1；否则保留中点，令 right=mid。每一步都缩小区间，结束时唯一边界就是 left。

例如 `[1,2,2,5]` 中 target=2 返回 1，target=3 返回 3，target=6 返回 4。若业务要判断是否存在目标，还需检查 `position<n && a[position]==target`。插入位置与命中位置不是同一种结果。

C++ 使用 `size_t`，Java 的数组长度为 int，但中点使用差值形式计算；Python 不担心固定宽整数相加溢出，仍采用相同写法便于对照。比较的是整数值，若推广到浮点或自定义对象，需要确保排序与查询使用同一有效比较关系。

完整实现：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。随机差分以 Python bisect_left 为参考，并包含空数组、全部重复、最小最大整数和不存在目标；性能使用标准库时，也要保留同样的返回语义。

<h2 id="q-011">面试问题：如何用三种语言实现 Top K，并根据规模选择算法？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

代码保留两个入口。`top_k_heap / topKHeap` 在只选部分元素时使用固定大小小顶堆，选全部元素时直接排序；`top_k / topK` 根据 K 与 n 的比例选择实现。两者都返回最大的 min(K,n) 个整数、按降序排列、保留重复值，不修改原输入；K=0 返回空，负数报错。

堆版本先对前 K 项建堆，再扫描后续值。超过堆顶时直接替换根并下沉，减少先 pop 再 push 的重复维护。Python 绑定 heapreplace 并缓存当前阈值，避免每个元素反复查找函数；C++ 和 Java 使用连续基本类型存储，Java 避免 PriorityQueue<Long> 的装箱。

本机基准显示，K 很小时堆合适，K 较大时其他路线更有优势。因此当前策略以 K 约达到 n/4 为切换点：Python、Java 转向原生完整排序，C++ 转向 nth_element 分区后排序前 K 项。该阈值是可调整的工程规则，测试没有证明它在所有机器、分布和规模上最优。

这也改变了空间与最坏界。固定堆可只保留 $`O(K)`$，自适应分支为保持输入不变可能复制 $`O(n)`$；C++ nth_element 的常见保证是平均线性分区，不能无条件宣称最坏线性。需要严格固定内存或持续处理流时，应使用堆入口并按具体实现扩展流接口。

完整实现：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。[基准说明](codes/BENCHMARKS.md)保留比较条件和结果；两种入口都参与随机差分，避免策略分支只在性能测试中出现。

<h2 id="q-013">面试问题：如何用三种语言实现二叉树 DFS 与层序遍历？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

`tree_orders / treeOrders` 一次遍历返回前序、中序和后序三个结果。栈帧保存节点与阶段：第一次进入记前序并处理左子树，第二次记中序并处理右子树，第三次记后序。每个节点经历三个阶段，仍是线性总工作。

`level_order / levelOrder` 用队列按层返回二维结果，每轮固定处理开始时的队列长度。空树返回空的各遍历结果，不构造虚拟节点。输入要求是一棵有限树，没有环或共享子节点；若传入一般对象图，需改用带 visited 的图遍历。

Python 使用 list 栈和 deque 队列；C++ 栈帧借用调用者节点指针；Java 栈保存帧对象、队列保存节点引用。C++ 的函数不拥有树，也不负责递归析构，测试节点由连续容器管理生命周期，避免把遍历无递归误解为任何树分配方案都不会栈溢出。

DFS 辅助栈与树高相关，BFS 队列与层宽相关，全部输出仍需线性空间。实现通过追加输出避免递归返回结果的反复拼接。对两万节点单链树，迭代版本仍能运行；这个测试专门检查深度边界，不能替代宽树与分叉顺序测试。

完整实现：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。手推例子时应同时写出三种顺序，并确认“左孩子先访问”的栈压入顺序，避免程序正确访问了所有节点却顺序错误。

<h2 id="q-014">面试问题：如何用三种语言实现二分图判断？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

接口输入顶点数 n 和无向边表，顶点编号范围为 `[0,n)`。函数构建双向邻接，对每个未染色分量做 BFS；新邻居染相反颜色，若已染色且与当前点同色就返回 false。空图和只有孤立点的图返回 true，自环返回 false。

统一边表接口能减少语言差异。Python 字典邻接若漏掉只有入边的顶点，可能访问不存在键；本实现明确声明全部 n 个顶点。C++ 与 Java 也验证端点范围，不让错误输入变成越界访问或悄悄连错节点。

Python 使用 deque 与列表邻接；C++ 用预分配顶点队列和邻接数组；Java 两遍构建基本类型邻接数组，先统计每个节点度数，再填充，避免每条边额外装箱。三者在入队时染色，同一节点只入队一次。

邻接表遍历时间 $`O(n+m)`$，空间 $`O(n+m)`$，无向边在内部存两次。重边不会改变二分性质，但会增加输入与扫描量。结果只回答是否可二分，不返回最大匹配或最优资源分配。

完整实现定位 `is_bipartite / isBipartite`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。测试对随机小图穷举所有二染色作为独立参考，包含奇环、偶环、断开分量与自环。

<h2 id="q-015">面试问题：如何用三种语言实现拓扑排序？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

接口接收有向边 u→v，表示 u 必须在 v 前。Kahn 算法统计每个顶点入度，将全部零入度点按编号顺序加入初始队列，再按输入邻接顺序释放后继。这样三语言在同一输入上可以返回一致的合法序列，但这个顺序不承诺字典序最小。

若最终处理了全部节点，返回结果；若仍有节点未处理，返回 None、nullopt 或 null 表示有环。n=0 时返回合法空序列，不能与环检测失败混在一起。端点越界或负 n 属于参数错误，使用异常表达。

Python 用 deque，C++ 与 Java 可以把结果数组同时作为先进先出的工作队列：head 指向下一个待处理位置，新增零入度节点追加到尾部。每个节点只入队一次，避免额外节点对象。重边分别计入入度，并在删除对应出边时逐次减小，保持一致。

时间与空间均为 $`O(n+m)`$ 量级。若要解释具体环路，可另做 DFS 或强连通分量分析；Kahn 剩余节点中还可能有被环阻塞的无环后继，不能全部标成环上的点。

完整实现定位 `topological_sort / topologicalSort`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。用于任务执行时，要在前置任务真正完成后更新依赖，静态拓扑排序只提供顺序约束。

<h2 id="q-016">面试问题：如何用三种语言实现 Dijkstra 最短路？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

接口使用有向加权边表、顶点数和源点，返回各点的最短距离。权重必须非负；不可达点使用共同的 `2^63-1` 哨兵。无效源点、端点或权重直接报错，不把负权图交给算法尝试。

优先队列保存 `(距离,顶点)`，每次弹出后，若距离已不是该点当前最优值就跳过。距离改进时插入新条目，无需定位并修改堆中旧条目。这种惰性删除让实现更直接，但可能保留多条过期记录，堆空间最坏与边数相关。

固定宽整数需要为相加留足余量。三个版本采用相同保守域：每条边不超过 `((2^62)-1)/n`，因此简单路径和一次松弛的候选值都远离不可达哨兵，并落在安全范围内。Python 也遵守这个范围，使跨语言结果可比较。它是接口约束，不是图算法的数学限制。

Python 使用 heapq，C++ 使用比较 pair 的小顶优先队列，Java 使用明确的 Long.compare 与 Integer.compare，避免用两值相减构造比较器导致溢出。Java 邻接端点与权重使用基本类型数组，减少边遍历装箱。

完整实现定位 `dijkstra`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。测试与小图 Bellman–Ford 参考比较，包含零权、重边、不可达节点和非法负权。最短路不自动返回路径；若需要路径，应在成功松弛时记录前驱。

<h2 id="q-028">面试问题：如何用三种语言实现并查集与树状数组？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

并查集提供 find 与 union，初始化时每个元素独立。find 使用路径折半，把当前节点指向祖父并继续前进；union 按集合大小把小树挂到大树，已经同组时返回 false。它维护无向连接的等价类，不保存路径，也不支持任意删边拆集合。

树状数组提供单点增加与前缀和。外部下标从 0 开始，`prefix_sum(end) / prefixSum(end)` 返回 `[0,end)` 的和；内部下标加一后用 lowbit 找父片段。n=0 允许查询空前缀，但不存在可更新位置。下标错误直接报错，不能让 0 内部下标陷入不前进的循环。

三语言都采用连续父数组、大小数组或求和数组。并查集通常具有接近常数的摊还操作成本；树状数组更新和前缀查询为 $`O(\log n)`$，存储 $`O(n)`$。C++ union 方法名为 `unite`，避免与语言关键字冲突。

树状数组还需要数值契约。代码要求整个操作序列中更新绝对值累计不超过 $`2^{62}`$，以保证 64 位累积安全；热循环不重新扫描全部历史验证这个条件，由调用者维持。Python 虽然可以使用更大整数，跨语言测试仍遵守共同域。

完整类名为 `DSU` 与 `Fenwick`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。测试分别用朴素集合标签合并与普通数组前缀求和作独立参考，连续交错更新和查询，验证状态维护而非仅验证初始结果。

<h2 id="q-018">面试问题：如何用三种语言实现 KMP？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

实现分为 `prefix_function / prefixFunction` 和 `kmp_search / kmpSearch`。前者返回模式每个前缀的最长相等真前后缀长度，后者扫描文本，失配时沿前缀函数回退模式状态，文本位置继续向前。

三个版本接收整数序列，适用于 token ID、预先解码的码点或明确的字节序列。空模式返回 0，未命中返回 -1，命中返回第一次出现的起始位置。返回的是输入序列单位，代码不会自动转换为 UTF-8 字节偏移。

模式 `ababaca` 的前缀函数为 `[0,0,1,2,3,0,1]`。扫描时 j 始终表示“已读文本后缀与模式前缀相等的长度”，因此回退只需要尝试 pi[j-1] 给出的下一候选。前缀处理线性、扫描线性，辅助空间与模式长度线性相关。

部分简短 KMP 写法把 `pattern + 分隔符 + text` 拼在一起，再求前缀函数。只有分隔符保证不在输入符号域中时才安全；任意整数 token 流未必有可用哨兵。因此配套实现直接进行两阶段处理，不依赖隐藏的特殊字符。

完整实现：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。随机参考是逐起点比较子序列，并混入中文码点与 emoji 码点；这既检查匹配逻辑，也检查跨语言符号单位是否一致。生产查找仍应比较成熟标准库的实际性能。

<h2 id="q-019">面试问题：如何用三种语言实现 Trie 前缀树？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

Trie 的节点保存“整数 token 到孩子编号”的映射与结束标记，根编号为 0。insert 沿路径查找，缺边才创建新节点；contains 既要求路径存在，也要求最后节点有结束标记；starts_with 只检查路径。插入空序列会标记根，空前缀始终有效。

用整数边标签避免把接口偷偷限制为 a-z。若固定使用 26 个孩子槽，中文、数字或负 token ID 会产生越界风险；若业务确实只允许小写字母，应在入口明确验证，而不是依靠输入“通常正确”。通用映射有更多内存开销，可以在固定词表场景再选择紧凑表示。

Python 不使用 `setdefault(token,新节点)`，因为即使命中，该新节点表达式也会被计算；C++ 使用 vector 节点池，新增节点可能重新分配，因此不跨扩容保留内部引用；Java 使用节点列表与 Map，查询路径为迭代过程，不依赖字符串长度的递归栈。

查询长度 L 的序列，需要 L 次边查找，采用哈希映射时通常是期望 $`O(L)`$；总节点数与不同前缀数量相关。这个实现没有删除、自动补全排序、持久化或线程安全，也没有 Radix 压缩，它用于把基本契约讲清。

完整类名均为 `Trie`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。测试与集合中的完整词和前缀判定对照，还包含两万 token 的长路径，用于检查插入、查询与 C++ 容器释放的深度安全。

<h2 id="q-020">面试问题：如何用三种语言实现多边形面积与点包含判断？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

代码采用简单整数多边形作为共同问题域。顶点按边界顺序输入，无孔洞、无自交；坐标绝对值不超过一百万，顶点数不超过十万，以保证 C++、Java 的乘积和累积落在 64 位安全范围内。函数检查数值范围，但不花额外成本验证多边形是否自交，结构前提由调用者保证。

`polygon_area2 / polygonArea2` 用鞋带公式返回两倍面积，整数结果完全避免除以二带来的小数表示；少于三个点返回 0。调用者若需要面积，可把结果除以 2，并明确是否需要精确半整数表示。

两函数都线性扫描顶点，辅助空间为常数。多边形方向反转不会改变非负面积与内外分类，重复首尾点也不应改变结果；这些性质可以作为变形测试。凹多边形、边上点、顶点和水平边专门用于验证相交计数。

<h2 id="q-022">面试问题：如何用三种语言实现回溯组合枚举？</h2>

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

`combinations_backtrack / combinationsBacktrack` 用递增 start 保证每个组合只出现一次，用剩余可选数剪枝，并在返回时恢复路径。答案保存独立副本，避免后续修改污染已经产生的结果。输入 n、k 非负，k>n 返回空，k=0 返回包含一个空组合的结果。

例如 n=4、k=2，输出依次为 `[1,2]、[1,3]、[1,4]、[2,3]、[2,4]、[3,4]`。选择 3 作为第一项后，只需继续尝试 4；选择 4 作为第一项时已经凑不够两个数，可以提前跳过。

回溯教学版本限制 k≤128，防止深路径依赖语言递归栈。代码还提供 `combinations` 迭代版本：从 `[1..k]` 开始，找到最右侧尚能增加的位置，增加后把右侧恢复为最小递增后缀，按字典序生成下一组。两种入口输出相同，但状态推进方式不同。

全部输出需要 $`\Theta(k\binom nk)`$ 量级的数据，k=0 等边界单独处理。迭代消除了递归栈，不会消除组合爆炸。调用者应在实际分配前估算输出规模；流式消费可以减少保留全部答案的内存，却不能让完整枚举变成常数时间。

完整实现：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。测试同时比较递归与迭代入口，并以 itertools.combinations 的小规模结果作参考，检查顺序、重复、空组合及多次调用无残留状态。

<h2 id="q-023">面试问题：如何用三种语言实现线性辅助空间的编辑距离？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

实现计算单位代价 Levenshtein 距离，允许插入、删除、替换，不包含把相邻两项交换作为一次操作。输入是整数序列，因此字符、词或 token 的差异由调用者预处理确定。返回最小操作次数，不返回完整编辑路径。

二维 DP 的当前格只依赖上方、左方和左上方。代码把较短序列放在列方向，保留一行数组；更新某格前先保存旧的上方值，使用单独变量保留旧的左上值，完成后推进。若过早覆盖对角值，就会读取当前行而非上一行的状态。

时间仍为 $`O(nm)`$，辅助空间降为 $`O(\min(n,m))`$。把表压成一行主要降低内存，不保证所有语言上都更快，也不能直接恢复对齐路径。需要路径时可以保存决策或使用分治重建等方法。

空序列到长度 m 的序列距离为 m，相同序列为 0。`ab` 与 `ba` 在本定义下距离是 2；如果期待结果 1，要求的是带换位操作的另一种距离，不能把测试期望偷偷改成相符。

完整实现定位 `edit_distance / editDistance`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。随机差分使用独立二维表参考，覆盖长度不对称与多种整数符号。语义相近的文本也可能有较大编辑距离，使用该指标前应明确评价目标。

<h2 id="q-024">面试问题：如何用三种语言实现覆盖极端数量级的牛顿平方根？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

实现先把 x 分成尾数与二进制指数，把指数调整为偶数，在有界尾数上进行牛顿迭代，再恢复尺度。这样避免以 x 直接作初值导致的极大中间数，也避免用 `t*t` 检查残差时溢出。

Python 使用 frexp/ldexp，C++ 使用对应标准数学函数；Java 的 getExponent 对所有次正规数返回特殊指数，因此代码先把次正规数缩放到正常范围，再还原指数。这一步使最小正浮点数也参与正确的尾数迭代。

停止条件比较相邻迭代值的相对变化，并设置 16 次上限；若没有达到条件，明确失败。x=0 直接返回，并保留负零；负数、NaN、无穷被拒绝。接口只讨论有限非负实数，不返回复数结果。

测试将结果与标准库 sqrt 比较，采用 ULP 尺度而非一个固定绝对 epsilon，包含最小次正规数、接近最大有限数和跨多个指数的随机输入。测试结果支持所覆盖输入范围内的误差结论，不能替代对全部浮点输入正确舍入的证明。

完整实现定位 `sqrt_newton / sqrtNewton`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。工程中通常直接调用成熟 sqrt；本例用于学习数值缩放、异常输入和终止条件，而不是用迭代替换硬件指令争取速度。

<h2 id="q-025">面试问题：如何用三种语言实现带主元选择的高斯消元？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

三个版本接收方阵 A 与向量 b，复制输入后求解，调用者原始数据保持不变。先按每行系数的最大绝对值做均衡化，再逐列选择当前最大绝对主元、交换行、消元，最后回代。

主元检查使用均衡后的尺度，避免把整个矩阵乘以一个很小常数就误判为奇异。当前教学接口将不超过 `1e-12` 的主元视为数值上不可可靠求解并拒绝；这个阈值属于数值策略，不是对数学秩的精确判定。无解与无穷多解也不会返回参数化结果。

输入维度错误、非有限值和零系数行都会被检查。若运算产生非有限结果，也明确失败。即使得到有限解，调用者仍应根据任务精度验证缩放残差，病态系统还需要条件数、QR/SVD 或其他稳定方法支持。

时间 $`O(n^3)`$，复制与矩阵存储 $`O(n^2)`$。求很多个右端项时，应复用 LU 分解；大稀疏系统应使用稀疏求解器；最小二乘不要默认先构造正规方程。教学实现保留清楚的行变换过程，不承担这些库级功能。

完整实现定位 `gaussian_solve / gaussianSolve`：[Python](codes/python/algorithms.py)、[C++](codes/cpp/algorithms.hpp)、[Java](codes/java/Algorithms.java)。验证使用已知解构造 b，加入行交换、整体极小或极大缩放与奇异矩阵，检查解误差和失败行为。
